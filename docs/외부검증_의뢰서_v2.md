### G — 원인 진단이 확인된 적이 없다

v1 은 원인을 **−20% 엔벨로프 문턱**으로 단정했다. 그런데 그 근거였던
2026-08-16 실측(651종목 중 2종목)도 9/1 실측(0/701)도 **복합 조건 통과 수 하나**였다.

```python
is_envelope_over_under = (이격 AND 거래대금(50억/100억) AND 상한가아님 AND 등락률≤10%)
```

단계별 집계는 **2026-09-14 에야 생겼다.** 9/15 첫 관측:

```
이격 3 → +거래대금(100억) 0 → +상한가·등락률 0
```

**이격은 0이 아니었다.** 하루 관측이고 그날은 경계장(문턱 2배)이라 단정하지 않는다.
다만 §3-2-1 이 완화 대상을 이격률로 지목했고 되돌리는 조건에 *"문턱 완화로도
안 되면 → 중기 채널 통합 또는 적재 중단"* 을 걸어 둔 것이 위험하다 —
**틀린 문턱을 낮추면 손대지도 않은 문턱 때문에 채널을 죽인다.**
→ `docs/정책변경_체크리스트.md` §4-2

| 판정 문턱·선정 로직을 **코드에 바로 적용** | 사전등록 대상이다. 제안은 문서로만 |
| 시장 스냅샷 파일 삭제·수정 | 그 시각에만 존재하는 값이다. 사후 복원 불가 |
| `docs/판정_*.md` · 날짜 박힌 수정보고 수정 | 박제 문서다. 틀렸으면 새 날짜로 새 파일 |
| **`ENVELOPE_BAND` 등 스위치 ON** | §3-2-2 의 10/5 조항과 사용자 승인 사항이다 |

## 7. 회신 형식 요청

1. **어느 구역을 봤는지** 먼저 밝혀 달라. Codex 작성분을 봤다면 자기 감사임을 명시
2. 결함은 **파일:줄** 로 지목하고, **왜 그것이 틀린 값을 내는지**를 재현 경로로
3. "개선 제안" 보다 **"이 주장이 틀렸다"** 를 우선해 달라
4. 확신이 없으면 확신 없다고 적어 달라. 우리는 이미 여러 번 확신해서 틀렸다
