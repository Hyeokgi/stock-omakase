# 클로드 전달용 — 계좌 입력 및 연구 정책 수정 보고

작성일: 2026-09-09. 기준 main: `7e66996`. 수정 브랜치: `fix/account-input-policy-20260909`.
대상: `수정공유_20260909.md`의 Q1·Q2와 §6-12-4에 대한 후속 수정.

## 요약

계좌 테마 제한을 목적별로 나누고, 준비된 자료를 검증·고정하는 오프라인 입력 빌더를 추가했다.
연구 질문이 다른 Q5와 테마 대장 연구를 무조건 직렬화하던 규칙을 완화하되 확증 검정의
사전등록·다중검정·미사용 구간·독립 재현 요구는 유지했다. 기존 라이브 시트·선정 프롬프트·
수집 작업·운영 배포는 변경하지 않았다. 별도 브랜치 수정이며 main 자동 병합은 하지 않는다.

**65개 계좌/저장/입력 테스트 통과. 기존 판정과 타점 자체 검사도 통과.**
테스트는 합성 자료 및 모의 저장 응답이다. 실제 386행 수익률은 계산하지 않았다.

## Q1 조치 — 테마를 모른다는 이유로 기본 계좌 계산까지 막지 않는다

`theme_policy` 세 모드를 추가했다.

| 모드 | 처리 |
|---|---|
| none | 현금·종목 한도만 적용. 테마 정보 미필수. 테마 최대 노출은 0이 아닌 null |
| representative | 당시 대표 테마 ID 하나와 근거를 요구. 그 테마만 제약 |
| complete | 당시 전체 소속 상태와 근거 요구. partial/unknown/대표 하나뿐인 자료는 거부 |

`theme_quality`로 상태와 출처를 신호일·종목별로 기록한다. 확인된 무소속은
`verified_none`과 `NO_THEME:종목코드`를 함께 요구한다. 미확인을 무소속으로 대체하지 않는다.
제약에 따라 승인 주문 자체가 달라지므로 성과 차이를 실제 성과의 상한·하한이라고 하지 않는다.
대표 테마 제한 결과로 전체 테마 집중 상한을 검증했다고 주장하지 않는다.

v2 입력은 재현 호환을 위해 유지하되 검증 근거 미확인 경고를 붙였다. 신규 workflow는
v3 빌더를 반드시 거치므로 기존 v2 파일만으로 검증 근거를 우회할 수 없다.

## Q2 조치 — 조정 기준을 문자열로 자가 인증하지 않는다

신규 v3는 `price_verification`과 `calendar_verification`에 verified 상태와 근거 참조를 요구한다.
거래일은 별도 확인한 sessions 목록과 분석 기간 전체가 일치해야 한다. 누락된 중간 거래일을
독립 기준 목록과 대조해 막는 테스트를 추가했다. 단, 입력자가 같은 목록을 복사하거나 거짓
verified를 선언한 것을 코드만으로 판별하지는 못한다. 실제 자료 확인 책임은 남아 있다.

가격은 기존 consistent_adjusted_ohlc 모형만 지원한다. 출처/기업행사 기준을 검증하지 못하면
unverified로 남기고 실행을 중단한다. 양수 가격에서 tradable을 추정하지 않는다.
분할/배당 현금흐름·실제 당시 정수 수량을 재현하는 원시가격 계좌 모형은 아직 미구현이다.
수정주가 정수 수량 계좌를 실제 체결 계좌라고 부르면 안 된다.

## 입력 빌더 구현 범위

`account_input_builder.py`는 rows·달력·OHLC·거래 상태·출처를 합친 준비된 JSON을 받아
입력 검증과 가상 계산을 수행하고, 물리 행 수를 승인/거절·제외·지수 행·대기·빈 행으로 대사한다.
검증 성공 시 읽어 확인한 SHA256을 포함해 고정 input.json을 내보낸다. 실패하면 quality.json만
남기고 종료 코드 2를 반환한다. 오류 상세는 비공개 파일에만 기록한다.

**네이버/시트 자동 수집 빌더가 아니다.** 기존 함수의 최근 20일 기본값, 종목만을 키로 한 캐시,
실패/잘못된 행 생략, TLS 검증 해제, tradable 누락을 그대로 옮기지 않았다. 기존 라이브 수집기는
이번에 수정하지 않았다. 기간 지정·캐시 분리·TLS 검증·응답 상태·완전성 검사를 갖춘 수집
어댑터를 별도로 구현하고 조정 기준을 확인해야 실제 입력을 만들 수 있다.

신규 workflow는 Drive에서 준비 자료 읽기 → 빌더 검증 → 계좌 계산 → 비공개 증거 업로드 순이다.
사용자 OAuth/실제 Drive 연동은 미검증이다. 입력 빌더의 quality.json은 로컬 보존이며 별도
원격 업로드는 하지 않는다. 성공 시 입력·계산 결과는 기존 증거 ZIP에 들어간다. 실패한 Actions의
임시 진단 파일은 영구 보존되지 않으므로 최초 자료 검증은 로컬에서 수행한다.

## 연구 규칙 수정

- 독립인 두 5% 검정을 OR 채택하면 전체 귀무가설하 오류율은 9.75%다. 항상 두 배라고 쓰지 않는다.
- Q5는 기존 Q5 연구 안의 주 검정이다. 테마 대장 전략의 유일한 성공 관문으로 삼지 않는다.
- 테마 연구는 현재 탐색적이다. 별도 사전등록·가설 묶음/알파 관리·미사용 검증·재현 전 채택 금지.
- 사전 고정한 연구들이 같은 미래 날짜를 검증에 쓰는 것을 일괄 금지하지 않는다. 다만 결과 접근과
  정책 변경을 기록하고, 같은 날짜의 두 분석을 서로의 독립 재현이라고 부르지 않는다.
- Q5 완료를 기다리지 않고 테마 연구의 수집·탐색·합성 분석기를 준비할 수 있다. 이번에 실제
  종베 특징 분석기나 승률 탐색은 구현/실행하지 않았다.
- 목표 효과 +0.10%p를 고정하면서 상향도 허용하던 모순 제거. 상향은 현재 설계 변경이 아닌
  별도 신규 연구로 취급한다.
- 20일 파일럿 표준편차에 의존한 N 표는 근사 예시임을 표시했다. 자기상관·추정 오차·올림·
  최소 길이 방법이 확정되기 전 자동 일정으로 쓰지 않는다. 임의의 새 통계 임계값은 넣지 않았다.
- 10/5 종베 자료 점검 방침과 수급 채널의 기존 강제조항은 유지했다.

## 테스트와 후속 확인

기존 47개 + 신규 18개 = 65개 통과. 신규 검사에는 테마 모드가 실제 주문을 바꾸는지,
unknown/partial 차단, 확인된 무소속 ID, 가격 근거 누락, 달력 중간 누락, 거래 가능 상태 누락,
행 수 대사, 원본 불변, 실패 시 실행 입력 미출력, 성공 시 고정 입력 출력이 포함된다.
`hyeoks_verdict.py --self-test`, `test_tajeom.py`도 통과했다.

클로드의 다음 작업 권고:

1. 이 브랜치 diff를 검토하고 같은 테스트를 재실행한다. 기존 수정 보고서는 역사 기록으로 보존한다.
2. 실제 공급자 자료의 조정 기준/기간/거래 상태를 확인한 수집 어댑터를 만든다. 검증할 수 없는
   항목에 verified를 넣지 않는다. theme none부터 기본 계좌 입력을 완성할 수 있다.
3. 준비 자료를 로컬 빌더로 검사하고 행 수·결측·기업행사를 확인한 뒤 실제 재계산 및 정정 보고를 낸다.
4. 테마 연구의 시점 후보·실패 사례 수집과 합성 분석기를 만든다. 조건 1~2개, 비용 후 손익과
   거래 빈도 중심으로 설계하되 실제 최적 문턱이나 승률은 아직 찾았다고 하지 않는다.
