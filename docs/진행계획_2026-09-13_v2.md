# 실행 계획 v2 — 두 전략에 집중하고 개발·검증을 병행

작성: 2026-09-13 / 사용자 요청에 따른 일정 개정. 운영대전제가 우선한다.
기존 일정표의 "기계는 연말, 판정은 내년 7월, 단축은 문턱 완화뿐"이라는 프로젝트 전체
일정 해석을 대체한다. 아래 날짜는 작업·점검 목표이지 수익성 입증/실전 개시 약속이 아니다.

## 바꾸지 않는 것

- 종베 15:05 진입 연구 → 다음 거래일 시가 전량 청산. 리포트는 스윙.
- 계좌 고점 대비 약 10% 감내 한도는 손실 보장이나 자동 손절 설정이 아니다.
- 4~5종목은 모의계좌 비교 가정. 자금 배분·개별 위험 한도는 미확정.
- 기존 Q5 효과 크기, 파일럿 20일, 본 구간 40~120일 규칙 및 별도 재현 60일은 유지.
- 차트/수급의 네 번 판정 달력과 리포트 A/B/C 달력을 소급 변경하지 않는다.
- `passed`/`hit` 자동 승인 보류는 유지. 추론 계획 검증 없이 해제하지 않는다.
- 모의 운용 준비와 실제 주문 허가는 구분한다. 지금 자동주문을 켜지 않는다.

8~10주를 모든 작업의 직렬 선행조건으로 삼지 않는다. 하프켈리·복잡한 청산·완전 자동주문은
선정 연구와 모의계좌 구축의 선행조건이 아니다. 실제 주문 전 필요한 안전장치를 생략한다는 뜻은 아니다.
계좌 계산기는 이미 `hyeoks_account.py`/`account_input_builder.py`에 있다. 신규 제작이 아니라
실행 가정 정렬과 검증된 입력 확보가 남은 작업이다. 이 문서 추가만으로 그 연결이 완료된 것은 아니다.

## 연구 범위와 결과 접근

Q5는 오후 거래대금 증가율 상위 분위의 효과이고, 테마 대장주 소수 선정과 다른 질문이다.
테마 연구의 수집·탐색·합성 개발을 Q5 종료까지 미루지 않는다. 미래 확증 분석 전에는 후보
규칙·비교군·가설 묶음·반복 검정 계획·결과 접근 구간을 정한다. 같은 날짜의 두 연구를 서로의
독립 재현으로 부르지 않는다. 탐색에 사용한 구간은 해당 조건의 검증에서 제외한다.

주의: 현재 `hyeoks_analyst.py`의 중기 프롬프트는 과매도 기술적 반등이며,
산업리포트 기반 구조적 성장은 장기 프롬프트에 있다. 산업리포트 자동수집만 늘려도
중기 채널이 살아난다고 가정하지 않는다. 사용자가 원하는 산업/실적 기반 스윙과의 차이는
중기 퍼널 진단 후 별도 정책 제안으로 다룬다. 이번에는 선정 문턱/프롬프트를 바꾸지 않았다.

## 남은 쟁점 관리

- `after_hours_regime()` 경계: 이미 `tests/test_review_regressions.py::test_regime_boundary`에서
  9/13·9/14를 시험한다. "자기검증 없음"은 오래된 상태 설명이다.
- 정책일: 신호일 경계는 여전히 임시 분류. 행별 freeze/policy_id와 연결 검증 전 확정 인증 금지.
- TLS: 이번 analyst 10곳과 스냅샷 개장 확인 1곳은 기본 검증 복원. 저장소 전체 완료가 아니다.
- 베타=1: 전략 정의/비교 가정이다. 사후 추정 베타로 과거 승패를 교체하지 않는다.
  과거 학습기간만 사용한 베타 보정 민감도는 별도 참고 연구이며 현재 핵심 개발의 선행조건이 아니다.
- 코드 push, CI 성공, 실제 장중 수집 성공, 동결 상태 파일 자동 push 성공은 서로 다른 증거다.
  서로 대신하여 "운영 검증 완료"라고 쓰지 않는다.

이 일정은 저장소의 협업 계획이다. 별도 예약 작업이나 상시 감시를 만든 것은 아니다.
