## 1. A/B/C 분석기 (`hyeoks_theme_abc.py`)

### 결함

| | 이전 | 문제 |
|---|---|---|
| 익일 | `next_trading_snapshots()` 가 **관측 파일 목록의 다음 날짜** | 스냅샷이 하루 빠지면 이틀치 수익률을 '익일 시가' 로 계산 |
| 성숙 | `stage_of()` = `len(dates) - 1` | 날짜가 비어도 성숙으로 세서 결측 시 Stage 1 에 일찍 진입 |
| 휴장일 파일 | 거래일로 취급 | 가드 실패로 휴장일 파일이 생기면 익일 자리를 차지 |

현재 자료(8/28~9/30, 22일)에는 빈 날·휴장일 파일이 **없어 실제 오염은 없었다**(구조적 위험).

### 수정 — Q5(`hyeoks_closing_bet.build_day`)가 이미 쓰는 규칙으로 맞춤

- `session_link(date, dates, nontrading)` — 다음 거래일을 **검증된 휴장 달력**(`next_trading_day`)으로 정한다.
  그날 15:05 파일이 없으면 다른 날로 대체하지 않고 `익일미성숙`(아직 안 옴) / `익일달력결측`(지났는데 없음).
  휴장일·주말 파일은 `휴장일파일` — 진입일도, 익일도 될 수 없다.
- `matured_dates()` / `stage_of()` — 성숙은 **익일 자료가 실제로 있는 진입일**만(진입일 13:00 슬롯 포함).
- `build_day()` — 휴장일 파일은 `skip`, 청산일(`exit_date`)과 결측 사유(`returns_note`)를 남긴다.
- 리포트에 **탐색(파일럿) 구간**을 날짜로 찍는다: 현재 `2026-08-28 ~ 2026-09-28 (20일)`.
  이 구간을 보고 C 조건 등을 고치면 사후 맞춤이고, 평균에 섞인 파일럿 이후 날짜를 미사용 검증 구간으로 부르지 않는다.

### 검증

- 자체시험 84건 통과(이전 71건대). 가짜 날짜(`["d"] * N`)와 주말·빈 날이 섞인 합성 21일을
  **생산 휴장 달력으로 만든 연속 거래일**로 바꿨다 — 이전 합성 자료는 바로 이 결함 때문에 통과하고 있었다.
- 새 회귀: 9/23→9/28(추석) 연결, 9/28 결측 시 9/29 로 대체하지 않음, 빠진 날의 앞날은 미성숙,
  마지막 날 `익일미성숙`, 휴장일·주말 파일 배제, 합성 파일에서 하루 지우면 앞날 수익률 없음·성숙 20→18.
- 변이시험: 익일을 '다음 파일' 로 되돌리면 **7건 실패**.
- **재검증(현재 자료)**: 수정 전후 리포트의 수치가 **완전히 같다**(라벨 문구·탐색 구간 줄만 추가).
  9/30 까지 22일·성숙 21일 — A +0.083% / B +0.158% / C −0.086%(비용 전).
- **코덱스 수치 재현**: 9/29 까지 자료만으로 돌리면 성숙 20일,
  A **+0.032%** / B **+0.092%** / C **−0.150%**(비용 전), 비용 후 −0.318 / −0.258 / −0.500%,
  B−A +0.060%, C−B −0.242% — 코덱스 보고 표와 **소수 셋째 자리까지 일치**.

해석은 코덱스와 같다. 이 20일에서 C 가 성과를 개선한 근거는 없다. 그렇다고 C 를 지우면 사후 최적화다.
일별 평균의 평균이며 계좌 수익률이 아니다. 익일 시가는 연구 대용값이다(운영대전제 §3).

## 2. 시장 스냅샷 시각 (`hyeoks_market_snapshot.py`)

`capturedAt` 은 **실행 시작** 시각이다(9/28·9/29 15:05 슬롯 실측 15:02:48·15:02:47).
전 종목 가격은 그 뒤 **한 번의 요청**으로 온다. 메타 행 끝에 세 키를 더했다.

| 키 | 뜻 |
|---|---|
| `priceRequestedAt` | 전 종목 시세 요청 직전 |
| `priceReceivedAt` | 시세 응답 수신 직후 — **가격 관측 시각에 가장 가까운 값** |
| `writtenAt` | 테마·업종 수집 후 파일 기록 시각 |

- `capturedAt` 의 뜻·위치는 그대로다. 시간창 판정·결측 감시·계좌 어댑터가 그 뜻으로 읽는다.
- 새 키는 **뒤에** 붙였다. 기존 키 순서 불변. 읽는 쪽은 `key=value` 로 파싱한다.
- ⚠️ 수신 시각도 네이버가 값을 만든 시각이나 체결 가능 시각의 **인증이 아니다**.
- 시험 5건(`tests/test_snapshot_timestamps_20261001.py`) — 실제 `main()` 을 네트워크 없이 돌려
  키 값·순서·기존 리더 호환을 확인. 첫 생산 확인은 다음 거래일 13:00/15:05 스냅샷.
