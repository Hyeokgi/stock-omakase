## 2. 신규 사이트 구조 (실측)

- `https://stock.naver.com/market/stock/kr/theme/1` → 200, 120KB, 그러나 본문은 헤더·푸터뿐.
  본문 한글 토큰 180개가 전부 UI 문구(“종목명”, “고객센터” 등)이고 테마명은 하나도 없다.
- `__NEXT_DATA__` 없음 / `__NUXT__` 없음 → App Router. 데이터는 React Suspense 경계 안에서
  클라이언트가 별도로 가져온다.
- URL의 `1`은 **페이지 번호가 아니라 테마 코드**다. RSC 페이로드상 라우트는
  `["", "market", "stock", "kr", "theme", ["code","1","d"]]` = `/market/stock/kr/theme/[code]`.
- API 베이스 2종
  - `https://stock.naver.com/api/...` — 시장 데이터 (Fastify. 없는 경로는 JSON 404를 준다)
  - `https://m.stock.naver.com/front-api/...` — 검색·토론 등 (`/search/autoComplete`, `/discussion/add` 형태)

### ⚠️ 캐치올 함정 (반드시 기억할 것)

`stock.naver.com/api/domestic/market/{이름}/list` 는 **존재하지 않는 이름에도 HTTP 200 + `[]`** 를 준다.

```
theme                  → 200, 20개
group                  → 200, 20개
industry               → 200, []      ← 실제로는 다른 경로를 쓰는 듯
completelyBogusName123 → 200, []      ← 아무 이름이나 []
```

즉 이 API로 이관할 때 **200을 성공으로 간주하면 안 된다.** 반드시 건수와 필수 필드를 검증해야 한다.

## 4. 조사 중 발견한 "이미 깨져 있던" 것 2건 (개편과 무관, 즉시 수정함)

### ① 🚨 위험종목 게이트가 통째로 열려 있었다

`hyeoks_static_collector.py`가 `value_input_option="USER_ENTERED"`로 문자열 `"True"`를 쓰면
구글시트가 이를 **불리언으로 해석**해 `TRUE`로 저장한다. 그런데 `omakase.py`는

```python
'is_junk': row[3] == 'True'      # 'TRUE' == 'True' → False
```

로 비교하고 있었다. 결과적으로 **DB_정적데이터의 275종목 전부가 `is_junk=False`** 로 읽혔다.

실제 피해 — 백테스트_로그 282건 중 **13건이 위험종목 명단과 겹쳤다.**

```
2026-08-11  리포트TOP2_단기  혜인          2026-07-31  리포트TOP2_단기  성호전자
2026-08-11  수급TOP2       NHN           2026-08-11  수급TOP2        코스메카코리아
2026-07-20  차트TOP2       누보           2026-07-10  차트/수급TOP2    대한광통신  …
```

**수정** — 대소문자·공백 무관하게 판정하는 `_sheet_bool()` 도입. 실데이터 검증에서
`수정 전 0종목 → 수정 후 275종목`으로 게이트가 복구되었다.

### ② 종목명→코드 검색 API 사망

`m.stock.naver.com/api/search/all` 이 404를 반환한다(3회 반복 확인). PC 개편과 함께 정리된 것으로 보인다.
`search_code_from_naver()`가 이걸 쓰고 있었고, 예외를 삼키고 `None`을 반환하는 구조라 **조용히 실패**하고 있었다.

**수정** — `ac.stock.naver.com/ac` 우선, 실패 시 `front-api/search/autoComplete` 폴백.

## 5-2. 실제로 구현한 이중화 (2026-08-26)

**설계 원칙: HTML이 '주', JSON이 '보조'.** HTML이 살아있는 동안 결과가 완전히 동일하므로
9/7 기준선이 흔들리지 않고, `finance.naver.com`이 죽으면 자동으로 JSON이 받는다.

| 지점 | 동작 |
|---|---|
| `hyeoks_static_collector.py` 위험종목 | **합집합** — HTML ∪ JSON. 실측 HTML 274 ∪ JSON 270 = 274 |
| `omakase.py` 테마 순위 | HTML 테이블 없으면 → `fetch_theme_list_json()` |
| `omakase.py` 테마 구성종목 | `type_5` 없으면 → `fetch_theme_stocks_json()` (단위 백만원으로 정규화) |
| `omakase.py` 주요뉴스 | 파싱 0건이면 → `fetch_main_news_json()` |
| `omakase.py` 검색상위 | 파싱 0건이면 → `fetch_search_ranking_json()` |

**fail-closed 판정도 이중화했다.** 수집기는 이제 "HTML 관리종목 건수" 단독이 아니라
**"두 소스 중 하나라도 정상인가"** 로 판정한다. 한쪽만 죽으면 진행하되 텔레그램으로 알리고,
둘 다 죽어야 중단(전일 스냅샷 보존)한다.

또한 시트 기록을 `USER_ENTERED` → **`RAW`** 로 바꿨다. §4①의 `'True'`→`TRUE` 변질을
근본에서 막는다(omakase 쪽 `_sheet_bool()`은 이중 안전망으로 유지).

## 6. 마이그레이션 판단 — **수급만 미이관**

기존 URL이 전부 살아있는 상태에서 지금 갈아타면 안 되는 이유가 있다.

**수급 소스를 바꾸면 V2 점수가 바뀌고, 그러면 9/7 재점검의 기준선이 오염된다.**
현재 HTML은 5일치를 읽어 `수량×당일종가`로 누적하고, 신규 JSON은 10일치를 준다.
같은 필드처럼 보여도 집계 구간·반올림이 달라지면 V2 점수가 미세하게 달라지고,
채널 판정(§ `docs/전략로드맵.md`)의 전/후 비교가 무의미해진다.

따라서 순서는 이렇게 간다.

| 시점 | 할 일 |
|---|---|
| **지금** | ✅ 깨진 2건 수정 · ✅ 진단기(25항목)+기준선 · ✅ 위험종목/테마/뉴스/검색상위 폴백 이중화 |
| **주 1회** | `--compare` 실행으로 회귀 감시 |
| **9/7 재점검 이후** | 수급(frgn)을 JSON으로 이관. 이관일 기록 + 전/후 표본 분리 |
| **기존 URL이 실제로 깨지면** | 폴백이 자동으로 받는다. 수급만 수동 이관 필요 |

**수급(frgn)만 폴백을 넣지 않은 이유** — 다른 폴백들은 HTML과 결과가 완전히 같아 무해하지만,
수급은 HTML이 5일치·JSON이 10일치라 집계 구간이 달라 **V2 점수가 미세하게 바뀐다.**
9/7 채널 판정의 전/후 비교가 무의미해지므로 재점검 이후로 미룬다.
단, 이 지점이 죽으면 진단기가 '치명적'으로 잡고 종료코드 1을 낸다.

## 7. 남은 숙제

- **수급(frgn)** — 폴백 미적용. 9/7 재점검 이후 이관 (§6 사유).
- **시황 뉴스목록 / 종목별 뉴스 / 시가총액** — JSON 대체재 미발견. 각각 뉴스 키워드,
  AI 리포트 근거, 시총 필터를 담당한다. 개편으로 죽으면 해당 기능이 비지만
  선정 로직을 멈추지는 않는다(시총은 `siseListJson`의 `mks` 필드로 대체 가능성 있음 — 미검증).
- **캐치올 함정** — `theme/{no}/stocklist` 도 없는 번호에 `200 []` 를 준다.
  어댑터는 건수로 판정하지만, 앞으로 이 계열 API를 추가할 때마다 같은 검증을 붙일 것.
- CSS 선택자 의존은 폴백이 없는 3곳(`.articleSubject a`, `.title a`, `#_market_sum`)에
  아직 남아 있다. 진단기가 감시한다.

## 8. 개편 당일 체크리스트

```bash
python hyeoks_naver_healthcheck.py --compare
```

1. **치명적 항목이 초록이면 손댈 것 없다.** 폴백은 자동으로 동작한다.
2. `외국인·기관 수급 HTML` 이 빨간색이면 → **수급 이관이 필요하다**(유일한 수동 작업).
   `m.stock.naver.com/api/stock/{code}/trend` 로 교체하고, 그날을 표본 분리 기준일로 기록할 것.
3. `위험종목 3종 HTML` 만 빨간색이면 → 조치 불필요. 수집기가 JSON 단독으로 명단을 만들고
   텔레그램으로 알린다(실측 270종목 확보).
4. 텔레그램에 `🚨 [위험종목 게이트 이상]` 이 오면 → 게이트가 실제로 비었다는 뜻이므로 즉시 확인.
