## 4. Stability Gate — 지금 돌아가는 것

### 4-1. 왜 만들었나

감사가 끝나지 않는 문제가 있었다. 정적 점검을 할 때마다 새 지적이 나오고,
고치면 또 나왔다. 코덱스가 **"종료선을 문서에 못박으라"** 고 제안했고 사용자가
목적과 원칙을 승인했다. 다만 **당시 구현을 1회차로 인정하지는 않았다.**

### 4-2. 규칙

```
기준 7개  ci_green · earnings_schema_ok · dart_complete · no_silent_parse_error
          store_written · ledger_written · no_unexplained_failure

판정 단위 = KRX 거래일 1회(cycle). 하루에 여러 번 돌아도 최대 1 cycle.
3거래일 연속 PASS → 운영 감사 Phase 종료.
비거래일 = SKIP (연속을 늘리지도 끊지도 않는다)
지문(stability_fingerprint)이 바뀌면 streak 즉시 0
```

**핵심 철학 — 이걸 의심해 달라:**
- **"모르는 것은 통과가 아니다."** 증거가 없으면 거짓이다. `None` 도 통과가 아니다
- **사람이 7개의 True/False 를 넣는 경로는 증거로 인정하지 않는다.**
  각 파이프라인이 영수증을 떨구고 Evidence Builder 가 기계적으로 조합한다
- **지문은 `data/` 를 제외한다.** 안 그러면 매일 데이터 커밋으로 streak 가 0 이 된다
- **Gate 자신을 실행하는 코드도 지문에 들어간다** (교차검증 3차에서 빠진 것이 발견됨)

## 9. 우리가 가장 틀렸을 것 같은 곳 (자진 신고 — 갱신)

v2 §8 의 다섯 가지는 **그대로 유효하다.** 더한다.

- **"정적 감사로 다 찾았다"는 착각.** 이번 Phase 의 P0 6건 중 **3건은 실제 실행이
  찾았다.** 546건이 통과하고 CI 가 초록인데 워크플로가 첫 실행에 즉사한 적이 있다.
  **시험이 초록인 것과 생산이 도는 것은 다르다** — 코덱스가 계속 지적해 온 그대로다
- **시험이 실제로 무엇을 실행하는지.** AST·텍스트 시험을 "검증했다"고 불렀다.
  `.github/*.py` 는 검사 범위 밖이라 **한 번도 읽히지 않았다**
- **같은 결함을 두 번 만들었다.** 벽시계 날짜 문제를 수집기에서 고치고, **똑같은
  것이 판정기에 남아 있었다.** 세 번째가 있을 것으로 의심한다
- **컨센서스 원인.** 레이트리밋 가설을 세웠다가 순환논증이라 철회했다. 지금 **미상**이다.
  증거는 0건이다(`consensus_aux` 미실행)
- **Gate 가 "끝"을 만들어 준다는 기대.** 3/3 은 운영 감사 Phase 의 종료선이지
  **알파의 승인도, 수익성의 증거도, 자동매매의 허가도 아니다**
