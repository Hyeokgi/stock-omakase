## 1. 역순 기록 방지 (사용자 지시 ①)

`streak()` v3 는 이력이 단조 증가라고 가정하는데 **`record()` 는 순서를 막지 않았다.**
방아쇠는 `docs/안정화_종료선_2026-09-18.md` 가 복구 절차로 적어 둔
"finalizer `workflow_dispatch` 로 빠진 과거 거래일 수동 판정" 이었다. 재현했다:

```
9/21·22·23 PASS  → streak 3        (3/3 도달)
9/18 뒤늦게 판정  → streak 0
이후 9/24·25·28  → streak 0        ← append-only 라 복구 경로 없음
```

조치
- `record()` 가 **마지막 기록보다 이른 날짜의 일반 append 를 거부**한다.
  사유에 무엇이 무엇보다 이른지, 어디에 남겼는지를 말한다.
- 판정 자체는 버리지 않는다 — **`data/stability_gate/backfill_audit.csv`** 에 남긴다.
  `streak()` 는 이 파일을 읽지 않는다. **연속 카운트의 근거가 아니다.**
- 중복은 기존대로 거부하며 감사 기록 대상이 아니다(같은 날을 두 번 세지 않는다).

⚠️ 자체 검토에서 내 첫 구현의 결함을 찾았다: 감사 경로가 쓰기 불가일 때
`_audit()` 의 예외가 그대로 올라가 **거부가 아니라 죽었다.** 거부가 본질이고
감사 기록은 부수적이므로, 쓰기 실패는 사유에 싣고 거부는 성립시킨다.
조용히 넘기지도 않는다(`⚠️ 감사 기록 실패(...) 이 판정은 보존되지 않았다`).

## 2. 영구 0 방지 (사용자 지시 ②)

v3 는 이력 전체를 미리 검사해 이상 행이 하나라도 있으면 `return 0` 이었다.
과거 행을 고치지 않으므로 그것은 **영구 0** 이다.

조치 — 무시하지도, 영구 차단하지도 않는다.
**앞에서부터 걸어 마지막 이상 지점을 찾고, 그보다 뒤의 행만 센다.**

- 이상 행을 건너뛰어 앞뒤를 잇지 않는다 → 연속성은 그 지점에서 끊긴다
- 그보다 뒤에 정상 거래일이 쌓이면 다시 센다 → **회복 경로가 있다**
- 이상 행이 가장 최근 끝에 닿아 있으면 셀 꼬리가 없다 → 0
  (`tests/test_audit_20260920.py` 가 고정한 코덱스의 엄격성 — 그대로 지켰다)

| 이력 | v3 | 지금 |
|---|---|---|
| 과거 역순 1회 + 이후 3연속 | 0 | **3** |
| 과거 중복 1회 + 이후 3연속 | 0 | **3** |
| 깨진 날짜 + 이후 3연속 | 0 | **3** |
| 최신 행이 중복 | 0 | 0 (유지) |
| 이력 전체가 역순 | 0 | 0 (유지) |
| `[9/22, 9/21, 9/23]` | 0 | 1 (9/23 만 — 건너뛰어 잇지 않는다) |

과거 행은 지우지 않는다. **읽는 방식만 바꿨다.**

## 3. 종목코드 검증 통일 (사용자 지시 ③)

같은 결함을 **세 번** 고쳤다. 규칙이 복사돼 있었기 때문이다.

```
2026-08-28  hyeoks_market_snapshot._is_code        isdigit() → 6자리
2026-09-15  hyeoks_account / account_source_adapter  isdigit() → [0-9A-Z]{6}
2026-09-20  naver_sources.consensus_estimates       \d{6}     ← 생산이 찾았다
            로그: `컨센서스 원천 실패 0015N0: Invalid stock code`
```

`tests/test_krx_code.py` 가 계좌 두 모듈만 묶어 뒀으므로 `naver_sources` 는
아무도 보지 않았다. 그래서 **정본을 `krx_code.py` 하나로 두고 공유**한다.

- 규칙: `[0-9A-Z]{6}` + 짧은 순수 숫자 zfill + `000000` 거부
- ⚠️ `str.isalnum()` 을 쓰지 않는다. **한글(`가나다라마바`)과 아라비아-인도 숫자
  (`٠١٢٣٤٥`)까지 참이다.** 넓히는 것과 아무거나 받는 것은 다르다
  (사용자 지시: "무조건 임의의 영문·숫자를 허용하지 말고").
- `naver_sources` 의 사본 2곳(`consensus_estimates`·`exact_code`)을 위임으로 교체
- `krx_code.py` 를 `FINGERPRINT_FILES` 에 추가 — 위임한 모듈이 지문에 없으면
  규칙이 바뀌어도 지문이 그대로다(3차 교차검증과 같은 계열의 구멍)
- `tests/test_krx_code.py` 가 이제 **정본과 모든 사본이 같은 답을 내는지** 묶는다.
  정상 영숫자 코드 · 너무 긴 경우 · 짧지만 숫자가 아닌 경우 · 특수문자 시험 추가.

발견 사실 하나: 짧은 **순수 숫자**는 거부가 아니라 zfill 이다(계좌 모듈의 기존 동작).
따라서 "길이 오류" 는 ① 너무 길다 ② 짧지만 숫자가 아니다 두 경우다.
내 첫 시험이 `"00593"` 을 거부 대상으로 적었는데 **코드가 아니라 내 기대가 틀렸다.**
