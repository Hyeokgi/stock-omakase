## 1. 정정 ① — 9/7 스위치 미실행은 **의도적 보류**였다

내가 커밋 `5a031d1` 메시지와 대화에서 *"§3-2-1 이 ON 을 사전등록했는데 배선이 안 됐다"*
라고 **미이행처럼** 썼다. **틀렸다.** §3-2-1 의 스위치 순서 조항이 이렇다 —

> `SUPPLY_V2_BAND` 가 §3-2 조건을 충족하면 **그쪽이 먼저**, `ENVELOPE_BAND` 는
> **다음 판정일(10/5)**. 미충족이면 9/7 에 단독 ON.

9/7 실측이 조건을 **충족**했다(수급TOP2 V2 80+ 구간 `N=27 · 평균 순알파 −3.110%`).
따라서 `ENVELOPE_BAND` 가 10/5 로 밀린 것은 **사전등록된 분기**다.

그리고 §3-1 이 같은 채널에 **폐기**를 지시해 두 사전등록이 충돌했고(§3-2-2),
2026-09-07 에 사용자가 **"오늘은 아무것도 하지 않는다"** 로 결정했다. 대가까지 표로
적혀 있다 — *"중기 채널이 4주 더 굶는다"*. `docs/수정공유_2026-09-07.md` 도 같은 날
*"둘 다 OFF. 9/7 에 아무 스위치도 켜지 않았습니다"* 로 명시했다.

**배선 누락이 아니라 기록된 결정이다.**

### 10/5 조항도 정확히 읽는다

내가 *"'또 미룬다'는 선택지에 없다"* 만 강조했는데, 바로 다음 줄에 예외가 있다 —
*"새로운 근거가 나와서 미루고 싶어지면 **그 근거가 무엇인지 먼저 여기 적고** 그 다음에 미룬다."*
막는 것은 연기 자체가 아니라 **근거 없는 연기**다. *"어떤 상황에서도 반드시 켠다"* 가 아니다.

## 2. 정정 ② — `_env = 0` 은 "−20% 이탈 종목 0개"가 **아니다** (코드 수정)

이게 더 중요하다. **스캐너 코드 자체가 과잉 진단을 찍고 있었고 내가 그걸 그대로 옮겼다.**

```python
# 관문① 은 네 조건의 곱이다
is_envelope_over_under = (이격 AND 거래대금 AND 상한가아님 AND 등락률≤10%)
```

거래대금 문턱은 평시 50억, 경계장 100억이다. 그러니 통과 수가 0이어도
**어느 조건에서 막혔는지 그 숫자 하나로는 갈리지 않는다.**
그런데 스캐너는 `_env == 0` 일 때 `"-20% 이탈 종목 자체가 0"` 을 찍고 있었다.

### 고친 것

| | 이전 | 이후 |
|---|---|---|
| 집계 | 복합 통과 수 하나 | **단계별** — 이격 → +거래대금 → +상한가·등락률 |
| 진단 문구 | `-20% 이탈 자체가 0` (단정) | 실제로 0이 된 **단계를 지목**한다 |

```
📊 [타점 인구조사] 스캔 710종목 · 관문① 단계별:
   이격 N → +거래대금(50억) N → +상한가·등락률 N → 과매도·역배팅 N건 · 반등미확인 N건
   ↳ 이격 조건 자체를 통과한 종목이 0 (거래대금 이전 단계)      ← _price == 0 일 때만
   ↳ 이격은 N종목 통과했으나 거래대금 문턱에서 전멸              ← 그다음
   ↳ 이격·거래대금은 통과했으나 상한가/등락률 조건에서 전멸
   ↳ 관문①은 통과했는데 반등 확인 게이트(관문②)에서 전멸
```

**따라서 9/14 에 확인된 사실은 "복합 조건 통과가 0건" 까지다.**
병목이 이격인지 거래대금인지는 **아직 모른다.** 단계별 수치는 9/15 관측부터 쌓인다.

> 그리고 `710/710 처리 · 실시간 API 실패 0건` 은 **실행 성공의 증거**이지
> 가격·거래량·시각의 정확성까지 인증하지 않는다. 그렇게 읽지 않는다.
