# 공동작업 허브 — Claude · Codex · 사용자

이 문서는 **비동기 기록 창구**다. 한 작업자가 남긴 기록을 다른 작업자가 저장소에서 읽고 이어 가기 위한 것이다.
**자동 메시지 전송도, 상시 감시도 제공하지 않는다.** 기록이 올라왔다는 알림은 없다. 읽는 쪽이 작업을 시작할 때 직접 최신 main 을 확인한다.
상대의 검토·승인·동의를 추정하지 않는다 — 상대 원문이 저장소에 없으면 '사용자 전달본' 으로 표시하고 그 한계를 적는다.

원격: <https://github.com/Hyeokgi/stock-omakase/blob/main/docs/공동작업_허브.md>

## 1. 작업 시작 시 (Claude · Codex 공통)

1. **최신 main 을 가져온다.** `git fetch origin main` 후 `origin/main` 의 이 허브와 아래 §4 의 열린 기록을 읽는다. 로컬 사본이 최신이라고 가정하지 않는다.
2. 읽는 순서: [`운영대전제`](운영대전제.md) → [`진행계획 v2`](진행계획_2026-09-13_v2.md) → 이 허브 → §4 기록 중 '열림' 인 것.
3. **지문 대상 파일을 바꾸기 전에 동결 규칙을 먼저 확인한다** (§6).
4. 작업이 끝나면 `docs/collaboration/` 에 기록을 만들고 §4 표에 한 줄을 추가한다 (§5).

## 5. 기록 만드는 법

파일: `docs/collaboration/YYYY-MM-DD_작성자_주제.md` (작성자는 `Claude` · `Codex` · `사용자`). 기록을 만들면 §4 표에 한 줄을 추가한다.
**자기 이름으로만 쓴다.** 다른 작업자의 판단을 대신 쓰지 않는다.

각 기록은 아래 항목을 모두 갖는다. 해당 없으면 '없음' 이라고 쓴다.

| 항목 | 쓰는 법 |
|---|---|
| 기준 커밋 | 작업을 시작한 main 의 커밋 해시 |
| 담당자 | 누가 수행했나 (지시한 사람이 있으면 함께) |
| 범위 | 한 것과 **하지 않은 것** |
| 실제 검증 결과 | 실제로 실행해서 얻은 수치·시험 결과. 실행하지 않은 것은 여기에 쓰지 않는다 |
| 미검증 사항 | 확인하지 못한 것, 가정한 것, 읽지 못한 자료 |
| 다음 행동 | 제안은 제안이라고 표시. 실행한 것과 구분 |
| 사용자 승인 필요 사항 | 이 기록의 어떤 것이 사용자 결정을 기다리는가 |
| 타인의 검토·승인 상태 | 상대가 검토했다는 **원문이 저장소에 있을 때만** 링크. 없으면 '없음' 또는 '사용자 전달본(원문 미대조)' |

보고서에는 **원격 링크와 커밋 해시**를 남기고, 로컬 경로(`C:\\...`, `/home/...`)만 전달하지 않는다.

## 6. 지문 대상 파일 — 동결 규칙

안정화 판정(Stability Gate)은 **하나의 고정 지문에서 연속 3거래일** 통과해야 끝난다. 지문 대상 파일을 바꾸면 연속 카운트가 0 으로 돌아간다.

- 대상 목록의 정본: `stability_gate.py` 의 `FINGERPRINT_FILES`. 현재 지문: `python3 -c "import stability_gate as G; print(G.fingerprint())"`.
- 2026-10-03 확인: `docs/`, `AGENTS.md`, `CLAUDE.md`, `hyeoks_theme_abc.py`, `hyeoks_quote_audit.py`, `hyeoks_theme_path_dict.py`, `hyeoks_research_daily.py`, `.github/workflows/research_daily.yml`, `tests/` 는 **대상이 아니다.**
  `omakase.py`, `hyeoks_analyst.py`, `hyeoks_run_freeze.py`, `stability_gate.py`, `.github/workflows/{main,ai_report,earnings_collector,consensus_aux,review_regressions,stability_finalizer}.yml`,
  `.github/workflow_states.py`, `price_levels.py`(2026-10-04 추가) 등은 **대상이다.**
- 대상 파일을 바꿔야 하면 바꾸기 **전에** 사용자에게 영향(연속 카운트 리셋)을 설명하고 승인을 받는다.
  이력: [`수정보고_2026-10-03_재시도묶음_동결업로드_판정조회.md`](수정보고_2026-10-03_재시도묶음_동결업로드_판정조회.md).

## 7. 쓰기 권한과 Codex 기록

Codex 는 GitHub 읽기는 되지만 신규 파일 생성이 `403 Resource not accessible by integration` 으로 거부되어 직접 기록하지 못했다(사용자 전달).
이 허브는 그 문제를 해결하지 않는다. 당분간의 방식:

- Codex 가 사용자에게 준 본문을 사용자가 전달하면, Claude 가 **'Codex (사용자 전달본)'** 으로 표시해 기록하거나 관련 문서에 옮긴다. 원문 문서와 대조하지 않았다면 그렇게 적는다.
- Codex 의 쓰기 권한이 생기면 Codex 가 직접 `docs/collaboration/` 에 기록한다. 권한 설정은 사용자 몫이다.
- `AGENTS.md` 는 이 저장소에 **없었으므로 새로 만들었다.** Codex 쪽에 별도의 AGENTS.md 가 있다면 내용을 합쳐야 한다 (사용자/Codex 확인 필요).

## 8. 공개 저장소 금지 목록

이 저장소는 **공개**다. 올리지 않는다: API 키·토큰·웹훅 URL·비밀번호 등 자격증명 · 비공개 원장 · 후보 풀 사본 · Drive 동결 번들 · 개인정보.
수치는 요약만 적고 원자료 행을 붙여 넣지 않는다. 의심되면 올리지 말고 사용자에게 묻는다.

## 9. 고정 제약 (요약 — 정본은 `운영대전제.md`)

- 과거 보고서·과거 판정 기록을 고치지 않는다. 신호가 적거나 성과가 나쁘다는 이유로 문턱을 낮추지 않는다.

- PR 은 사용자가 요청할 때만 만든다.
