# 네이버 의존 진단 경보 보완 — Claude 전달

## 원인과 수정

구 HTML 8개가 사라진 것은 실제 원천 변화지만, 대체 API가 정상인데도
구 HTML의 FATAL 등급으로 전체를 '치명적 파손' 처리하던 경보 판정이 부정확했다.
기준선을 실패 상태로 덮거나 경보를 끄지 않고 기능 단위로 판정하도록 변경했다.

- `naver_health_policy.py`: 수급/위험종목/테마목록/테마구성/시가총액/뉴스/검색상위의
  대체 경로를 명시적으로 묶는다. 하나라도 검사 통과면 대체 성공을 기록하고,
  해당 기능의 모든 경로가 실패하면 기능 장애로 알린다.
- 모닝 뉴스·정확 검색·컨센서스·가격·일봉 등 독립 필수 검사는 별도로 유지한다.
  일부 정상 API가 다른 기능의 실패를 숨기지 않는다.
- 구경로 단독 실패/중복 경로 열화는 JSON/텍스트 artifact에 남기되 반복 Telegram 알림은 생략한다.
  전종목 벌크 대체 후보와 시간외 보조 필드만 참고 항목으로 분류했다.
- 대표종목 삼성전자의 시세 시각과 일별 수급 날짜 검사 추가.
  검토된 휴장 달력을 사용하며 장전/주말/휴장에는 직전 예정 거래일을 고려한다.
  09:10~15:20 시세 10분 초과 지연, 날짜 지연, 미래 시각, timezone 누락을 거부한다.
  수급은 당일 미확정치를 강요하지 않고 직전 예정 거래일까지 있어야 한다.
  10분은 수집 이상 감지용 잠정 운영 허용치이며 실전 주문용 실시간성 보증이 아니다.
- 위험종목 JSON에서 필수 상태 필드 누락/null을 검사한다.
- `health_report.json` 구조화 결과와 검사 실행 ID를 보관한다.
  `notify_naver_health.py`가 이를 재평가하며, 텍스트의 ❌ 검색으로 장애를 결정하지 않는다.
  파일 누락/버전 오류/실행 ID 불일치/검사 누락/종료코드 불일치는 정상으로 숨기지 않는다.
- Telegram HTTP 응답 및 ok=false도 실패로 처리한다.

## 검증

- unittest 196개 통과(기존 180 + 신규 16).
- 2026-09-14 15:37 KST 실제 진단: 35개 검사 중 구 HTML 8개 실패,
  기능 단위 경보 0개, 대체 경로 통과 8개, 종료코드 0.
- 구 HTML 실패는 기준선 회귀 로그에 그대로 남는다. 원천 변화의 역사 기록이다.
- 정상 결과의 Telegram 알림 생략도 함수로 검증했으며 실제 메시지는 보내지 않았다.
- 실제 Google Sheets는 읽거나 쓰지 않았다. 유료 AI/주문/전략 변경도 없다.

## 남은 범위

출력 상태는 `sources_available`, 시트 쓰기 검증은 `not_checked`다.
대표종목 시세/수급 이외 모든 종목과 모든 필드의 신선도를 인증하지 않는다.
테마·뉴스 등은 기존 형태/건수 검사이며 전체 종단간 품질 인증은 아니다.
예정 휴장 달력은 임시휴장까지 실시간 인증하지 않으며 범위 밖은 검사 실패로 알린다.
기존 주 1회 일정은 유지한다. 상시 실시간 장애 감시를 새로 켠 것은 아니다.
