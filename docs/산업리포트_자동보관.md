## 예약 작업 절차

1. Google Drive 스킬을 읽고 폴더 메타데이터와 전체 파일 목록을 페이지 끝까지 확인한다.
2. `data/research_private/sync_state.json`의 마지막 **전체 검증 성공일**을 읽는다.
   없으면 Drive의 보관 manifest로 복구한다. 최초 확인된 성공일은 2026-09-13이다.
3. 마지막 성공일에서 14일을 뺀 날짜(단, 최초 감사 범위 2026-08-26보다 이전으로 가지 않음)를 시작일로 삼는다.
   누락된 실행을 오늘 기준 14일로 잘라 버리지 않는다.
4. `python hana_research.py --since YYYY-MM-DD --refresh`를 실행한다.
   Python 3 표준 라이브러리만 필요하다. TLS 검증을 끄지 않는다.
   페이지 반복/파싱 실패/비PDF/수집 상한 초과는 성공으로 처리하지 않는다.
5. 로컬 manifest와 이전 보관 manifest, Drive의 전체 목록을 대조한다.
   새 형식 파일명에 해시 앞 12자가 있지만 **내용 동일 판정은 전체 SHA256**을 사용한다.
   기존 수동 업로드와 중복이 의심되면 원문을 내려받아 해시를 비교한다.
   해당 비교를 하지 못한 파일은 이름이 다르다는 이유만으로 미저장 확정하지 않는다.
6. 중복을 제거한 신규/변경 PDF만 연결된 사용자 Drive 인증으로 업로드한다.
   실행당 업로드 상한 60개. 초과하면 backlog를 기록하고 성공일을 전진시키지 않는다.
   업로드 응답이 불명확하면 재조회 전 재시도하지 않는다.
7. 각 파일의 ID·이름·MIME·부모 폴더·크기를 재조회하여 검증한다.
   클라우드 바이트의 SHA256을 다시 다운로드하여 검증한 것은 아니라는 점을 구분한다.
8. 게시일/게시 시각, 최초 관측 시각, 내용 관측 시각, 출처 ID/URL, 전체 해시,
   크기, Drive ID, 중복 연결을 비공개 로컬 manifest 및 Drive 날짜별 JSON에 보존한다.
   같은 날 재실행은 새 타임스탬프 이름을 사용하고 기존 기록을 덮어쓰지 않는다.
   게시 시각은 웹 목록 기준이다. PDF 파일명에 적힌 미래 날짜를 관측 시각으로 사용하지 않는다.
9. 전부 검증했을 때만 sync_state.json의 성공일과 최신 보관 manifest ID를 갱신한다.
   실패/미처리 파일이 있으면 기존 성공일을 유지한다.
10. 새 자료가 없고 상태가 같으면 알리지 않는다. 신규 보관, 실패, 인증 만료, 필요한 조치만 알린다.

예약은 유료 Gemini 호출, 종목 선정, 코드 수정, git push, 기존 PDF 삭제/덮어쓰기,
공유 권한 변경, 주문을 수행하지 않는다. 인증 실패를 서비스계정 비밀키 추출로 우회하지 않는다.

## 분석 변경과 한계

- 폴더 이름 대신 고정 ID, Drive 전체 페이지, 동일 내용 MD5 중복 확인.
- 최신 파일명 순으로 최대 8건. 파일명 날짜는 큐 우선순위일 뿐 게시일 인증이 아니다.
- 20분이 지나면 새 요청을 시작하지 않으며 GitHub 60분이 실행 전체의 하드 상한이다.
  8건은 요청 건수 상한이고 PDF 길이/모델 가격에 따라 비용은 달라진다.
- 원문 명시 추천만 최대 2개, 없으면 무추천. 악재도 남긴다.
  인용문 존재를 검사하지만 LLM 인용의 진위/상장 종목 매칭까지 독립 인증한 것은 아니다.
- 직전 원문 비교가 없으므로 변화 여부는 `unverified`.
  아직 의미 변화 탐지기나 검증된 자동 제외 분류기가 완성된 것은 아니다.
- A열은 실제 분석일을 유지한다. F열에 원문일(모델 추출, 미인증), Drive ID,
  근거, 입력 버전 `report-input-v2`를 남긴다.
  소급 수집/늦은 분석을 당시 이용 가능한 과거 신호로 백테스트에 넣지 않는다.
- 기존 A:G를 지우지 않고 건별 RAW append로 저장한다.
  append 응답이 불명확한 실패는 즉시 중단하며 다음 실행에서 원장을 재조회한다.
- 기존 소비자의 날짜 정리/중복 제거 로직까지 개편하지 않았다.
  새 원문 추출 정책 전후 결과를 동일 정책 표본으로 섞지 말아야 한다.
- 기업리포트/공시/다른 증권사 자료는 아직 확대 수집하지 않는다.
  후보 종목 코드 매핑·공시 수신 시각·중복 정책을 정한 뒤 별도 연결한다.
