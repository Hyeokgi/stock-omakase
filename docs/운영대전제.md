# HYEOKS 운영 대전제

버전: operating-principles-v1 / 합의일: 2026-09-13 / 근거: 사용자와의 운영방안 합의.
대상: Claude Code 및 이 저장소에서 전략·수집·검증·운영을 다루는 모든 협업자.

## 1. 프로젝트 목적

목적은 오류 없는 수집기에서 끝나는 것이 아니라, 축적한 데이터로 수익에 기여하는
선정 조건을 찾아 리포트 스윙과 종베의 실제 운용 기준을 개선하는 것이다.
월 또는 분기 15~20%는 사용자가 추구하는 도전 목표다. 둘 중 어느 기간을 공식 목표로
삼을지는 아직 확정하지 않았다. 보장 수익·입증된 기대수익·의무 합격 문턱으로 취급하지 않는다.
목표 수익률에 맞을 때까지 과거 데이터의 조건·비중·평가기간을 조정하지 않는다.

## 2. 확정한 운영 방향

- 사용자는 직장인으로 장중 지속 감시와 재량 대응이 어렵다. 이 제약을 설계에 반영한다.
- 두 전략을 병행한다: **리포트 선정 종목은 스윙 보유**, **종베는 익일 시가 전량 청산**.
  여기서 양방향은 두 전략의 병행이며 롱/숏·공매도 전략 도입을 뜻하지 않는다.
- 종베 진입 연구 기준은 **15:05 슬롯**이다. 의도한 시각, 실제 데이터 시각,
  가정 체결가와 실제 체결가는 구분한다. 사용자의 의도 없이 종가/15:20 진입으로 바꾸지 않는다.
- 종베의 기본 청산은 **다음 거래일 시가 전량 청산**이다. 이익·손실 여부와 무관하다.
  손실 포지션을 임의로 스윙으로 전환하거나 회복할 때까지 보유한 것으로 계산하지 않는다.
- 큰 갭상승 시 부분 익절 후 트레일링은 사용자가 언급한 미래 대안이다.
  현재 기본 전략에는 포함하지 않는다. 향후 별도 검증과 운영 여건 확인 후 결정한다.
- 사용자가 감내 가능하다고 밝힌 계좌 하락 한도는 **고점 대비 약 10%**다.
  입출금 효과를 구분한 계좌 전체 평가액(미실현 손익 포함) 기준으로 다룬다.
  원금 대비 손실이나 개별 종목 손절 10%와 혼동하지 않는다.
  이는 감내 한도이지 손실 보장·정확한 자동 손절 발동점이 아니다. 갭과 체결 실패로 초과할 수 있다.

## 3. 잠정 가정 — 아직 최적값이나 실행 설정이 아님

- 동시 보유 **4~5종목**은 사용자의 예상이다. 계좌 검증 시 우선 비교할 가정이며
  매일 반드시 채워야 하는 수가 아니다. 정확한 상한은 검증 후 정한다.
- 리포트/종베의 자금 배분, 현금 비중, 종목별·테마별 상한은 미확정이다.
- 10%에 이르기 전 신규 매수 축소/중단·위험 감축 규칙의 구체적 발동 수치는 미확정이다.
- 스윙의 정확한 보유기간·청산 규칙, 과매도 반등 외 눌림목 전략 추가도 자동 승인하지 않는다.
- 시가 가격의 시장/거래소 정의와 주문 제출 시각·유형·체결 처리도 구현 전에 명시한다.
  기존 KRX 일봉 시가를 연구 대용값으로 써도 실제 체결 가능성을 인증한 것은 아니다.

## 4. 다음 검증의 방향

- 종베는 다음 날 장중 상승률이나 종가 수익률이 아니라 **15:05 진입 → 익일 시가**의
  비용 후 수익을 주 평가 대상으로 삼는다. 장중/종가 결과는 별도 참고값이다.
- 기본 수익률은 `(익일 시가 가정 체결가 / 15:05 가정 체결가 - 1) - 비용`이다.
  주문 지연·스프레드·슬리피지·세금/수수료·체결 불가를 별도로 점검한다.
  15:05→당일 종가 이동분을 다시 비용으로 빼는 이중 계산을 하지 않는다.
- 대장 선정 효과와 추가 조건 효과를 분리한다: 당시 투자 가능 후보군 → 당시 테마 대장
  후보 → 추가 조건 통과 후보. 오른 종목뿐 아니라 실패한 후보와 무신호일도 보존한다.
- 다음 날 결과로 대장·테마 소속·진입 조건을 소급 정의하지 않는다.
- 리포트는 동일 후보군에서 단순 규칙 대비 AI의 추가 가치를 구분한다.
- 최종 평가는 개별 추천 평균이 아니라 **같은 계좌 자금으로 실행 가능한 비용 후 성과**다.
  동시 보유·현금·자금 중첩·기회 포기·미청산 포지션과 최대낙폭을 포함한다.
- 두 전략이 같은 종목을 보유하면 매수분별 청산 규칙은 구분하되 위험 노출은 합산한다.
  다른 종목이라도 같은 테마면 자동으로 분산됐다고 판단하지 않는다.

## 5. 점검·변경 원칙

정해진 날짜의 중간점검은 **선정기준을 발견하고 개선하기 위한 과정**이다. 수집만 무기한
유지하는 것이 목적은 아니다. 성과 차이를 설명하는 근거가 생기면 새 기준을 제안할 수 있다.

오류는 즉시 바로잡되, 신호가 적거나 최근 성과가 나쁘다는 이유만으로 전략 문턱을 낮추지 않는다.
기준 발견에 사용한 데이터의 성적은 탐색 결과로 표시하고, 개정 기준은 이후 미사용 데이터에서
검증한다. 시도한 조건·실패한 가설·정책/입력 버전·적용 시각을 남긴다.
정기 점검 자체를 반복검정 오류율 통제나 독립 재현으로 취급하지 않는다.
통계적 승인 여부는 별도 추론 계획과 실제 구현 검증에 따라 판단한다.

이 원칙과 충돌하는 변경은 사용자에게 이유와 영향을 설명하고 승인을 받은 후 문서 버전을
갱신한다. 과거 보고서는 삭제하거나 당시 기준을 새 기준으로 소급 변경하지 않는다.

## 6. 문서와 구현의 구분

이 문서의 추가는 **방향의 합의 기록**이지 자동 주문·배분·손절 실행의 승인이 아니다.
2026-09-13 본 문서 추가 시점에는 문서와 연결 안내만 변경했다.
수집기·분석기·시트·주문 시스템에 모든 원칙이 구현됐다고 간주하지 않는다.
기존 연구안의 익일 종가 라벨은 과거 가정으로 보존하고, 향후 종베 기본 검증은 익일 시가로
정렬한다. 기존 분석기의 라벨 변경에는 별도 코드 변경·테스트·버전 기록이 필요하다.
