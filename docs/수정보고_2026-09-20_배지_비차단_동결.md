## 1. 무엇이 문제였나 — 실측으로 확인한 경로

코덱스 `16424d2` 가 `main.yml` 에 배지 보존 스텝을 넣었다. 기능·설계는 타당하다.
그런데 `--upload` 가 실패 시 **exit 1** 이었고, 그것이 Gate 까지 이어졌다.

```
배지 업로드 실패 → 스텝 exit 1 → main.yml run = failure
  → workflow_states 가 "failure" 보고
  → evidence_builder.no_unexplained_failure = False
     사유: workflow=['main.yml=failure']
  → 그 거래일 Gate FAIL
```

연구 자료 수집 실패가 생산 안정화 판정을 떨어뜨린다.
`consensus_aux.yml` 를 분리한 이유와 **같은 범주**다 —
*"보조 자료의 실패가 주 산출물의 판정을 흐리지 않게 한다."*

**닿지 않는 경로가 아니다.** 스캐너 영수증은 `if new_rows:` 안에서 나오고
`new_rows` 는 EOD 창(15:00~15:30)에서 채워진다. 배지 관측 창은 14:20~15:10 이라
**15:00~15:10 에서 겹친다.** GAS 가 10분 간격이므로 영수증 생성 회차가 그 구간에
놓일 수 있다.

실측한 실패 경로 두 가지 — 둘 다 `archive() = 1` 이었다.

| 경로 | 비고 |
|---|---|
| Drive 업로드 실패(id 없음/예외) | 네트워크 호출이므로 평시에도 가능 |
| `completed.json.gz` 없음 | **업로드가 성공해도** 불완전 표본이면 실패로 셌다 |

- `archive()` 의 반환값(실패 건수)은 그대로다 — 호출부·시험이 쓴다.
- **성공했는데 실패 상태를 남기지 않는다**, **관측 창 밖(하루 대부분)은 실패가 아니다.**

## 7. 보고 표현 정정 — 코덱스 지적 3건 (2026-09-20 후속)

코덱스가 §2 의 표현 세 가지를 지적했다. **셋 다 맞았고**, 실측으로 확인한 뒤 고쳤다.
코덱스의 판단대로 동결을 즉시 깨야 할 생산 장애는 아니었지만, 카운트 시작 전이라
지금 고치는 편이 낫다(첫 카운트는 월요일 9/21 이고 아직 PASS 행이 없다).

### ① "항상 exit 0" 은 과한 표현이었다

처리한 실패 경로만 비차단이었다. `archive()` 안의 **미포착 예외**는 그대로 올라갔다.
실측: `archive()` 첫 줄 `import hyeoks_run_freeze` 는 폴더 루프 **밖**이라
per-bundle try/except 가 덮지 않는다. 그 모듈이 깨지면 CLI 가 죽는다.

조치 — 두 겹으로 막고, 막지 못하는 한 겹을 명시한다.
- CLI 가 `archive()` 호출을 감싸 **미포착 예외도** 경고 후 exit 0
- `main.yml` 에 셸 가드(`if ! python ...; then echo ::warning:: ; fi`).
  **모듈 로드 실패**(문법 오류·의존성 부재)는 파이썬 코드가 돌기 전이라
  모듈 안에서 막을 수 없다 — 그 마지막 한 겹을 셸이 맡는다.
  GitHub 의 `bash -e` 모드에서 exit 0 임을 확인했다.

### ② "N건" 이 실제 건수가 아니었다

`archive()` 가 `1 if failures else 0` 을 돌려줬다. 종료코드로 쓰던 잔재다.
그 값을 요약에 실으니 **5건이 실패해도 "1건" 으로 보고**됐다(실측).
개별 경고는 건마다 남았으므로 정보가 사라진 것은 아니지만, 요약이 틀렸다.

조치 — 종료코드로 더는 쓰지 않으므로 **실제 건수**를 돌려준다.
`if archive():` 는 그대로 동작하고, 코덱스 시험 3건(단일 번들)도 그대로 통과한다.

### ③ "주 산출물은 정상" 은 이 코드가 확인하지 않는다

정확한 의미는 **"배지 실패만으로 주 시스템을 실패 처리하지 않는다"** 이다.
주 산출물 자체의 정상 여부는 `evidence_builder` 의 7기준이 따로 판정한다.
메시지를 그렇게 고치고, 시험이 옛 문구의 재등장을 막는다.
