## 1. 🔴 §6-7 질문 1 — 유니버스 문제가 아니라 대장 판정 문제다

로드맵이 2026-08-27 에 등록한 질문:

> *"그날의 진짜 주도주(시장 전체 거래대금 상위)를 우리 스캐너가 후보에 넣었는가.
> **못 넣었다면 §6-6 의 부진은 선정 기준이 아니라 유니버스의 문제다.**"*

13일 × 시장 거래대금 상위 5 = **65 종목**을 우리 단계에 통과시킨 결과:

| 단계 | 남은 수 | 비율 |
|---|--:|--:|
| **A** 투자 가능 후보군 | **65** | **100%** |
| **B** 테마 대장 판정 | 11 | **17%** |
| **C** 시스템 추가 조건 | 4 | **6%** |

**유니버스 문제가 아니다.** 시장 상위 5는 **전부, 예외 없이** A 안에 있었다.
빠지는 곳은 **B — 대장 판정**이다. 여기서 **83%가 사라진다.**

날짜별로는 **13일 중 5일(9/02·03·04·08·14)이 0개** — 그날 시장 거래대금 상위 5 중
단 하나도 대장으로 잡히지 않았다.

이것은 로드맵 §6-7 이 적어 둔 의심의 **실측 확인**이다:

> *"현재 판정은 상대 순위이고 거래량 급증 조건이 없다 — 평소에도 거래가 많은 종목이
> 테마 안에서 1등 하면 대장이 된다. 고수가 말하는 '평소보다 급격히 늘어 시장을
> 주도하는 종목' 과는 방향이 다르다."*

방향이 다른 정도가 아니라 **거의 무관**했다.

## 4. 정의 — 내가 고른 문턱이 하나도 없다

| 계층 | 정의 | 출처 |
|---|---|---|
| **A** | 거래대금 ≥ 50억 · 거래정지·관리종목 제외 · 현재가>0 | `hyeoks_closing_bet.MIN_TURNOVER` |
| | *테마 소속은 A 의 조건이 아니다* — 넣으면 B−A 에 테마 소속 효과가 섞인다 | |
| **B** | 테마 내 거래대금 상위 5 중 등락률 1위 | `omakase.py:604·611` |
| | + 1등이 2등의 5배 넘는 테마는 통째로 배제 | `omakase.py:607` |
| | 소속 테마는 `topThemeNo` 하나만 — `themeNos` 전부 쓰면 한 종목이 여러 테마의 대장이 되어 중복 | |
| **C** | B 중 거래대금 ≥ **100억** 그리고 등락률 **3~29.5%** | `omakase.py:1709·1710·2013~2015` |
| **B_시장** | 시장 전체 거래대금 상위 5 | §6-8 조건 1 |

**C 의 문턱은 전부 시스템에 이미 있던 값**이다. 오늘 고른 값이 하나도 없다.
문턱을 오늘 고르면 그것이 사후 맞춤이고, 시스템 값을 쓰면 무엇을 재는지가 명확하다 —
**현행 시스템이 실제로 거르는 그 조건의 효과**를 잰다.

`C_VARS`(오후수급비·고가유지율·등락률·상한가여부)는 **계산해서 기록만** 한다.
**코드에 문턱이 없다.** 이 변수들의 문턱은 별도 사전등록으로 정한다.

   없어 뺐다. 실제 시스템의 C 는 이보다 작다.
