# 우선 전략 모의 평가기 사용법

`python priority_trials.py --input PRIVATE.json`

준비된 JSON만 읽는 오프라인 도구다. 자동 수집/선정/주문/계좌 계산/통계적 채택 도구가 아니다.
현재 데이터 형식은 `priority-trials-v1`이며 기존 원장의 과거 마크를 이 형식으로 바꿔 미래
검증이라고 부르면 안 된다. 실사용 기록 어댑터는 아직 연결하지 않았다.

## 필드

| 필드 | 내용 |
|---|---|
| schema | priority-trials-v1 |
| as_of | 시간대 포함 평가 기준 시각 |
| calendar_evidence | 거래일/개폐장 시각 근거 참조 |
| sessions | 날짜 오름차순 dict: `{날짜: {open: 시간대 포함 시각, close: 시간대 포함 시각}}` |
| policies | report_short/report_mid/closing_1505별 아래 정책 |
| days | 전략별 일자 기록. 선정 없음과 기록 누락을 구분 |
| signals | 고정된 전략별 선정 기록 및 모의 체결 관측 |

정책: version, rule_source, frozen_at, start_date, buy_fee, sell_fee, buy_slippage, sell_slippage.
비용/슬리피지는 0~1 미만 비율이고 생략할 수 없다. 0을 쓰면 무비용 가정이며 실측을 뜻하지 않는다.
규칙과 수치는 사용자가 확정한 원본을 참조한다. 코드가 임의 선정 문턱을 만들지 않는다.

일자 기록: strategy, date, recorded_at, source, policy_version, signal_ids.
아무 것도 선정하지 않은 날도 빈 signal_ids로 그 당시 기록해야 한다. 기록 누락은 no_signal이 아니다.
종베는 해당 일자 15:05까지, 리포트는 다음 거래일 시가까지 기록해야 한다. 장 종료 후 발행하는
리포트를 허용하며 선정 시각은 기록 시각보다 늦을 수 없다. 정책 등록 이전 기록은 허용하지 않는다.

선정 기록: id, strategy, code(6자리), signal_date, selected_at, source, policy_version,
entry 및 exit. 각 체결 관측은 `{at, price, tradable, source}`를 가진다.
시가 진입은 실제 거래일 달력의 개장 시각, 종베는 신호일 15:05, 청산은 해당 거래일 폐장 시각이다.
가격은 유한 양수이며 거래 가능 상태를 해당 시점에서 확인해야 한다. false/결측은 실패로 남고
체결 처리하지 않는다. 예정 청산 불가 시 실제 지연 청산 추적은 후속 구현 과제다.

15:02 스냅샷 값을 15:05 실제 체결값으로 바꿔 넣지 않는다. 가격 수신 지연을 허용하려면 별도
정책과 타임스탬프 검증이 필요하다. 현재 정확한 시점 계약은 기준선을 위한 것이며 관측 저장을
15:05 정각으로 위장하라는 뜻이 아니다. 실제 주문/호가 수량 충족을 자동 보증하지 않는다.

## 출력과 한계

전략별 policy_missing/data_blocked/paper_only와 모든 거래 상태가 따로 나온다.
누락이 있어도 확보된 종료 거래 통계를 볼 수 있으나 표본 전체 성과로 해석하면 안 된다.
미성숙은 대기로 남고 승률에서 제외된다. 가격 누락을 0% 수익으로 채우지 않는다.
모든 상태의 live_approved는 false다. 결손 상태가 있으면 CLI 종료 코드 2지만 다른 전략
결과도 비공개 출력 폴더에 보존한다. 정책 미등록은 결과에 명시하며 성공 종료가 투자 승인은 아니다.

data/priority_private에 실행별 입력/결과/소스/해시를 저장한다. 경로는 Git 무시 대상이며
원격 보존은 미연결이다. 형식 예시는 tests/test_priority_trials.py의 합성 fixture를 참조한다.
실제 기록 존재/시각을 해시만으로 인증하지 못하므로 당시 저장 원본과 접근 이력을 따로 보존해야 한다.

현금·동시 보유·종목/테마 한도·MDD·대조군 대비·유의성·과최적화는 이 도구의 계산 대상이 아니다.
이 도구를 기존 계좌 NAV 검증의 대체재로 쓰지 않는다. 목적은 세 전략의 미래 기록 연결을
과거 원장 복원 및 Q5 완료와 분리해 조기에 시험하는 것이다.
