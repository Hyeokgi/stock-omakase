# 1.5단계 결론 — 픽 확대는 답이 아니다. 대신 다른 게 보였다

작성: 2026-09-16 (KST) · 근거: `docs/시그마실측_2026-09-16.md` (원장 300픽)
선행: `docs/시그마결론_2026-09-16.md` §3

> **탐색 결과다. 판정이 아니다.** 아래 수치는 이미 판정에 쓴 데이터에서 사후에 찾은 것이므로,
> 이걸로 규칙을 바꾸면 **같은 데이터로 검증할 수 없다**(운영대전제 §5).

---

## 0. 먼저 정정 — "달력 시간 0" 은 틀린 약속이었다

1.5단계를 "과거 데이터로 재면 달력 시간 0"이라고 적었는데 **틀렸다.**
"TOP3·TOP5 였다면 알파가 얼마였나"를 재려면 **뽑히지 않은 후보의 수익률**이 필요한데
그게 어디에도 없다:

- `omakase.py:3129` 의 `candidate_pool` 은 메모리에서 계산되고 **TOP2 만 원장에 남는다**
- 과거 순위 재구성도 불가능하다 — 점수가 그날의 테마 순위·뉴스·정적DB 등
  재현 불가능한 상태에서 계산된다(`analyze_single_stock` 인자)
- `data/scanner_census` 는 퍼널 **카운트**만 있고 순위 목록이 없다

대신 **뽑힌 둘 사이의 순위 효과**는 잴 수 있었다. 그게 아래다.

## 1. 차트TOP2 — V1 에 양의 순위 신호가 **관측됐다**

| | 값 |
|---|---|
| 순위 효과 (1순위 − 2순위) | **+4.36%p** (SE 3.39 · 1순위가 이긴 날 16/21) |
| V1 <40 | −6.27%p (N=1) |
| V1 40~60 | −1.54%p (N=6, 승률 33%) |
| V1 60~80 | −0.36%p (N=22, 승률 45%) |
| **V1 80+** | **+2.79%p** (N=61, 승률 62%) |

**관측된 구간평균은 단조 증가한다.** 다만 "V1 이 정보를 담고 있다"까지는 아직 강하다 —
낮은 구간은 N=1·6 으로 비교 근거가 못 되고, 순위 효과 +4.36%p 도 SE 3.39 로 유의하지 않다.
정확한 표현은 **"현재 탐색표본에서 V1 과 알파 사이에 양의 순위 신호가 관측됐다"** 이다.

### ⚠️ 2026-09-16 철회 — 픽 확대의 기간 효과는 **판정 불가**

여기 원래 "2픽 45일 → 3픽 76일 → 5픽 167일" 표가 있었고
"픽을 늘리면 기간이 늘어난다"고 결론지었다. **철회한다.**

그 표는 TOP3~5 데이터가 아니라 **두 겹의 가정**이었다:

1. "현재 TOP2 는 둘 다 80+ 이고, 추가 3개는 60~80 일 것이다" — 근거 없다.
   실제 3~5위가 80+ 일 수도, 40~60 일 수도 있다.
2. 픽 수 증가 시 `σ/√k` — 같은 날 픽의 독립성 가정이다.
   수급TOP2 실측이 이미 이 가정을 깨고 있다(감소율 0.92 vs 예측 0.75).

현재 데이터가 말해 주는 것은 여기까지다:

> **TOP2 안에서 V1 순위와 성과 사이에 양의 순위 신호가 관측됐다.
> 따라서 TOP3~5 가 TOP2 와 같은 δ 라고 가정하면 안 된다.**

"그래서 픽을 늘리면 기간이 반드시 늘어난다"까지는 갈 수 없다.
**픽 확대 효과는 `rank_pool` OOS 데이터로 직접 측정한다**(2026-09-17~ 적재 시작).

## 2. 수급TOP2 — 상위 구간에 **하방 꼬리** 가 반복 관측된다

| | 값 |
|---|---|
| 순위 효과 (1순위 − 2순위) | **−3.02%p** (SE 2.48 · 1순위가 이긴 날 13/23) |
| V2 <40 | −5.27%p (N=1) |
| **V2 40~60** | **+4.47%p** (N=18, 승률 61%) |
| V2 60~80 | −1.44%p (N=8, 승률 50%) |
| **V2 80+** | **−3.09%p** (N=30, 승률 27%) |

⚠️ **"점수가 높을수록 나쁘다"는 정확하지 않다.** `<40` 도 −5.27%p 이므로
전체 모양은 단조 감소가 아니라 **역U자**에 가깝다(omakase.py:3137 도 원래 그렇게 적었다).

그리고 순위차를 보면 평균은 −3.02%p 인데 **1순위가 이긴 날은 13/23** 이다.
평균에서는 1순위가 나쁜데 승패에서는 오히려 더 자주 이겼다 —
**몇 번의 큰 1순위 손실이 평균을 끌어내리고 있을 가능성이 크다.**

따라서 지금 세울 가설은 "순위가 역전됐다"가 아니라
**"V2 고득점, 특히 80+ 구간에 큰 하방 꼬리 또는 소진 효과가 있는가"** 이다.

이건 새 발견이 아니라 **재확인**이다. `omakase.py:3137` 이 2026-08-07 실측(N=189)으로
이미 같은 것을 기록해 뒀다 — *"80~100 은 −5.89%(승률 22%)로 최악… 수급TOP2 는
'V2 상위 2개'를 뽑으므로 하필 이 최악 구간을 집게 된다."*

**즉 수급TOP2 가 9/07 에 폐기 판정(평균 −1.11%, t=−0.32)을 받은 이유가 여기 있을 수 있다.
채널이 나쁜 게 아니라 선정 규칙이 거꾸로일 가능성이다.**

## 3. 그런데 이걸로 규칙을 바꿀 수 없다

`omakase.py:3143` 에 `SUPPLY_V2_BAND` 스위치가 이미 준비돼 있고 기본 밴드가 45~79 다.
위 실측(40~60 이 +4.47)은 그 방향을 지지한다. **그래도 지금 켜지 않는다.**

- 이 수치는 **이미 판정에 쓴 데이터**에서 사후에 찾았다. 여기서 밴드를 고르고
  같은 데이터로 검증하면 순환이다(운영대전제 §5).
- `CLAUDE.md`·§3-2-2 가 `SUPPLY_V2_BAND` 를 **사용자 승인 사항**으로 못박고 있다.
- 구간 N 이 얇다(60~80 은 8건). −1.44%p 를 확정으로 볼 수 없다.
- omakase 주석 자신이 이미 같은 이유로 보류해 뒀다 —
  *"문제 구간 표본이 아직 N=9로 얇아… 로직을 바꾸면 그 시점부터 표본 성격이 달라져,
  변경 전/후를 비교할 기준선이 사라진다."*

## 4. 정직한 결론

**픽 확대는 기간 단축의 답이 아니었다.** 차트TOP2 에서는 오히려 기간을 늘린다.
"최단시간"을 σ 로 푸는 길은 여기서 닫혔다.

남은 길은 둘뿐이고 둘 다 σ 가 아니라 **δ** 쪽이다:

1. **δ 를 키운다** — 더 좋은 선정. 수급TOP2 의 역방향 순위가 그 후보지만,
   **미사용 구간에서 검증해야** 쓸 수 있다.
2. **δ 가 작다는 걸 받아들이고 기간을 감수한다** — 차트TOP2 기준 45~167거래일.

어느 쪽이든 지금 실자금을 넣을 근거는 없다. Gemini 의 NO-GO 는 유지된다.

## 6. 한계

- 순위 효과는 **상위 2개 안에서의** 기울기다. 3~5위로의 외삽이 아니다.
- 짝 21·23일은 얇다. SE 3.39·2.48 이므로 +4.36 도 −3.02 도 유의하지 않다.
- 구간별 N 이 1~61 로 편차가 크다. N=1 구간은 값으로 읽지 않는다.
- §1 의 δ 대입은 "상위 2개는 항상 80+" 라는 **가정**이다.
- 이 문서는 어떤 전략도 승인하지 않고, 어떤 규칙 변경도 승인하지 않는다.
