## 확인한 것

**1. `_incidents` 는 거래일 영수증이 아니다 — 시험이 아니라 코드로 확인했다.**
`data/receipts` 를 읽는 경로는 `production_receipt.load(day, root)` 하나뿐이고
`dir_for(day)` = `data/receipts/<날짜>` 만 훑는다. `_incidents` 는 날짜 폴더 밖이므로
어떤 거래일 조회에도 들어가지 않는다. 깨진 줄로 세어져 `no_unexplained_failure` 를
떨어뜨리는 일도 없다. 코덱스의 시험도 같은 것을 주장하고, 그 주장은 사실이다.

`.github/receipt_commit.sh` 는 `if: always()` 로 돌고 `git add -- data/receipts` 이므로
`_incidents` 파일도 공개 저장소에 커밋된다. 실려 나가는 항목은 스키마·상태·관측시각·
phase·`cycle_date: null`·`sheet_access_started: false`·복구안내뿐이다. 종목·점수는 없다.

**2. 지연 수집은 여전히 거부한다.** `record_cycle_rejection()` 뒤에 `raise` 가 남아 있어
거래일이 불명확한 회차는 시트에 손대기 전에 죽는다. 이 패치는 지연을 자동으로 전날에
귀속시키지 않는다. 9/21 earnings #77 · consensus #3 같은 회차는 앞으로도 실패하고,
다만 그 실패가 왜 났는지가 파일로 남는다.

**3. 08:30 재예약은 같은 거래일을 두 번 세지 않는다.** `record()` 가 같은 `cycle_date`
중복을 이미 거부한다(신규 시험이 06:30·08:30 양쪽에서 `previous_trading_day()` 가
`2026-09-21` 로 같고, 두 번째 `record()` 가 거짓을 돌려주는 것을 확인). 다만 이 재예약도
GitHub 예약기를 공유하므로 **정시 실행 보장이 아니다.** 관측된 지연은 최대 5시간 46분이다.

**4. 새 시험이 9/21 실제 회귀를 잡는다 — 변이시험으로 확인했다.**
`hyeoks_analyst.py` 의 `KST` 정의를 다시 `RECEIPT_STATE` 아래로 되돌리자
`test_real_initializer_order_executes` 가 생산과 똑같은 `NameError: name 'KST' is not
defined` 로 실패했다. 원본은 즉시 복원했다. 소스 문자열 검사가 아니라 실제 초기화
문장을 실행하는 시험이다. 다만 외부 import 와 analyst 전체 실행은 검증하지 않는다.

**5. 전체 시험 650건 통과 — 이번에는 내 환경에서 재현했다.**
직전 보고에서 "전체 통과를 재현하지 못했다" 고 적은 이유가 확인됐다. 컨테이너에
`bs4`·`gspread`·`oauth2client` 가 없어 `EarningsCollectorCliTests` 5건이 떨어지고 있었다.
패치 적용 전 `7a0b8e3` 에서도 같은 5건이 떨어져 이 패치의 회귀가 아니다.
