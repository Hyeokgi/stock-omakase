# 계좌 NAV v2 — 입력과 실행 규약

> 9/9 후속 수정: 신규 입력과 테마 정책은 [계좌 입력 v3 사용법](계좌입력_v3_사용법.md)을 따른다.
> 아래는 v2 기록이다. v3에서는 테마 제한 없는 진단 모드를 지원하며 신규 workflow는 검증 근거를 요구한다.

구 `+6.58% / MDD 4.55%`는 정정 대기다. 순알파 곡선을 계좌 수익률로 부르지 않는다. 이 모듈은 원장 추천을 일정한 자금 규칙으로 가상 집행하는 연구용 재구성이지 실제 증권계좌 수익률 인증 도구가 아니다.

## 무엇이 바뀌었나

- 원장 `종목T+H − 지수T+H` 마크 합산을 제거했다. NAV는 현금과 종목 수량×동시점 가격이다.
- 원장의 `진입일`은 신호일이다. 다음 거래일 시가 매수, 신호일+H 거래일 종가 청산으로 원래 추적 규약과 맞췄다. H=1이면 다음 날 시가 매수·같은 날 종가 청산이다.
- T+H가 아직 안 왔거나 청산일 거래정지이면 열린 포지션으로 남긴다. 원장 수익률 마크가 없어도 가격이 있으면 포지션을 재구성한다.
- 모든 활성 종목을 같은 거래일 가격으로 평가한다. 가격이 없으면 전체 계산을 중단하며 마지막 값을 들고 가지 않는다.
- MDD는 최초 자본을 포함한 이전 NAV 최고점 대비 하락률이다. 일별 종가 기준이며 장중 MDD는 아니다.
- 초기 자본·주문 금액을 사전에 고정하고 실제 현금을 차감한다. 같은 날 종가 매도금으로 오전 매수를 충당하지 않는다.
- 동일 종목과 여러 날짜·채널의 보유를 합산해 비중을 제한한다. 신호 당시의 모든 소속 테마 ID에 노출을 반영한다.
- 전략, 랜덤2, 랜덤2_배지, 지수 buy-and-hold를 분리한다. 승률은 실제 모형상 종료된 거래만 계산한다.

## 필요한 고정 입력

`hyeoks_account.py --input PRIVATE.json --output-dir PRIVATE_OUTPUT`

입력은 **account-input-v2 JSON** 하나다. 원시 입력을 자동으로 외부에서 다시 조회하지 않는다. 같은 파일로 재실행하면 같은 계산 결과가 나와야 한다.

| 키 | 규약 |
|---|---|
| schema | `account-input-v2` |
| as_of | 평가를 마친 거래일, `YYYY-MM-DD` |
| captured_at | 원본 묶음 생성 시각, 시간대 포함 ISO |
| calendar_source | 실제 거래소 거래일 자료의 출처/버전 |
| price_source | 가격 공급자·조회/조정 기준의 출처/버전 |
| price_basis | `consistent_adjusted_ohlc`만 허용 |
| sessions | 분석 시작일(모든 신호 포함)부터 기준일까지 빠짐없는 실제 거래일 목록. 선택적으로 이후 거래일도 포함 가능 |
| rows | 백테스트_로그 전체 헤더와 행. 기존 원장 스키마·중복·수식 오류 검증을 재사용 |
| prices | `{종목코드: {날짜: {open,high,low,close,tradable}}}` |
| theme_map | `{신호일: {종목코드: [당시 테마ID, ...]}}`. 소속 없는 종목은 명시적인 개별 분류 ID 사용 |
| indices | 선택. `{지수명: {날짜: OHLC와tradable}}`; 별도 무비용 가상 보유 계좌 |
| config | 초기자본·주문금액·비중 상한·매수/매도 비용·슬리피지 |

OHLC는 모두 유한 양수이고 저가≤시가/종가≤고가여야 한다. `tradable`은 명시적 boolean이다. 거래정지일은 거래 불가능으로 표시하고 공급자가 확인한 평가가격을 별도로 제공해야 한다. 가격이 확인되지 않으면 중단한다. 값이 0인 원시 봉을 임의로 정상 가격으로 바꾸지 않는다.

입력 공급자는 거래일 누락과 시점 소속 정확성을 확인해야 한다. 코드가 출처 문자열을 요구하고 날짜를 검증하는 것이 출처의 진위를 증명하는 것은 아니다. 원장에 지금 없는 역사적 소속을 현재 소속으로 소급해 넣지 않는다.

일관된 수정 OHLC로 고정한 **가상 수량** 모형이다. 실제 분할 시 수량 변경·배당 현금흐름을 구현하지 않았으므로 raw와 adjusted를 섞지 않고 raw 모드는 거부한다. 실제 계좌 정산과 완전 일치를 원하면 권리처리 이벤트가 추가로 필요하다. 원장 진입가 열을 수정 OHLC에 섞지 않고 입력 OHLC 시가로 재구성하며 원본 열은 증거로 보존한다.

## 기본 자금 가정

초기자본 1,000,000, 주문당 50,000, 종목 상한 10%, 테마 상한 20%, 매수 비용 .175%, 매도 비용 .175%, 슬리피지 0이다. 수익성에 유리하도록 고른 값이 아니라 테스트 가능한 기본 설정이며 실운영 비중 변경이 아니다. 금액의 단위는 입력 가격과 같아야 한다.

실제 비용은 체결 금액에 양쪽 각각 적용하므로 단순히 수익률에서 .35%p를 빼는 것과 완전히 같지는 않다. 체결 슬리피지는 매수 가격을 높이고 매도 가격을 낮추는 별도 가정이다. 주식 수량은 정수, 차입은 없고 조건 미충족 주문은 축소가 아닌 거절한다. 주문 우선순위는 진입일·채널명·거래ID 순으로 결정되며 매번 고정된다.

상한은 신규 주문에서 검사한다. 보유 중 가격 상승으로 상한이 넘어가도 강제매도는 하지 않고 최대 노출을 결과에 기록한다. 종목별/테마별 최대 노출은 개장·종가 평가 기준이다. 테마가 중복되므로 테마 노출 비율의 합은 100%를 넘을 수 있다.

## 보존과 개인정보

로컬 실행은 입력·결과·보고서·계산 소스 2개·전체 SHA256 manifest를 임시 디렉터리에 쓴 뒤 읽어 확인하고 완료 디렉터리로 원자적으로 옮긴다. 실패한 임시 묶음에는 COMPLETE가 없으며 완료로 취급하지 않는다. 재실행은 UUID로 다른 묶음을 만든다.

수동 GitHub workflow는 비공개 Drive JSON 파일ID와 출력 폴더ID를 요구한다. 별도 GitHub Secret `ACCOUNT_DRIVE_OAUTH`에 사용자가 동의한 `authorized_user` OAuth JSON(client_id, client_secret, refresh_token 포함)이 필요하다. 해당 사용자가 입력을 읽고 출력 폴더에 쓸 수 있어야 한다. 기존 `GCP_CREDENTIALS`는 변경하거나 재사용하지 않는다. 권한이 사용자 단위인지 검사하고 `anyone/domain/group` 및 공유드라이브는 현재 지원하지 않는다. 권한을 자동 변경하지 않는다. 계좌 결과 ZIP 업로드 후 권한과 전체 내용 SHA256을 다시 확인해야 잡이 성공한다.

공개 아티팩트 업로드와 결과 Git 커밋/푸시는 제거했다. 로그에 원장·거래 결과를 출력하지 않는다. 전체 Drive 경로는 실제 인증된 저장소에서 검증되기 전까지 운영 완료로 간주하지 않는다. 서비스 계정은 My Drive 파일 소유/저장용량이 없으므로 이번 경로에서는 사전에 거부한다. [Google 공식 설명](https://developers.google.com/workspace/drive/api/guides/about-shareddrives). 사용자 OAuth 승인이 필요하며 채팅의 Google Drive 연결은 GitHub Actions 인증을 대신하지 않는다. 승인 범위는 Drive API이며 토큰은 채팅/저장소/보고서에 붙이지 않는다. 사용자 확인 없이 공유권한을 늘리거나 공개 저장소로 우회하지 않는다.

## 검증

`python hyeoks_account.py --self-test`

실제 일별 가격과 거래일 달력·소속 이력이 확보되기 전에는 386행의 새 수익률을 만들지 않는다. 테스트의 합성 데이터는 실제 성과가 아니다. 기존 10/5 일정이나 전략 문턱·시트·AI 선정 코드는 이 수정으로 변경되지 않는다.
