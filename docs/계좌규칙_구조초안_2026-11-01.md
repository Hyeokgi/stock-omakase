# 두 전략 같은 계좌 규칙 — 구조 초안 (2026-11-01, PC Claude)

**초안이다. 숫자를 정하지 않았고, 운영 승인도 아니다.** 운영대전제 §3(배분 · 상한 · 위험 감축 수치 미확정)을 그대로 따른다.
근거 — 전략 평가(Codex · Gemini, 2026-10-31, PC 허브 `work\전략평가_2026-10-31\`) 우선순위 5. 두 모델이 공통으로 '종목 고르기와 계좌 손실 제한이 연결되지 않았다' 고 짚었다. 금요일 1~2위의 과거 최대낙폭은 20~28% 인데, 사용자가 견딜 수 있는 낙폭은 고점 대비 약 10% 다.

## 1. 지금 계좌 계산기(`hyeoks_account.py`)가 하는 것

| 항목 | 지금 |
|---|---|
| 계좌 묶음 | 원장의 모든 전략 채널(단기 · 중기 · 장기 등)이 한 계좌(`strategy`)에 들어간다. 대조군(랜덤2)은 따로 |
| 한 번 살 때 금액 | 주문마다 같은 금액(`ticket_cash`). 전략별 자금 몫이 없다 |
| 한 종목 · 한 테마 한도 | 있다(`max_stock_weight` · `max_theme_weight`). 새로 살 때만 막고, 이미 산 뒤 값이 올라 넘으면 팔지 않는다 |
| 동시 보유 수 상한 | 없다(최대 보유 수를 기록만 한다) |
| 계좌 낙폭에 따른 매수 줄이기 · 멈추기 | 없다 |
| 하루 안 순서 | ① 종베 시가 청산 → ② 시가 매수 → ③ 15:05 매수 → ④ 종가 청산(사전등록 2026-09-16) |
| 종베(15:05 → 다음 날 시가) | 체결 경로는 있지만 **원장에서 종베 주문을 만들지 않는다**(미연결). 15:05 한도 판단의 종가 사용(결함 I)은 2026-11-01 고침 |
| 금요일 밤 NXT 20:00 매수(관측 ⑥) | 경로 없음 |

코드의 기본값은 시험용이다. 승인된 숫자가 아니다.

## 2. 정해야 할 것 — 구조만

| R1 | 자금 나누기 | 공용 풀(먼저 온 주문이 쓰기) / 칸막이(리포트 몫 · 종베 몫 · 현금) | 두 전략의 동시 보유 · 자금 중첩 실측(같은 계좌 재구성 결과) |

## 3. 정하지 않는 것
- 숫자(비율 · 칸 수 · 단계별 하락 폭). 위 근거 없이 정하면 과거 자료에 맞춘 값이 된다(운영대전제 §1 · §5).
- 자동주문 · 실전 자금 투입. 이 문서는 계산기와 모의 계좌의 구조 논의용이다.
- 관측 기간 결과를 보고 고르기. 관측 판정일 전에는 관측 수익을 이 규칙의 근거로 쓰지 않는다.

## 4. 다음 순서(제안)
1. 원장에서 종베 주문을 만드는 연결(R8 의 15:05 자격 포함) — 별도 PR, 사용자 결정.
2. 연결 뒤 두 전략을 같은 계좌에 넣은 재구성에서 R1 · R2 · R5 · R6 의 실측(건수 · 겹침 · 묶인 자금)을 숫자 없이 먼저 본다.
3. 숫자 제안은 블록 A 평가(2026-11-20, 리포트 쪽)와 관측 중간 판정(2027-04, 종베 쪽) 뒤에 근거와 함께 사용자에게 올린다. 승인되면 운영대전제 문서의 버전을 갱신한다.
