## 0. 결론 먼저

| 게이트 | 상태 | 근거 |
|---|---|---|
| `calendar_verification` | ✅ **열린다** | 출처가 다른 예정 휴장 목록과 관측이 13/13 일치 |

## 1. 거래일 — 이미 있던 자료로 풀렸다

### 원래 문제는 순환논리였다

어댑터의 설계 주석 그대로다: *"지수 일봉으로 만든 목록을 같은 목록으로 검증했다고
하지 않는다."* 거래일을 네이버 지수 일봉에서 뽑고, 그게 맞는지도 같은 일봉으로
확인하면 아무것도 확인한 게 아니다.

### 저장소에 이미 독립 자료가 있었다

```
data/market_snapshot/nontrading.txt      ← 예정 휴장 목록
data/market_snapshot/calendar_scope.json ← 범위·출처·확인일
  version:    krx-scheduled-2026h2-v1
  checked_at: 2026-09-13  (사람이 확인)
  범위:       2026-08-01 ~ 2026-12-31
  출처:       한국천문연구원 월력요항 / KRX 시장 개폐 규정 (URL 박혀 있음)
```

**이건 네이버와 출처가 다르다.** 여기서 거래일을 유도(주중 − 휴장)해서 실제 관측과
맞추면 순환이 깨진다. 새 자료를 구할 필요가 없었다 — 이미 있는 걸 안 쓰고 있었다.

### 대조 결과 (2026-08-28 ~ 09-15)

| 항목 | 값 |
|---|---:|
| 예정 거래일 | 13 |
| 관측 거래일 | 13 |
| 예정인데 관측 없음 | **0** |
| 달력 밖인데 관측 있음 | **0** |

전 구간 일치. 두 어긋남의 뜻이 다르다는 것도 코드에 박아 뒀다:

- `expected_only` — 예정 거래일인데 관측이 없다 → 임시휴장이거나 **우리 수집이 실패**.
  파일이 없다는 이유로 휴장일을 새로 만들지 않는다.
- `observed_only` — 관측은 있는데 예정 휴장일이다 → **등록 달력이 틀렸다.** 더 심각하다.

### 무엇을 세우고 무엇을 못 세우는지 블록 안에 박았다

근거 블록에 `establishes` / `does_not_establish` 를 같이 넣는다.
등록 달력 스스로가 `scheduled_closures_only_not_actual_session_certification` 이라고
밝히고 있으므로, **실제 장 운영 인증이 아니다.** 임시휴장·시스템 장애로 예정과
실제가 다를 수 있다. 이 문장을 빼면 과장이 된다.

## 2. 가격 — 지금 자료로는 안 풀린다. 그게 답이다

우리가 가진 두 가격 계열:

| | 출처 | 성격 |
|---|---|---|
| 일봉 | `fchart.stock.naver.com/sise.nhn` | **수정주가** |
| 스냅샷 | `stock.naver.com/api/domestic/...` | 그 시각 체결가 |

**같은 벤더(네이버)의 다른 엔드포인트다.** 맞춰보면 불일치는 잡히지만,
일치해도 독립 확인이 아니다 — 네이버의 조정 기준이 통째로 틀렸다면 둘 다 같이 틀린다.

그래서 `price_evidence()` 는 **언제나 `unverified`** 를 돌려준다.
도구가 스스로 통과시키면 게이트가 무의미해진다.

### 그래도 대조에는 값이 있다

일봉은 **소급 조정**되고 스냅샷은 **그날 값**이다. 기업행사가 있었으면 둘이 어긋난다.
`price_agreement()` 가 그걸 잰다 — 같은 날 시가, 그리고 **전일 종가**
(일봉 `close(d-1)` vs 스냅샷 `prev_close_derived(d)`). 후자가 기업행사 탐지기다.
"가격 조정 기준과 기업행사 대조"가 바로 이것이고, 대조 결과는 근거 블록의
`crosscheck` 에 담아 사람이 보게 한다. 다만 **판정은 하지 않는다.**

### 필요한 것

KRX 공식 시세 또는 다른 벤더의 수정주가·기업행사 이력. 사람이 넣기 전까지 안 열린다.

## 3. 게이트가 실제로 어떻게 반응하는지 (측정)

말이 아니라 실제 `validate_bundle` 을 통과시켜 봤다
(`tests/test_evidence.py::GateIntegrationTests`).

| 넣은 것 | 결과 |
|---|---|
| 근거 없음 | 🚧 `calendar_verification` 에서 막힘 |
| 도구가 낸 달력 근거 | 🚧 **달력은 통과**, `price_verification` 에서 막힘 |
| 달력이 어긋난 경우의 블록 | 🚧 달력에서 막힘 (도구가 `verified` 를 안 만든다) |
| 도구가 낸 가격 근거 | 🚧 가격에서 막힘 (스스로 인증하지 않는다) |
| 달력 + 사람이 넣은 가격 근거 | ✅ 통과 |

두 번째 줄이 이번 작업의 성과다 — **막히는 지점이 달력에서 가격으로 옮겨갔다.**
마지막 줄은 남은 일이 정확히 무엇인지 보여준다.

## 4. 만든 것

- `hyeoks_evidence.py` — 순수 함수 + CLI. 네트워크·시트를 쓰지 않는다.
- `tests/test_evidence.py` — 23건. 일치 사례만이 아니라 **어긋남이 실제로 잡히는지**
  건다(관측 누락 / 휴장일 관측 / 범위 밖 / 뒤집힌 범위 / 기업행사 / 반올림 허용).

  어긋나면 잡을 실패시킨다(fail-closed).

## 5. 이 문서가 승인하지 않는 것

- 실제 장 운영 인증. 등록 달력은 **예정** 휴장 목록이다.
- 가격 조정 기준의 확인. 같은 벤더 대조로는 성립하지 않는다.
- 2027년. 등록 달력 범위는 2026-12-31 까지이고, 범위 밖은 추정하지 않고 **막는다**.
