교체 여부**를 제시하라고 요구했다. 정당한 요구다. 아래는 그 답이고, **값은 어디에도
적지 않는다.**

저장소는 이 사실을 이미 알고 있었다. `hyeoks_morning.py:34-35` 에 주석이 남아 있다 —
"이 키는 공개 저장소 소스에 하드코딩돼 있었다. git 이력에 남아 있으므로 **키 교체가

빠졌고 이력에만 남아 있다. `git log --all -S'FRED_API_KEY'` 로 도입 커밋을 따라가야 보인다.

## 🔻 철회 — KIS 앱키/시크릿

**"FRED_API_KEY 와 KIS_TOKEN 이 공개 git 이력에 평문으로 있다" 고 쓴 것 중
KIS 쪽은 근거가 없다. 철회한다.**

- `omakase.py:222` 의 `KIS_TOKEN` 은 리터럴이 아니라 `get_kis_access_token()` 호출이다.
- `hyeoks_analyst.py:425` 의 `KIS_TOKEN` 은 빈 문자열 초기화다.
- `KIS_APP_KEY`·`KIS_APP_SECRET` 은 `os.environ.get(...)` 이다.
- 이력 전수 검색(`KIS_APP_KEY`·`KIS_APP_SECRET`·`KIS_TOKEN`)에서 **평문 대입은 나오지 않았다.**

같은 검색에서 `DART_API_KEY`·`TELEGRAM_BOT_TOKEN`·`GEMINI_API_KEY` 도 평문 대입이 없다.
**평문으로 확인된 것은 `FRED_API_KEY` 하나다.**

## 검색 방법 (재현용)

값을 출력하지 않는다. 변수명 옆에 12자 이상 리터럴이 대입된 추가 줄만 세고,
`${{ secrets.* }}`·`os.*` 은 제외한 뒤 커밋·파일·변수·길이만 남긴다.

```
for name in FRED_API_KEY KIS_APP_KEY KIS_APP_SECRET KIS_TOKEN \
            DART_API_KEY TELEGRAM_BOT_TOKEN GEMINI_API_KEY; do
  git log --all -p -S"$name" --format='@@COMMIT %h %ad %s' --date=short
done | <마스킹 스캐너>
```

한계: 이 검색은 **위 7개 이름**과 `api_key`/`APP_KEY`/`APP_SECRET` 만 본다.
다른 이름으로 들어간 비밀이나 `secret.json` 류 파일이 이력에 섞인 경우는 잡지 못한다.
전수 보증이 아니다.

## 권고

코덱스 판단에 동의한다. **이것은 3거래일 동결이 끝나기를 기다릴 사안이 아니다.**
노출된 키가 아직 유효하다면 폐기·재발급이 먼저다. 코드에서 지운 것만으로는
공개 이력의 노출이 해소되지 않는다.

순서:
1. FRED 계정에서 해당 키를 **폐기**하고 새 키를 발급한다.
2. 새 키를 Actions secret `FRED_API_KEY` 에 넣는다. 코드는 이미 그걸 읽는다.
3. 이 문서의 "키 자체 교체" 칸을 완료로 갱신한다.

저장소 코드 변경은 필요 없다. 이력 재작성(force-push)도 권하지 않는다 —
이미 공개된 값은 회수되지 않으므로 **폐기가 유일한 해결**이다.
