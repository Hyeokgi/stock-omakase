## 1. P0-1 — 재표본 길이를 정확히 `n` 으로

### 무엇이 틀렸었나

`block_bootstrap_p()` 는 `nb = ceil(n/block)` 개의 블록을 뽑은 뒤
`tot / (nb * block)` 로 평균냈다. `n` 이 `block` 의 배수가 아니면 재표본이
**원표본보다 길어진다.** 사전등록(§3-5-6)이 정한 것은 "같은 길이의 표본"이다.

### 왜 방향이 나쁜가

길게 평균낼수록 귀무분포의 산포가 **좁아진다.** 좁은 귀무분포는 관측 평균을
더 극단적으로 보이게 만들고, 그래서 **p 가 과소평가**된다. 즉 **승인이 쉬워지는
방향**의 오류다. 반대 방향이었다면 급하지 않았겠지만 이건 그렇지 않다.

크기는 현재 파라미터에서 작다 — 차트TOP2(H=5, 날짜 ~44)는 44→45 로 1.02배,
중기(H=10, 날짜 ~20)는 절단이 아예 없다. **작다는 것은 고치지 않을 이유가 아니라,
지금 고쳐도 기존 관측이 안 흔들린다는 뜻이다.**

### 수정

```python
nb   = -(-n // block)                      # 올림: 필요한 블록 수
tail = n - (nb - 1) * block                # 마지막 블록에서 실제로 쓸 길이 (1..block)
for b in range(nb):
    st   = rng.randrange(n)
    take = block if b < nb - 1 else tail   # 마지막 블록만 자른다
    for k in range(take):
        tot += centered[(st + k) % n]
m = tot / n                                # ← n 개의 평균. nb*block 이 아니다
```

**난수 소비를 바꾸지 않았다.** `rng.randrange` 호출 수는 그대로 `nb` 회다.
그래서 `n % block == 0` 인 경우는 **비트 단위로 같은 값**이 나온다.
기존 관측을 재계산해도 달라지지 않는다는 뜻이고, 아래 두 번째 테스트가 그것을 건다.

### 검증 3건 (신규)

1. **정확히 n** — `n=3, block=2` 에서 사양을 테스트 쪽에 독립적으로 다시 써서 대조.
   `(c[s1] + c[s1+1] + c[s2]) / 3`. 옛 코드는 4개를 4로 나눴으므로 반드시 갈린다.
   결과 `got = want = 0.001996007984031936`.
2. **배수면 절단 없음** — `n=4, block=2` 가 같은 사양으로 일치.
3. **방향 확인** — 같은 블록 추출에서 40개 평균과 31개 평균의 산포를 직접 비교.
   `sd(40개)=0.1337 < sd(31개)=0.1486`. 옛 방식이 실제로 더 좁다.

## 2. P0-3 — α 를 호출자가 넣는다

### 무엇이 틀렸었나

```python
if p <= 0.05 / (m - i + 1)       # α 가 함수 안에 상수로 박혀 있었다
```

트랙마다 α 가 다르다. **트랙 C 확증**은 §3-5-6 의 결정일 4회 보정으로 0.05/4 = **0.0125**,
**트랙 E 탐색**은 사전등록이 **보정 없는 0.05** 로 못박았다. 함수가 0.05 를 숨겨 갖고
있으면 트랙 C 를 **4배 느슨하게** 돌려도 겉으로 드러나지 않는다.

### 수정

`def holm(pairs, m=None, alpha=0.05)` — 인자로 뺐다.
**기본값 0.05 는 기존 호출 동작 보존용이지 트랙 C 의 정답이 아니다.**
실제 트랙별 α 배선은 순서 3(승인 게이트)에서 한다. 그것이 U1~U5 에 걸려 있다.

### 호출부는 일부러 안 바꿨다

`hyeoks_verdict.py:1090` 은 여전히 기본값 0.05 로 돈다. 대신 그 자리에 경고 주석을 달았다:

```python
# ⚠️ α 는 아직 트랙별로 나뉘지 않았다. 여기 들어가는 값은 `holm` 의 기본값 0.05 이고,
#    §3-5-6 이 트랙 C 에 지정한 0.0125 가 아니다. 이 이름이 `nominal_` 인 이유가 그것이다.
```

바로 다음 줄에서 `passed = set()` 로 비우므로 **운영상 승인으로 새지 않는다.**
여기서 0.0125 를 지금 넣으면 "트랙 C 의 α 는 0.0125" 라는 U 항목 하나를 코드로
먼저 확정하는 것이 되므로 하지 않았다.

### 검증 4건 (신규)

- α 기본값 0.05 — 기존 호출 동작 그대로 (`p=0.03, m=1` → 통과)
- α=0.0125 로 낮추면 같은 p 가 탈락
- 트랙 C 설정(α=0.0125·m=2) 1위 문턱은 **0.00625** — 0.006 통과
- 같은 설정에서 0.007 은 1위도 탈락

## 3. P1-2 — `scanner_census.py` 머리말 과잉진단 정정

### 무엇이 틀렸었나

초판 머리말:

> 2026-09-14 스캐너 실측: **스캔 710종목 · 엔벨로프(-20%) 통과 0종목.**
> 중기 채널이 굶는 원인은 … **관문①(엔벨로프 밴드)에서 후보가 0** 이라는 것이었다.

관문① 은 **이격 · 거래대금 · 상한가 아님 · 등락률 ≤10%** 의 복합 조건이다.
복합 통과 0 은 **어느 항이 막았는지 못 가린다.** 그런데 문장은 이격률을 범인으로
지목했다. 이것은 지적받은 그 유형(§ 9/14 GPT 지적)과 같은 오류이고,
같은 날 스캐너 진단 문구는 고치면서 **이 파일 머리말은 안 고쳤다.**

### 그리고 다음 날 실제로 뒤집혔다

단계별로 나눠 센 9/15 실측: **이격 3 → 거래대금(100억) 0.**
이격은 통과했고 **거래대금이 죽였다.** 초판 진단은 틀렸다.

### 수정

머리말을 "관문① 복합조건 통과 0" 으로 바꾸고, 그 숫자로 말할 수 있는 범위를
**"막힌 지점이 태그 생성 이후가 아니라 관문① 이전"** 까지로 한정했다.
그 아래에 ⚠️ 정정 블록을 붙여 초판 문장이 무엇을 단정했고 무엇이 그것을 뒤집었는지
남겼다. **초판 문장을 지우지 않고 무엇이 틀렸는지 적는 방식**이다.

### 여기에 걸린 더 큰 문제도 머리말에 적었다

§3-2-1 이 완화하라고 지정한 대상은 **이격률**(-20%→-12%)인데 9/15 증거는
**거래대금**을 가리킨다. 지정대로 이격률만 풀면 아무것도 안 바뀌고, 그러면
§3-2-1 의 되돌림 조항이 **안 건드린 문턱을 두고 채널을 폐기**할 수 있다.
상세는 `docs/정책변경_체크리스트.md` §4-2. **여기서 문턱을 바꾸지 않았다.**
