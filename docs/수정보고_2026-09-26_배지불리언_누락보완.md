# 배지 참·거짓 값 누락 보완 — 2026-09-26

사용자의 오류 수정 요청으로 진행한 연구 입력 무결성 수정이다. 신규 전략 도입이나
선정 문턱 변경이 아니다. 기준 main: `8111b8e5190757247daba2a86a6cf40aea4ee28c`.

## 원인과 관측 범위

`badge_observations.capture()`가 Python `bool`만 허용해 `numpy.bool_`를 `null`로
저장했다. pandas 평균으로 만든 비교식은 NumPy 스칼라를 반환할 수 있고, Python의
`and`는 첫 거짓 피연산자 자체를 반환한다. 따라서 실제 False가 결측으로 바뀐다.
NumPy True도 입력 타입에 따라 같은 손실을 겪을 수 있음을 합성 실행으로 확인했다.

검사한 사용 가능 원본에서 외인 적극매수 값이 없는 행은 9/22 696/727,
9/23 710/732였다. 모든 결측의 원인을 이 하나로 단정하지 않는다. 앞선 보고의
“독립 조건 전 행 보존”은 구조 존재 확인이며 값의 완전성 인증이 아니었다.

## 변경 범위

- Python bool과 실제 NumPy bool 스칼라만 JSON true/false로 정규화한다.
- 문자열, 숫자 0/1, 배열, NaN, 임의 객체를 bool로 강제 변환하지 않는다.
- 입력 부재·명시적 null·잘못된 타입·검증되지 않은 이력을 사유로 구분한다.
- NumPy로 계산된 Minervini 진단의 참·거짓도 문자열이 아닌 JSON boolean으로 저장한다.
- 관측/완료 파일에 배지별 true/false/missing/invalid_type 집계를 기록한다.
  각 배지의 true+false+missing은 대상 행수와 맞으며 실패 행도 분모에 남는다.
- 행 누락 0건과 배지 값 누락 0건은 다르다. 둘을 별도 로그로 표시한다.
  잘못된 타입은 경고하되 연구 보조 경로가 주 스캐너를 실패시키지는 않는다.
- 외곽 번들 버전은 v1 호환 유지, 새 조건 인코딩은 `badge-conditions-v2`로 명시한다.
- CI에 실제 NumPy를 설치해 이 결함이 대역 bool 시험으로 헛통과하지 않게 한다.

수정 파일: `badge_observations.py`, `.github/workflows/review_regressions.yml`,
`tests/test_badge_boolean_20260926.py`. 스캐너 선정식·점수·밴드·15:05 시각·청산 기준·
Gate 판정 기준은 변경하지 않았다. 과거 번들·시트·영수증·runs.csv도 수정하지 않았다.

## 검증

- 신규 14개 시험. 실제 NumPy true/false, 짧은 회로식, 잘못된 타입, 이력 결측,
  capture→gzip→모의 archive, 배지별 분모, NumPy 없는 환경의 import까지 확인.
- 기존 배지 시험을 포함한 57개 통과(Windows Python 3.12, UTF-8, Git Bash 경로 설정).
- 메모리에서 허용 타입을 Python bool만으로 되돌리면 신규 시험 2개에서 실패 5개
  (subtest 포함)가 발생한다. 시험 후 원래 값을 복구하며 생산 파일을 변조하지 않았다.
- 전체 695개 시험 재실행: 693개 통과, 기존 `/proc` 경로 시험 2개 실패, 오류 0개.
  초기 Bash 부재와 UTF-8 환경 문제는 테스트 실행 환경에서 보완했다.
  남은 두 시험은 Linux `/proc`를 쓰기 불가 경로로 가정하지만 Windows에서는 같은
  의미가 아니다. 해당 모듈·시험은 기준 main과 무수정이다. 전체 통과라고 보고하지 않는다.
- Drive 업로드는 Mock만 사용했다. 실제 시트 쓰기·유료 API·생산 워크플로 수동 실행 없음.

## 동결 영향과 적용 후 확인

Git에 저장되는 LF 바이트로 계산한 지문:
`bfb421d66cb9` → `1af4a5c8d3a5`.
Windows checkout CRLF 바이트 지문과 혼동하지 않는다. 변경된 지문 대상은 배지 모듈과
CI 워크플로 2개이며, 지문 대상 목록 자체는 바꾸지 않았다.

main에 반영되면 기존 9/23 PASS는 보존하되 새 지문 카운트에는 합치지 않는다.
9/28 전에 반영되고 이후 변경·결측 없이 통과하면 9/28·29·30 세 사이클,
10/1 아침 최종 판정이 가능한 조건부 일정이다. 정시 실행과 PASS를 보장하지 않는다.

첫 거래일 생산에서 확인할 것:
1. `condition_schema=badge-conditions-v2`와 배지별 집계가 원격 번들에 존재하는가.
2. 외인 적극매수 등 각 조건의 결측률이 어떻게 변하는가. 0%를 강제하지 않는다.
3. true/false/missing 합이 대상 수와 일치하고 임의 false 채움이 없는가.
4. 15:05 이전 사용 가능 회차와 원격 다운로드 해시가 일치하는가.

과거 null은 자동 복원하지 않는다. 당시 원시 입력이 충분한 경우에만 별도 파생 자료로
복원할 수 있다. 복원 불가능한 값은 unknown으로 유지하고, 인코딩 버전 전후 품질을
분리한다. `NOT_JOINED`, `NOT_APPLIED`, 원천 시세 시각 미인증은 이번 수정으로 해결되지 않는다.

## Claude 전달 요약

원격 반영은 완료되지 않았다. 로컬 Git push는 쓰기 인증 부재로 실패했고 GitHub
연결 도구의 create_tree도 `403 Resource not accessible by integration`으로 거부됐다.
main 보호가 원인이라고 단정하지 않는다. 따라서 원격 지문은 여전히
`bfb421d66cb9`, 기존 연속 PASS는 1/3이고 이 수정의 Linux CI는 아직 실행되지 않았다.
동봉한 실제 git format-patch 파일을 최신 main에서 `git apply --check` 후 적용한다.
전체 Linux CI와 첫 생산 번들을 확인한 뒤 적용 완료를 선언한다.

NumPy boolean이 null로 유실되는 저장 결함을 수정했다. 선정 규칙은 그대로다.
배지별 결측 사유와 품질 집계가 새 번들에 추가된다. 기존 null을 False로 해석하지 말 것.
인코딩 v2와 기존 자료를 구분하고, Gate는 새 지문으로 재시작한다.
시험 성공과 실제 장중 원격 번들 확인은 다른 증거이며 첫 생산 확인은 아직 남아 있다.
