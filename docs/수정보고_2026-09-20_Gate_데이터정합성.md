## 변경

1. Feature Store v3: 정적 DB 등록 여부가 아닌 실제 is_junk bool을 저장한다.
   True=Y, False=N, 누락/비정상 형식/구형 집합 입력=UNKNOWN. 생산자가 dict 값을 보존한다.
2. Gate v3: PASS 행 사이의 예정 거래일 연속성을 확인한다. 평일 결측은 연속을 끊고,
   정상 휴장·주말만 건너뛴다. 중복·역순·잘못된 날짜는 0으로 판정한다.
   빈 지문과 거래일 SKIP을 성공 근거로 쓰지 않는다. 과거 runs.csv는 변경하지 않았다.
3. 지문: naver_sources, after_market_quotes, telegram_target, performance_memory,
   data_quality, run_freeze 및 nontrading.txt/calendar_scope.json을 포함한다.
   일별 관측 데이터는 제외하지만 달력 설정은 실행 계약이므로 포함한다.
4. cycle_date_matches는 명시적 True여야 한다. None/누락은 store_written 실패다.
5. rank_pool의 rows는 성공 채널 수 대신 date/channel/run_id가 일치하는 저장 행을 재조회한다.
6. 실적/AUX: 시작 시각을 시트 접근 이전에 잡는다. 거래일 00~06시 시작은 이전 날 예약의
   지연인지 현재 날짜 실행인지 불명확하므로 명시적 PRODUCTION_CYCLE_DATE 없이는 거부한다.
   workflow_dispatch에 cycle_date 입력 추가. 주말 귀속은 기존 달력 정책 유지.
   이는 예정 시각을 복원한 것이 아니다. 06시 이후까지 밀린 실행의 의도한 날짜를
   자동 인증하지 않는다. 완전한 해결에는 트리거가 의도한 사이클 ID를 전달해야 한다.
7. 컨센서스 영수증에 targets/실제 attempted/empty/unprocessed를 분리한다.
   성공+예외 실패만으로 설명되지 않던 항목을 다음 실행부터 구분한다.
   요청 간 기존 0.2초 대기는 유지한다. 원천 오류 자체를 해결했다는 뜻이 아니다.
8. finalizer에 Actions 읽기 권한 명시.

## 과거 데이터 처리 — 원본 불변

feature-store-v1/v2의 is_junk는 연구 조건/제외 조건으로 사용하지 않는다.
당시 정적 DB 원본과 연결해 검증 가능한 경우에만 별도 교정 산출물을 만들 수 있다.
지금의 정적 DB를 과거에 소급 조인하지 않는다. 이번에는 과거 파일을 고치거나
복구했다고 주장하지 않는다. 새 v3도 UNKNOWN은 정상(N)이 아니다.
그 외 열 전체가 무효라는 뜻은 아니며, 분석 소비자는 열별 유효성을 구분해야 한다.
