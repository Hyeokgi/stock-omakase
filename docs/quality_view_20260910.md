# 데이터 품질표 연결 및 해석 교정 — 2026-09-10

## 변경 범위

`main`의 8f5621c를 기준으로 독립 변경했다. 이전 별도 브랜치의 계좌/15:05/우선검증 변경은 이번 변경에 포함하지 않는다.

- `hyeoks_data_quality.py`: 기존 `백테스트_로그`만 참조하는 `데이터_품질표` 수식 생성 및 읽기 전용 연결 검사.
- Google Sheets에 품질표 설치. 원장에 쓰지 않으며 시트 공유 권한도 바꾸지 않는다.
- 원장 추가/변경 시 네이티브 수식으로 자동 재계산. 추가 Gemini 호출이나 새로운 수집 스케줄은 없다.
- `main.yml`: 기존 스캐너 실행 뒤 품질표 열 구조/수식/계산 오류 검사. 오류를 성공으로 삼키지 않는다. 데이터 품질 합격 판정이 아니라 연결 무결성 점검이다.
- `omakase.py`: 대시보드의 `실수익`을 `비용전수익`, 승률을 `비용전승률`로 교정. 켈리 숫자는 보존하되 `추천 비중`이 아닌 `이항 근사 연구 지표`로 명시. 차기 자동 갱신에도 같은 문구 유지.

## 품질표 구조

1. A1:I9: 채널별 원장/제외/진입가/기준 호라이즌 수익·지수 짝 기록 수와 비율. 비율 분모에 미성숙 행이 포함되므로 품질 합격률이 아니다.
2. A11:O17: 현재 날짜, 스키마 점검, 자료 범위와 미검증 항목.
3. A19:D23: 최근 120 **달력일**의 동일 추천일 비교. 일별 채널 내 평균을 먼저 구한 뒤 공통 날짜에 동등 가중. 단기 T+5·중기 T+10 각각 차트TOP2/랜덤2와 비교.
4. A25:C26: 최근 추천일, 중복 trade_id에 해당하는 행 수. 중복은 삭제하지 않고 알린다.
5. A29:O149: 비교 산출 근거. Google Sheets 네이티브 표, 날짜/퍼센트 형식. 값 없는 날은 수익률 0%로 대체하지 않는다.

수익률은 원장 네이티브 숫자(0.01 = 1%)로 계산한다. 요약 차이만 100을 곱해 %p로 표시한다. 짝 표본은 제외 표식이 없고, 양수 숫자 진입가와 숫자 종목/지수 수익률을 모두 요구한다. 0% 수익은 유효한 표본이다.

## 아직 증명하지 않는 것

- 추천이 없는 날의 정상 무신호/휴장/수집 실패 구분. 거래일 달력과 실행 로그를 대조하지 않았으므로 누락이라고 단정하지 않는다.
- 동일 후보군, 정책 버전, 모델 입력/출력 동결, 추천 시점 이전 정보 사용, 거래정지 및 체결 가능성.
- 기록된 T+H가 정확한 실제 거래일에 수집됐는지, 가격 원천이 독립 검증됐는지.
- 수수료·세금·슬리피지·갭 손절·동시보유 제약을 반영한 계좌 수익.
- 이 원장의 T+1 시가 진입을 **15:05 종베 체결**로 대신하지 않는다. 종베 항목은 별도 원장 연결 전 `미연결`이다.

## 시스템 변경 방향

- Gemini 모델을 교체하거나 승률이 높아 보이는 채널로 즉시 비중을 옮기지 않는다. 같은 날짜 비교도 후보군/정책까지 통제한 인과 실험은 아니다.
- 다음 데이터 계약: run_id, policy_id, 모델/프롬프트 버전, as_of/decision_at, 후보 코드 목록과 순서, 선정/비선정, 명시적 no_signal/error, freeze 저장 결과를 키로 결합.
- AI의 추가 가치는 **동일한 후보군·시점·청산 규칙**에서 사전 고정한 차트 규칙 및 랜덤 대조군과 별도로 검증한다. 과거 성과를 보며 프롬프트와 평가 기준을 동시에 바꾸지 않는다.
- 단기·중기·15:05 종베는 별도 실험으로 유지한다. 비용 후 기대수익과 낙폭을 함께 보고, 이항 켈리 숫자를 계좌 비중으로 사용하지 않는다.
- 30건은 지표 표시 하한이지 통계적 유의성이나 실전 승인의 기준이 아니다.

## 확인 방법

```
python -m unittest discover -s tests
python -m py_compile omakase.py hyeoks_data_quality.py
python hyeoks_data_quality.py --check --spreadsheet-id <기존 스프레드시트 ID>
```

마지막 명령은 기존 `secret.json` 서비스 계정을 읽기 전용 범위로 사용한다. 권한/연결 오류는 실패로 반환하며 원장 내용과 자격증명은 로그에 출력하지 않는다. GitHub에서는 기존 스캐너의 다음 실행 시 같은 점검이 수행된다.

품질표 수식은 정렬/덮어쓰기 없이 필터로 조회한다. 수식이 바뀌면 점검이 보수적으로 실패한다. 신규 설치용 `--requests <새 sheetId>`는 JSON만 출력하며 직접 업로드하거나 기존 탭을 삭제하지 않는다.

## 롤백

이 변경 커밋을 revert하면 실행 경로/표기 수정이 복구된다. 이미 설치된 품질표는 독립 수식이므로 남는다. 삭제하지 않아도 스캐너나 원장을 변경하지 않는다. 기존 켈리/대시보드 숫자는 보존했고 표기 및 주의문만 수정했다.
