# 한투 접근 토큰 공유 — 발급 알림 줄이기 (2026-10-30, PC Claude)

## 왜
사용자 — "한국투자증권 API 알림이 이전보다 자주 오는데 필요해서 오는지 중복인지". 한투는 토큰 발급마다 알림을 보낸다. 10/8 이후 연구 수집기가 실행마다 따로 발급해 평일 하루 1회 → 5회(스캐너 1 · 한투 뉴스 3 · 15:05 잠정 수급 1), 금요일 +2(금요일 하락 알림 GitHub · PC). 같은 실행의 이중 발급 같은 버그는 없었고, 연구 수집기를 운영 시트 토큰과 분리한 설계 때문이었다. 사용자 결정 — "알림을 공유".

## 무엇
| 파일 | 변경 |
|---|---|
| `kis_token_share.py` (새) | 시트 `⚙️설정` 의 `KIS_TOKEN` · `KIS_TOKEN_DATE`(스캐너 omakase 가 하루 1회 발급 · 기록)를 **읽기만** 한다. 날짜가 오늘이고 가벼운 시세 조회(FHKST01010100) 한 번이 통하면 함께 쓰고, 아니면 기존 방식대로 따로 발급(시트에 쓰지 않음). 키 파일이 없으면(PC · 시험) 바로 따로 발급. 토큰 값 출력 없음 |
| `hyeoks_kis_news.py` · `hyeoks_flow_estimate.py`(기록 실행만) · `hyeoks_friday_dip_alert.py` | 토큰을 `token_for_run(...)` 으로 받는다. 잠정 수급의 시험 호출 · 대조, 분봉 백필은 그대로 따로 발급 |
| `kis_news.yml` · `flow_estimate.yml` · `friday_dip_alert.yml` | `gspread oauth2client` 설치, 시트 읽기 키 만들기(없으면 건너뜀), 항상 지우기(공개 건수 커밋 전) |
| `tests/test_kis_token_share_20261030.py` (새) | 오늘 토큰 공유 · 어제 것 · 없음 · 안 통함 → 발급, 키 없음, 세 수집기 연결 · 시트 쓰기 없음 · 워크플로 정리 |

## 예상 효과
평일 발급 5 → 1(스캐너)~2회. 스캐너 첫 실행(07시대)보다 먼저 도는 수집기는 없다. 금요일 PC 판 알림은 GitHub 판 대조 뒤 지울 예정이라 그만큼 더 준다.

## 설계 변경
- 잠정 수급(`flow-estimate-v1`) · 한투 뉴스 머리 주석의 '운영 토큰은 읽지도 쓰지도 않는다' → '쓰지 않고 읽기만 한다'. 수집 내용 · 판정 · 사전 등록과 무관(토큰은 인증 수단일 뿐).
- 지문 대상 아님(세 수집기 · 세 워크플로 · 새 모듈 모두 `FINGERPRINT_FILES` 밖).

## 시험
전체 1,263건 중 실패 3건(리눅스 `/proc` 경로 시험, main 과 같다).
