## 범위

- rev3(`4d5e449`): 실전 1순위에서 내리고 무자금 보조 검증으로 유지, 120거래일 상한 이후 평가 차단, 가격 결측 품질 보류, 38종목-일 정정.
- 이번 변경: 사용자가 전달한 **코덱스의 탐색 목록**(스냅샷 비교 9개 · 배지 비교 8개 · 확인한 강건성 · 상위 2종목 미시험 · +0.042% 의 구성)을 사전등록 §11-1 에 옮겼다.
  §4-4 시도 1 을 같은 내용으로 정확히 고치고, 17개가 독립 검정이 아니라는 단서를 넣었다.
- 하지 않은 것: `LOCKED` 전환, 품질 보류 임계 변경, 정의·문턱 변경, 운영 코드 변경.

## 실제 검증 결과

- rev3 구현: 전체 807건 통과, 이 연구 시험 37건, 변이 5종 검출, `stability_fingerprint` 불변 `0a9958926a96` (`4d5e449` 시점).
- §11-1 기록은 **문서 편집**이다. 코드를 바꾸지 않았다. 코덱스 원문 문서와의 대조는 하지 않았다.

## 미검증 사항

- §11-1 이 코덱스 원문과 정확히 일치하는지 (사용자 전달 본문만 근거).
- 코덱스의 계산 결과(+0.042%, 강건성 확인 결과) — 독립 재실행하지 않았다. Claude 는 해당 계산을 재현하지 않았다.
- 품질 보류 임계(5%·10%)의 적정성. 코덱스는 이를 '제안된 운영 기준이며 통계적 안전 보증이 아님' 이라고 밝혔다 (사용자 전달).

## 다음 행동

1. 사용자가 품질 보류 임계를 승인하거나 다른 값을 지정한다.
2. 사용자가 `LOCKED` 를 승인하면 Claude 가 상태 전환 커밋을 만들고 해시를 §11 에 적는다. 시한은 문서상 **2026-10-05 이전**이다.
3. 시한 안에 못 하면 `CONFIRM_FROM` 을 미룬다 (코드·문서 동시 갱신, 잠금 전에만).

## 사용자 승인 필요 사항

- 품질 보류 임계 5%·10% 승인. **이것은 잠금 승인이 아니다.**
- `LOCKED` 승인.

- 코덱스: 사용자가 전달한 메시지에 따르면 '연구용 조건부 승인, 보완 후 잠금' 권고를 했다. 코덱스의 원문은 이 저장소에 없고 Claude 는 읽지 못했다.
  **코덱스가 rev3 를 검토·승인했다고 기록하지 않는다.**
- 사용자: 우선순위 하향(§10)을 수용했다. 잠금과 임계는 승인하지 않았다.
