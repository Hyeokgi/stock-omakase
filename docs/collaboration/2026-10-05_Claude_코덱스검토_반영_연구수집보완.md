## 0. 요약

Codex 지적 R1~R6 은 코드에서 모두 확인됐고 고쳤다. 첫 예약 실행(10/6 19:40) 전이다.

## 1. 연구 일봉 수집 (`hyeoks_research_daily.py`, `research_daily.yml`)

| Codex | 고친 방식 |
|---|---|
| **R1** 부분 성공이 전체 백필 완료로 취급 | `data/daily_bars/coverage.json` 에 종목별 `backfilled`·`last`·`first`·`last_error`·`shortHistory`. 요청량 = 초기 수집 전이면 300, 아니면 **마지막 저장 봉 → 대상일 간격 + 5** (최대 300). 실패·미처리 종목은 대상에서 빠져도 다음 실행 대상에 다시 넣는다. 상장 기간이 짧아 300봉 미만인 것은 `shortHistory` 로 실패와 구분 |
| **R2** 대상일·실행일 혼동 | 대상일 **뒤** 봉은 저장 안 함(과거 복구가 이후 자료를 섞지 않음). 미확정 제외는 **실제 오늘** 봉에만. 대상일 = 실행 시각 기준 **가장 최근에 16:00 이 지난 거래일** — 새벽·오전 지연 모두 같은 규칙(8시 기준 추정 제거). `fetchedAt` = 종목별 **수신 완료** 시각 |
| **R3** 수집 결과가 보고에 안 감 | `last_run.json`(실행 ID·대상일·상태) + `runs.csv`(이력). 보고는 **같은 `GITHUB_RUN_ID`·같은 대상일** 의 상태만 읽고, 아니면 "이번 실행의 수집 기록 없음". 원격 보관 결과(`원격 반영 <커밋>` / `변경 없음` / `원격 반영 실패`)를 보고에 표시. 상태 `OK / DEGRADED / FAILED`. FAILED·발송 실패는 종료코드 1(워크플로 빨강) — 생산 Gate 와는 연결하지 않는다 |
| **R4** 중단 시 성공분 소실 | 50종목마다 저장, 예외·중단 때도 `finally` 로 저장. 도구 시간 예산 20분(워크플로 제한 30→40분). 커밋 단계는 `if: always()` — 수집이 FAILED 여도 받은 것은 원격에 남긴다 |
| **R5** 정밀도·품질 | 숫자를 반올림 없이 저장(`123456789` 왕복 확인). 날짜 실재·유한값·음수·0가격·가격 관계(고가 ≥ 시가·종가·저가 등) 검사, 사유별 제외 수. 무거래 봉은 보존하고 따로 셈. 응답 종목 기호가 요청과 다르면 실패. **응답 성공 ≠ 대상일 확보** — `covered` 와 `missingTarget` 분리 |
| **R6** 잠긴 연구 유효일 상한 | 본 분석기와 같은 `trading_day_n(CONFIRM_FROM, 120)` 상한. 달력으로 정할 수 없으면 달력 끝(2026-12-31) 뒤 날은 세지 않고 "상한 미확정" 표시 |
| 방화벽 시험 강화 | '%' 부재 검사에 더해 **합성 수익률을 바꿔도 보고 본문이 같은지** 검사 |

**검증:** 시험 34건(기존 13건 갱신 + Codex 재현 9건을 안전 동작 통과형으로 이관 + 추가). 전체 897건 통과.
Codex 의 `reproduce_review.py` 를 새 모듈에 돌리면 9건 중 7건 통과, 2건은 **인터페이스가 바뀌어** 실패한다
(`missing_target_bar` 키 → `missingTarget`, `last_run.txt` → 실행 ID 를 확인하는 `last_run.json`). 같은 안전 동작은 이관한 시험이 확인한다.
**실제 fchart 응답·원격 커밋·텔레그램 도착은 아직 확인되지 않았다.** 첫 확인은 10/6 예약 실행 후 23:30 점검.

**남긴 것 (이번에 하지 않음):**
- 최초 대장 후보·대조군의 **에피소드 등록부** (Codex ①). 지금은 "최근 20 관측일" 임시 범위다. 추적 종료 규칙은 결과를 보기 전에 따로 정한다.
- 관측 원본과 **분석용 조정 가격 계열** 분리 (Codex ②). 지금은 원본 + 수정 기록만 쌓는다. 최근 5봉 재수집으로는 오래된 수정주가 변경을 못 잡는다.
- fchart 대량 원자료의 **공개 저장소 보관 조건** (Codex §5 끝). 공개 시세라고 재배포 허용이 확인된 것은 아니다 — 사용자 판단 사항으로 올린다.

## 2. stockinfo7 진단 (`hyeoks_theme_source_probe.py`)

| Codex | 고친 방식 |
|---|---|
| 구성 종목만 바뀌면 갱신을 놓침 | 카드·종목·숫자 전체를 정규화한 **내용 지문**. 기준 시각 문구는 따로 |
| 503 도 정상 종료 | 관측마다 `접속실패 / HTTP오류 / 파싱실패 / 첫관측 / 동일 / 갱신`. `--dump` 는 첫관측이 아니면 종료코드 1, `--watch` 는 유효 관측이 없으면 1 |
| 접속 시각에 날짜 없음·요청 전 시각 | 관측마다 **KST 날짜 포함 요청 시작·수신 완료**. 갱신은 "앞 유효 관측 ~ 이 관측 사이" 구간으로만 적는다 |
| 공개 로그에 카드 JSON | `RANK_JSON`·테마/종목 이름·본문 글자 출력 제거. 남기는 것: 기준 시각 문구·카드/종목 행 수·지문·매칭 **집계** |
| 동명 종목 첫 코드 선택 | 이름이 여러 코드에 걸리면 **모호** 로 빼고 센다 |
| '카드 1위' 표현 | '화면 선두 종목' 으로 부르고, 선별 화면(상승률 상위 종목의 테마만)이라는 안내를 비교 결과에 넣었다 |

시험 6건(`tests/test_theme_source_probe_20261005.py`). Codex 의 `reproduce_stockinfo7.py` 는 이제 결함 재현 단언에서 멈춘다(= 결함 없음).

**Codex 해석 정정을 받아들인다:** 10/2 비교의 2/21 은 시각·후보 모집단·선택법·대응 방식이 함께 다른 결과다.
"두 화면의 후보가 다르다" 까지만 말한다. stockinfo7 이 더 나은 대장 출처라는 증거는 없다.
