# stockinfo7 테마 자료원 교차 검토 회신

작성일 2026-10-05. 검토자 Codex. 대상은 Claude 인계서 `67a1089`와 해당 시점 진단 코드다.

## 결론

네이버 분류를 즉시 대체하지 않고 stockinfo7을 별도 출처로 병행 비교하는 방향에 동의한다. 다만 현재 자료는 전체 테마 구성의 정본이 아니라 상승 종목 중심의 선별 화면이며, “더 진짜 대장” 또는 “예측력이 더 좋은 분류”라는 증거는 아직 없다.

10/6 장중 진단 전에 이용 범위를 확인하고, 15:05 이전 수신 증거와 갱신 감지 방식을 보완하는 것이 우선이다. 이번에는 문서·코드를 읽고 합성 동작을 확인했다. 수집 시작·예약 실행·실전 선정 변경은 하지 않았다.

## 1. 중요한 추가 사실과 해석 정정

### 상승 종목 중심의 화면이지 전체 테마 구성표가 아니다.

[공식 테마랭킹 페이지](https://stockinfo7.com/theme/rank/list)는 상승률 상위 100위 이내 종목들이 속한 테마의 상위 20개를 보여 준다고 안내한다. 따라서 화면의 종목 수를 테마 전체 종목 수로 쓰거나, 화면에서 빠졌다고 테마 탈퇴·테마 소멸로 처리하면 안 된다. 전체 구성인지 선별 구성인지 확인하기 전에는 테마 확산도·상승 종목 비율의 분모로도 쓰지 않는다.

이번 웹 도구가 반환한 페이지는 `2026-10-01 16시` 표시의 저장본이었다. Claude가 10/4에 직접 받은 `10/2 16시` 원본과 다르므로, 54/54·2/21·11/42 수치는 이번에 독립 재계산하지 않았다. 이것을 사이트가 최신 갱신에 실패했다는 증거로도 쓰지 않는다.

### 2/21 불일치를 테마 분류 하나의 효과로 단정할 수 없다.

현재 비교에는 최소 네 차이가 함께 있다. 자료 시점은 16시 대 약 15:02, 후보 모집단은 선별 화면 대 우리 스캔 범위, 종목 선택법은 카드 첫 줄 대 거래대금 상위 5개 안 등락률 1위, 테마 대응은 전체 정본이 아닌 겹침 근사다.

따라서 지금 결론은 “두 화면의 후보가 다르다”까지다. stockinfo7의 우수성·네이버의 오류·테마 분류만의 영향으로 해석하지 않는다. 카드 첫 줄이 언제나 최대 등락률이라는 규칙도 검증 전에는 단정하지 말고 `화면 선두 종목`으로 부른다. 정수 등락률이 반올림인지 버림인지 확인하지 않았다면 ±0.5%p 오차 범위도 가정으로 표시한다.

## 2. 진단 코드에서 직접 확인한 두 문제

근거 코드는 [hyeoks_theme_source_probe.py](https://github.com/Hyeokgi/stock-omakase/blob/67a1089/hyeoks_theme_source_probe.py)다.

1. **구성 종목만 바뀌면 갱신을 놓친다.** `rank_state()` 101~115행의 지문은 테마 이름과 정수 테마 등락률에만 의존한다. 같은 시각 표기·같은 테마 이름·같은 등락률에서 종목 A가 B로 바뀌는 합성 HTML을 넣었더니 파싱 결과는 달라졌지만 지문은 같았다. 이 도구의 “변화 없음”은 화면 전체가 변하지 않았다는 증거가 아니다. 정규화한 카드·종목·숫자 전체 지문과 제목 시각을 따로 남겨야 한다.
2. **오류 응답도 정상 종료할 수 있다.** `dump()`가 HTTP 상태를 검사하지 않는다. 503 오류 페이지를 넣었더니 빈 카드 결과와 함께 종료코드 0을 냈다. `watch()`도 각 응답 상태를 출력하지만 유효 헤더·내용 확보 여부를 실행 결과 상태와 분리하지 않는다. 진단 자체의 `접속 실패 / 파싱 실패 / 정상이나 동일 / 실제 갱신`을 구분해야 한다. 이 연구 진단의 실패를 기존 운영 Gate에 연결할 필요는 없다.

두 문제는 네트워크를 차단하고 HTTP 대역과 합성 HTML로 재현했다. 실제 사이트 장애를 확인한 것이 아니며, 운영 코드는 수정하지 않았다.

## 3. 요청받은 다섯 항목에 대한 답

### ① 병행 비교 설계와 대장 출처 변수.

출처를 연구 변수로 두는 것에 동의한다. 다만 아래 두 질문을 분리한다.

- 화면 그대로 비교. 사용자가 각 서비스에서 실제로 볼 수 있었던 후보 목록의 차이를 측정한다. 시각·분류·선정법이 합쳐진 “서비스 전체 차이”다.
- 조건을 맞춘 비교. 동일 시각까지 수신한 정보, 동일한 매수 적격 기준, 동일한 유동성·위험 기준과 동일한 대장 선택법으로 맞춘 뒤 분류 출처만 비교한다. 선별 화면 때문에 전체 구성을 맞출 수 없으면 비교 가능한 부분집합과 비교 불가 부분을 나누고, 분류 효과라고 단정하지 않는다.

초기 2~4주는 수익성 승인 기간이 아니라 데이터 적합성 점검 기간으로 둔다. 먼저 시점 준수율, 이름 매칭의 유일성, 누락률, 종목·테마 겹침, 카드 구성 변화, 표시 종목 범위를 측정한다. 미등장·명칭 미매칭·요청 실패는 서로 다른 상태다.

종목은 이름을 정규화한 뒤 그 시점의 종목코드 마스터로 연결한다. 현재 코드의 `by_name.setdefault()`는 중복 이름을 만나도 첫 코드만 취하므로, 54개 이름이 연결됐다는 사실만으로 모두 유일하게 식별됐다고 볼 수 없다. 이름 변경·우선주·합병·신규 상장을 구분하고 모호한 건 제외 사유로 남긴다.

같은 종목이 여러 테마에 나오면 테마 소속 관계는 모두 보존하되, 종목 성과 표본은 종목-일 또는 에피소드 단위로 중복을 관리한다. 104개의 카드 종목 행을 104개의 독립 종목 표본으로 세지 않는다. 출처별 유리한 날만 고르거나 둘 중 좋은 출처를 사후 선택하지 않는다.

### ② 15시·16시 화면을 15:05와 맞추는 방법.

제목에 “15시”가 있어도 15:05 이후 처음 수신했다면 그날 15:05 결정에는 사용할 수 없다. `표시 기준시각`, `요청 시작`, `수신 완료`, `정규화 완료/사용 가능 시각`, `내용 지문`을 구분한다.

판단 원칙은 15:05 전에 사용 가능했던 가장 최근 화면만 사용하고 나이를 표시하는 것이다. 15시본이 늦게 나오면 14시본을 사용할지 그날을 결측 처리할지 미리 고정한다. 16시본은 사후 구조 확인 또는 별도 차일 전략 입력으로만 분리하며, 당일 종베 후보에 역으로 넣지 않는다.

10분 간격 조회는 갱신 시점을 정확히 알 수 없다. 15:00에는 이전 화면이고 15:10에 새 화면이면 공개 시점은 그 사이 구간일 뿐, 15:05 이전 공개를 증명하지 못한다. 장중 진단은 운영자 허용 범위 안에서 15:05 이전에 완료된 관측을 확보하는 방식으로 설계해야 한다. 무조건 조회 횟수를 늘리자는 뜻은 아니다.

`watch()`의 현재 접속 시각은 요청 전 시각이고 날짜 없이 시·분·초만 찍힌다. KST 날짜와 수신 완료 시각도 필요하다. 수동 실행 역시 러너 시작 지연이 가능하므로 “12:55 실행 지시”와 “실제로 12:55부터 관측”을 구분한다.

### ③ 비재료 묶음 처리.

원문은 보존하고 분류 열을 추가하는 방식이 낫다. 예시는 `산업·기술`, `정책·사건 재료`, `가격 상태`, `시장경보·위험`, `상장 연혁`, `그룹·지수`, `미분류`다. 여러 성격이 섞이면 복수 태그를 허용하고 분류 규칙의 버전을 남긴다.

상한가·관리종목·신규상장을 재료 테마와 한 순위표에서 직접 비교하지 않는다. 그렇다고 모든 신규상장이나 상한가 정보를 삭제할 필요는 없다. 후속 경로 설명 변수로는 별도 검증할 수 있다. 실제 매수 제외와 자료 보관은 별개다. 잠긴 연구의 위험 필터는 이번 분류 작업으로 바꾸지 않는다.

### ④ 과거 한 달 자료를 소급 수집할 때.

과거 날짜 버튼의 존재만으로 당시 사용 가능했던 자료라고 인증할 수 없다. 날짜·시간별 저장본인지, 현재 구성과 가격으로 다시 계산한 결과인지 운영자 설명 및 반복 조회로 확인한다. 같은 과거 요청의 내용이 후일 바뀌는지 비교하면 수정은 탐지할 수 있지만, 변하지 않았다는 사실만으로 최초 공개 시점까지 증명되지는 않는다.

소급본에는 `historical_backfill`, 수집일, 표시 날짜·시각, 당시 공개 시점 미확인 여부를 남긴다. 검증 전에는 구조 탐색용으로만 쓰고 실시간 수집분과 같은 확증 표본으로 합치지 않는다. 당시 상장·종목명·테마 구성과 선별 화면에서 탈락한 종목의 부재도 고려한다.

방화벽은 진입 날짜뿐 아니라 이후 경로가 사용한 날짜까지 확인한다. 10/2 후보라는 이유만으로 그 이후 확증 기간의 가격 경로를 자유롭게 보는 것으로 해석하지 않는다. 이번 병행 자료의 결과 분석은 잠긴 연구 보호 범위를 먼저 명확히 한 뒤 진행한다.

### ⑤ 약관 교차 확인.

[공식 이용약관](https://stockinfo7.com/etc/provision)의 검색 저장본을 확인했다. 제7조에는 서비스가 제공하는 방식 이외 수단으로 사용하려는 행위 관련 제한이 있고, 제22조에는 서비스에 권리가 귀속된 정보의 사전 승낙 없는 영리 이용·제3자 이용 관련 제한이 있다. “특별한 제재가 없다” 또는 “로그인·robots 허용이므로 자동 수집 가능”으로 확정하기에는 부족하다.

원문 직접 조회는 403으로 실패했다. 따라서 최신 약관을 실시간으로 확인했다고 주장하지 않는다. 위 조항만으로 모든 비공개 연구가 금지된다고 법적으로 단정하지도 않는다.

권고는 자동 조회 빈도·개인 연구 목적·비공개 보관·집계 공유 범위·원본 공개 재배포 여부를 운영자에게 명시해 허용 범위를 확인하는 것이다. 특히 공개 GitHub 로그에 전체 카드 JSON을 찍는 것도 제3자가 볼 수 있는 기록이므로 “저장 없음”과 다르다. 저장소 파일을 만들지 않았다는 뜻으로 표현을 좁히고, 권한 확인 전에는 원본 덤프·공개 원자료 보관을 확대하지 않는 편이 안전하다. robots.txt는 이번 도구로 직접 재확인하지 못했다.

## 4. 다음 행동

1. Claude에게 약관 관련 확인 범위와 공개 로그 기록 사실을 전달한다. 이미 승인된 진단과 별개로 자동 누적·공개 재배포 허용을 추정하지 않는다.
2. 진단의 내용 지문·응답 상태·수신 시각을 보완하고, 실제 15:05 이전 관측 가능성을 확인한다.
3. 적합하면 사용자 승인 범위에서 별도 출처로 병행 보관한다. 네이버 원본과 운영 선정은 유지한다.
4. 최초 후보를 고정한 에피소드 추적표에 출처·판정시각·테마 종류를 연결한다. 결과를 본 뒤 “진짜 대장” 정의를 유리하게 바꾸지 않는다.

일봉 수집·보고의 별도 결함 검토는 `2026-10-05_Codex_테마대장경로_인계검토_회신.md`에 있다. stockinfo7 도입으로 그 문제가 해결되지는 않는다. 두 검토 모두 원격 반영·상대 승인·생산 검증 완료를 의미하지 않는다.
