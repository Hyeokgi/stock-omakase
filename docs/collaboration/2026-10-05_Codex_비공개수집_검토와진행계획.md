## 1. 결론

원자료 비공개 전환, 실행별 원본 보존, 연구와 생산 판정 분리, 잠긴 연구의 결과 열람 통제는 타당하다. 이 방향을 유지한다. 대장 정의를 처음부터 다시 만들거나 운영 선정 기준을 바꿀 필요는 없다.

다만 **수집기 구현 완료와 연구 자료의 사용 가능 판정은 별개**다. 다음 경계가 남았으므로 “A 완전 해결”, “중복 없음”, “15시본 확보”라는 표현은 좁혀야 한다. 생산 P0라고 일괄 분류하거나 안정화 종료를 무기한 미룰 사안은 아니다. 연구 파일에서 최소 보완하고, 기존 생산 변경은 별도 판단한다.

## 2. 확인된 개선

- 가격·종목별 상태·HTML은 Drive 업로드 대상으로 분리하고 공개 요약에는 행 원자료를 넣지 않는다. 다만 Drive 접근 권한은 이번에 직접 확인하지 않았다.
- 매 실행 300봉을 요청하고, 대상일 이후 자료와 당일 미확정 봉을 분리한다.
- 종목별 기간 충족을 `완전 / 짧은응답 / 검사탈락 / 대상일없음`으로 구분한다. 짧은 응답을 짧은 상장 이력이라고 인증하지 않는다.
- 보조 연구 실패를 운영 Gate의 새로운 판정 기준으로 넣지 않는다.
- 보고 함수는 구조·수집 상태만 내보내며 합성 수익률을 바꿔도 보고 내용이 같다는 시험을 통과했다.
- 시험 결과는 일봉 40건 + stockinfo7 수집 6건 + 진단 6건, **52건 모두 통과**다. HTTP get/post 호출은 0건이며 소켓도 차단했다. 전체 911건을 재현했다는 뜻은 아니다.

## 3. 실제로 재현한 남은 경계

### R7. 우선 구간 자체는 반복 누락될 수 있다. 연구 품질 우선 보완.

근거는 [우선 구간 구성](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_research_daily.py#L199), [시간 제한과 재개 위치](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_research_daily.py#L277)다.

우선종목 2개와 나머지 1개를 두고, 매번 첫 종목까지만 처리할 예산으로 두 번 실행했다. 실제 요청은 `[000001, 000001]`, 마지막 실행의 미처리 2개, 재개 위치는 0이었다. Claude의 A 시험은 **우선 구간이 빈 경우**의 나머지 회전은 검증하지만 우선 구간의 뒤쪽은 검증하지 않는다.

권고는 우선 구간에도 회전 위치 또는 미처리 우선 재시도 규칙을 두는 것이다. 지수·오늘 후보·미종결 에피소드·고정 대조군의 필요성을 유지하면서 어느 구간도 무한 대기하지 않게 한다. “항상 먼저”와 “모두 매일 확보”는 다르다. 실제 대상 수와 평균·느린 응답 시간을 첫날 측정해 시간 예산을 판단한다.

### R8. 화면의 날짜가 달라도 당일 15시본처럼 보고된다. 자료 채택 전에 보완.

근거는 [theme_obs_summary](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_research_daily.py#L393)다. 현재 `header.endswith(' 15시')`만 확인한다.

10/6 15:02:01에 받은 화면의 헤더를 `2026-10-02 15시`로 넣어도 `15시본 15:02:01 (15:05 전 수신)`이라고 보고했다. 이 시험은 실제 오래된 응답이 발생했다는 증거가 아니라, 발생하면 구분하지 못한다는 재현이다.

화면 기준일·시각을 별도로 파싱하고 요청일·대상 거래일과 일치시키자. 수신 시각, 파싱 완료 시각, 실제 의사결정에 사용 가능했던 시각도 구분한다. 잘못된 날짜는 오류·오래된 자료로 남기고 오늘 비교에 넣지 않는다.

### R9. 동일 화면의 원본 참조와 보관 영수증이 부족하다. 분석 연결 전 보완.

근거는 [flush_private와 flush](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_theme_source_collect.py#L58)다.

15:10 체크포인트 뒤 화면이 계속 같으면 공개 메타는 `첫관측, 동일, 동일` 3행인데 첫 행만 privateFile이 있고 나머지는 빈칸이다. 원본이 지워졌다는 뜻은 아니다. 앞선 내용 지문으로 찾을 수 있지만, 각 관측에서 검증된 원본으로 직접 연결되지 않는다. 다른 변경 화면과 같은 배치가 되면 동일 화면의 참조가 다른 내용의 파일을 가리킬 여지도 있다.

관측마다 마지막으로 보관된 동일 내용의 원본을 참조하게 하자. stockinfo7 업로더 반환 Drive ID는 현재 버리고, 요약에는 name/ok/error만 남긴다. 일봉은 ID·크기가 있지만 SHA256은 없다. 두 경로 모두 `파일명·바이트 수·SHA256·Drive ID·업로드 접수 상태·원격 재다운로드 검증 상태`를 분리하면 좋다. 자동 재다운로드 기능까지 첫날 필수로 만들 필요는 없고, 첫 생산 파일을 수동으로 대조해도 된다.

### R10. stockinfo7 백업 중복은 완전히 막히지 않는다. 운영 보완.

근거는 [다음 관측이 마감 뒤면 즉시 종료하는 분기](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_theme_source_collect.py#L134)와 [시작 시 마감 검사](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_theme_source_collect.py#L157)다.

합성 시계에서 첫 실행은 16:26:04에 끝났고, 16:28 시작 백업은 다시 수집했다. 16:35 이후 시작만 검사해서 “앞 실행이 끝나면 항상 창 밖”이라는 보장이 없다. 대상일·관측창 완료 상태 또는 관측 키에 따른 중복 처리가 필요하다. 실패한 앞 실행까지 완료로 오인해 건너뛰어서는 안 된다.

추가 의심은 예약 대기 중인 실행의 저장소 상태다. 두 워크플로는 checkout의 ref를 명시하지 않는다. [공식 checkout 설명](https://github.com/actions/checkout#usage)은 기본값이 이벤트의 ref/SHA라고 밝힌다. 선행 실행의 상태 커밋보다 오래된 이벤트 SHA를 받으면, 뒤 실행은 최신 완료 기록을 못 볼 수 있다. concurrency만으로 최신 상태 열람이 보장되지 않는다. **이 부분은 실제 GitHub 대기 실행으로 재현하지 않았으며 코드·문서에 근거한 위험**이다. 코드 버전과 중복 판정용 최신 상태를 구분해서 읽고, 읽은 상태 커밋도 남기는 방안이 안전하다.

### R11. 수집 성공 후 보고만 실패하면 백업이 보고를 재시도하지 않는다. 운영 보완.

근거는 [OK/DEGRADED일 때 전체 생략](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_research_daily.py#L547)이다.

수집 상태 OK를 저장한 뒤 같은 실행의 발송을 실패시키면 종료코드 1이었다. 다른 실행 ID의 백업은 종료코드 0으로 생략했고 발송 호출도 0회였다. 수집 완료와 보고 완료를 하나로 보는 것이 원인이다. 보고 접수 상태를 별도로 남기고, 수집을 반복하지 않고 미발송 보고만 복구해야 한다. Telegram 응답이 불명확한 경우에는 중복 가능성도 별도로 남긴다.

## 4. 첫 생산 전에 특히 확인할 통합 위험

**연구 gzip 파일이 산업리포트 PDF 분석 대상으로 들어가지 않는지 확인해야 한다.**

첨부는 PDF와 연구 원본이 같은 폴더라고 명시한다. 공유 업로드 함수는 filename/base64만 보내므로 서버가 정하는 MIME 유형을 이번 코드만으로 알 수 없다. 반면 [hyeoks_trend.py](https://github.com/Hyeokgi/stock-omakase/blob/acc68ee/hyeoks_trend.py#L51)는 같은 폴더의 `application/pdf`를 가져오고, 파일명의 `.pdf` 확장자나 실제 PDF 서명 확인 없이 처리 예산에 넣어 Gemini 파일 업로드를 시도한다.

따라서 외부 GAS가 gzip도 PDF 유형으로 만들면 연구 파일이 리포트 처리와 섞일 수 있다. **현재 실제 MIME을 확인한 것은 아니므로 조건부 위험**이다. 첫 연구 파일의 부모 폴더·MIME·이름·권한·실제 바이트를 확인하자. 잘못된 경우 업로드 유형 또는 연구 전용 폴더를 바로잡거나 PDF 소비자에 진짜 PDF 필터를 두는 작은 수정이 필요하다. 이 위험 때문에 정상 산업리포트 분석을 시험 삼아 유료 실행하지는 않는다.

쓰기 전용 GAS의 동일 파일명 처리·애매한 성공 후 재시도 시 중복 생성 여부도 미검증이다. 업로드 ID 수신과 파일 무결성 검증을 혼동하지 말자. `finally`는 정상 예외 처리에는 도움이 되지만 강제 종료·러너 소멸까지 보존을 보장하지 않는다.

## 5. 인계서의 다섯 질문에 대한 답

### ① 매일 300봉 재수집.

현재의 쓰기 전용 제약 아래서는 **초기 수집 방식으로 수용 가능**하다. 다만 중복 다운로드 비용·시간 제한·300봉 창 밖의 소실을 감시해야 한다. 나중에 읽기 가능한 비공개 상태 저장을 마련하면 증분 수집과 정기 전체 대조로 줄일 수 있다. 지금 저장 구조 전체를 다시 만들 필요는 없다.

처음 받은 값과 이후 값은 모두 불변 원본으로 보존한다. 분석별로 사용한 파일·해시·수신 시각을 고정한다. 재수집 자체는 **수정 탐지가 아니라 비교 가능한 자료 확보**다. 동일 종목·날짜의 값이 달라졌는지 비교하는 단계가 별도로 필요하다.

실제 과거 의사결정 입력은 그때 사용 가능했던 버전만 사용한다. 이후 가격 경로는 동일 기준의 기업행사 조정 계열을 확보한 뒤 계산한다. 서로 다른 날짜에 받은 수정주가와 최초 스냅샷 가격을 그대로 나누지 않는다. 차이가 났다고 액면분할로 자동 단정하지 말고, 조정 사유 미확인이면 해당 경로 평가를 보류한다.

### ② 우선 구간과 추적 기간.

에피소드 등록부가 생기면 **오늘 신규 후보 + 미종결 에피소드의 종목 + 최초 고정한 대조군 + 기준 지수**가 핵심 대상이다. 대장 배지가 사라져도 추적을 계속한다. 최근 20관측일은 임시 수집 근사일 뿐, 대장이 끝났다는 증거나 반드시 충분한 보유 기간이 아니다. 결측일은 종료일로 바꾸지 않는다.

에피소드 추적의 행정적 최대 기간은 연구 시작 전에 정하되 10일·10%를 수익 최적화 문턱으로 자동 고정하지 않는다. 상한에서 미종결이면 우측 검열로 남긴다. 미래 자료로 “곧 다시 대장이 될 종목”만 우선 선정하면 안 된다.

### ③ stockinfo7의 15:05 정렬.

주 분석은 **당일 15시 기준 화면이고, 실제로 15:05까지 수신·파싱 완료된 것 중 가장 최근 관측**을 쓰는 것을 권한다. 없다면 결측이다. 14시본은 별도 오래된 자료 비교군으로만 남기고 주 분석의 15시본 빈칸에 대신 넣지 않는다. 15:05 이후 받은 화면을 헤더가 15시라는 이유로 소급 사용하지 않는다.

운영 기준 15:05는 유지한다. 10분 간격으로는 갱신 순간이 아니라 “직전 동일 관측과 첫 갱신 관측 사이”만 안다. 실제 신호 선택·주문까지 필요한 여유 시간도 따로 측정해야 한다. 일단 관측 후 필요한 경우에만 수집 시각 보완을 결정하고 무작정 빈도를 높이지 않는다.

### ④ 10/7~10/8 에피소드 등록부 첫 판.

첫 판의 성공 조건은 **동일 후보를 끝까지 추적하고 분모가 사라지지 않는 것**이다. 네이버와 stockinfo7은 다른 출처로 병행 보존하고, 아직 어느 쪽이 진짜 대장인지 하나로 합치지 않는다. stockinfo7은 선별 화면이므로 거기 안 나온 종목을 테마 비구성원으로 단정하지 않는다.

- 최초 시각·출처·그날 테마·최초 대장 후보·고정 대조군·선정 당시 조건을 등록한다.
- 주 대조군은 같은 날 같은 테마의 적격 비대장 종목이다. 등락률·유동성·변동성 등이 비슷한 비교를 사전에 제한된 규칙으로 정한다. 정의상 대장을 만드는 변수까지 무리하게 똑같이 맞추지 않는다.
- 보조 대조군은 그날 A 모집단에서 적격 조건을 같이 적용해 고정된 방식으로 선정한다. 표본 추출 시 코드 정렬과 고정 시드를 기록한다.
- 대조군이 이후 대장이 되더라도 교체·삭제하지 않는다. 사건으로 표시한다. 여러 테마에 같은 종목이 겹치면 독립 표본처럼 반복 세지 않는다.
- 상태는 진행 중·관측 결측·종료·상한 도달을 구분한다. 최초 배지 소실만으로 종료하지 않는다.
- 당시 상태표와 이후 결과표를 분리한다. 연구 탐색에는 상태뿐 아니라 **결과에 쓰는 가격 날짜도 10/2까지로 제한**하고, 10/6 이후 확증 기간의 성과 열람을 우회하지 않는다. 미성숙한 기존 에피소드는 미성숙으로 둔다.

가격 계열 확인 후에만 바로 상승·횡보 뒤 상승·가격조정 뒤 회복·추세 약화의 경로를 붙인다. 일봉 한 봉에서 상승·하락 기준을 모두 건드리면 순서를 알 수 없으므로 미확정으로 둔다. 미래 결과로 만든 경로 이름을 예측 입력으로 쓰지 않는다.

### ⑤ 이용 범위와 중단 기록.

사용자가 개인 비영리 수집을 선택했다는 기록과 **제공처가 허용했다는 증거는 별개**로 유지한다. 이 회신은 허용 여부의 법적 판정을 하지 않았고 약관을 새로 교차 검토하지 않았다.

인증 요구·접근 거부·운영자 중단 요청은 우회하지 않고 해당 자료원 수집을 보류한다. 429는 제공처의 재시도 안내와 제한을 따르고 반복 시 보류한다. 관련 날짜·조건·연락 내용을 최소한으로 남긴다. 삭제가 필요하면 정확한 파일·기간·사본 범위를 정하고 사용자 승인을 받아 진행한다. 증거 없이 “개인용이므로 문제없음”으로 기록하지 않는다.
