## 1. 저장소에 없던 것

### 1-1. 네이버 뉴스 검색 API 는 쓰지 않기로 했다 (10/7~10/8 대화)

- 네이버 개발자 센터 애플리케이션 등록 화면의 '사용 API' 목록에 '검색'(과 '데이터랩')이 없었다. 'API 상태' 화면에는 검색 API 가 정상으로 나왔다. 이미 등록된 앱이 쓸 수 있다는 뜻이지 신규 신청이 된다는 뜻은 아니다.
- 'API 제휴 신청' 화면에 검색 API 신규 제휴를 받지 않는다는 안내가 있었다. 반려 사유에 "API 결과 데이터의 추출 및 저장 목적" 이 들어 있었다(사용자 캡처, 저장소 미보관). 제목·시각을 쌓는 우리 목적과 맞지 않는다.
- 그래서 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 시크릿은 만들지 않았다. 재료 층은 OpenDART 공시(기존 `DART_API_KEY`)와 한투 '시황·공시 제목'(기존 한투 앱키)으로 갔다 — [재료 층 기록](2026-10-08_Claude_재료층_DART수집개시_한투뉴스시험.md).
- 검토만 하고 쓰지 않은 대안이 있다. 빅카인즈(한국언론진흥재단) 뉴스 API 는 신청·승인이 필요하다. 언론사 RSS 는 언론사별 이용 조건 확인이 필요하다. 키움 OpenAPI+ 는 뉴스 조회가 없는 것으로 보이고 윈도우 PC 상주가 필요하다. 키움 REST API 는 뉴스 항목이 있는지 확인하지 않았다. 키움 쪽은 Claude 의 기억에 기댄 추정이고 문서로 확인하지 않았다.

### 1-2. 예약 점검은 클라우드 세션 안에서 돈다 — 그 세션을 보관하면 멈춘다

- 그 세션의 안내를 옮긴다. 이 루틴은 그 대화 세션에서 실행되므로, 세션을 보관(아카이브)하면 함께 멈춘다.
- 사용자가 PC 세션에서 작업을 이어 가더라도 **클라우드 세션은 보관하지 않는다.**
- 10/12 08:30 점검은 클라우드 세션에서 돈다. 그날 07:45 텔레그램 브리핑 원문 대조가 필요하면 원문을 **그 클라우드 세션**에 붙인다. PC 세션에 붙이면 그 점검과 이어지지 않는다.

### 1-3. 통합 AI 는 어떻게 주고받나 (요청서 끝 질문에 대한 답)

[Gemini 평가 요청서](2026-10-11_Claude_Gemini_시스템평가_요청.md) 끝에 남은 질문에 대한 답이다.

- 사용자 PC 에 통합 작업공간이 있다. PC 의 Claude 세션이 Codex(앱에 들어 있는 CLI)와 Gemini(Antigravity CLI `agy`)를 명령줄로 부른다. 클라우드 세션은 그 작업공간과 CLI 에 닿지 않는다.
- 클라우드 세션과 PC 세션 사이의 창구는 **이 허브와 `docs/collaboration/`** 이다.
- 클라우드 세션이 Gemini·Codex 에게 맡길 요청서를 여기에 올린다. 사용자가 PC 세션에 처리하라고 하면 PC 세션이 pull → 실행 → 결과를 `날짜_<AI>_주제.md` 로 올리고 허브 §4 에 한 줄을 더한다. 작성자 표기는 "<AI> (PC Claude 전달본)" 이다.
- 자동 감시는 없다. 첫 사례는 [Gemini 평가 보고](2026-10-11_Gemini_시스템평가_보고.md) (`2068ab3`) 다.

### 1-4. 작업 주체가 둘이 됐다

- 사용자는 2026-10-11 부터 주식 작업을 PC 세션에서도 이어 간다. 두 세션이 같은 저장소에 쓴다.
- 두 세션 모두 작업을 시작할 때 `git fetch origin main` 후 최신 허브를 읽는다(허브 §1 그대로). 지문 대상 파일은 한쪽에서만 고치고, 고치기 전에 기록을 먼저 남긴다.
- PC 체크아웃은 2026-10-11 기준 GitHub 보다 537커밋 뒤처져 있었다. fast-forward 로 맞췄다.
- PC 체크아웃은 Windows 라서, 거기서 지문을 계산하면 CRLF 때문에 다른 값이 나온다(10/9 Codex 확정). 지문은 CI 값으로 본다.
- PC 쪽 시험 환경에는 아직 pytest 가 없다. 시험이 필요한 변경은 설치 후에 하거나 클라우드 세션·CI 결과로 확인한다.
