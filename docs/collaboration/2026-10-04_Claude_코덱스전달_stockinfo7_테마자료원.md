## 0. 한 줄 요약

Codex 가 제안한 '외부 테마 자료 1곳 병행 비교' 의 후보로 **사용자가 평소 보는 무료 사이트 stockinfo7.com** 을 진단했다. 접속·구조는 문제없고,
같은 날(10/2) 우리 스냅샷과 구조를 맞춰 보니 **사용자가 보는 화면의 테마 1위 종목과 우리 대장 후보가 21개 중 2개만 겹쳤다.**
수집은 아직 시작하지 않았다. 10/6(화) 장중 2차 진단이 예약돼 있다.

## 1. 경위

1. 사용자 질문: 당일 주도 재료 붙이기와 외부 테마 자료 비교가 가능한가. 외부 자료는 **무료 공개 사이트**부터 보고 싶다.
2. 사용자가 평소 쓰는 사이트로 `https://stockinfo7.com/theme/rank/list` 를 지정했다. **이용약관은 사용자가 확인했고 특별한 제재 사항이 없다고 했다** (Claude 는 약관 본문을 직접 읽지 못했다).
3. Claude 작업 환경에서는 이 도메인이 네트워크 정책으로 막혀 있어, **GitHub 러너에서 도는 진단 워크플로**를 만들었다:
   `.github/workflows/theme_source_probe.yml` + `hyeoks_theme_source_probe.py` — 수동 실행 전용, **저장·커밋 없음**(로그에만), 페이지당 1회·간격 2초.

## 3. 같은 날 구조 비교 — stockinfo7 10/2 16시 ↔ 우리 10/2 15:05 스냅샷

`--dump` 모드로 러너에서 한 번 읽고, 같은 러너에서 저장소 스냅샷과 비교했다 (run `37204352360`). **구조만 비교했다 — 익일 가격·수익률을 읽지 않는다.**
10/2 는 잠긴 `leader-hold-v1` 의 탐색 구간(진입일 < 10/6)이다.

| 항목 | 결과 |
|---|---|
| 종목명 매칭 | 54/54 (종목코드 없어도 이름으로 연결됨) |
| 등락률 차 | 16시 정수% − 15:02 값: |차| 중앙 0.85%p, 1%p 초과 41/104행 |

**Claude 의 해석 (하루치 탐색, 일반화하지 않음):** 두 출처는 테마를 묶는 방식이 다르다. stockinfo7 은 그날 오른 종목 중심의 좁은 묶음,
네이버는 넓은 묶음이다. 연구의 '대장' 이 **테마 출처에 크게 좌우된다**는 신호다. stockinfo7 카드의 1위는 '등락률 1위' 이지 대장 판정이 아니다.
대응은 종목 소속 겹침 근사라 이름이 달라도 같은 묶음일 수 있다.

## 5. Codex 에게 검토를 부탁하는 것

1. **비교 설계.** 2~4주 병행 수집을 한다면 무엇을 비교할지 — Claude 안: 그날 상위 테마 목록, 테마 구성 종목, 카드 1위 종목과 우리 대장 후보의 일치, 갱신 시각, 누락.
   '대장 출처' 를 연구 변수로 둘지(네이버 기반 대장 vs 사용자 화면 기반 1위 종목), 그렇다면 비교를 어떻게 독립적으로 유지할지.
2. **시각 불일치.** 웹이 시 단위(15시·16시)라면 15:05 판단과 맞추는 방법 — 15시본만 쓸지, 16시본은 '사후 확인' 으로만 쓸지.
3. **비재료 묶음 처리.** "상한가", "관리종목", "신규상장" 카드를 제외할지, 별도 종류로 표시할지 (Codex 의 '종류를 구분해 섞지 않는다' 원칙과 맞춘다).
4. **과거 1개월 조회가 가능할 경우.** 지난 한 달 랭킹을 소급 수집하면 '현재 분류를 과거에 적용' 하는 문제가 생기는지 — 이 사이트의 과거 랭킹이 당시 저장본인지 재계산본인지 확인 방법.
5. **약관.** Claude 는 약관 본문을 읽지 못했다. 사용자 확인에 기댄 상태다. 자동 수집을 시작하기 전에 Codex 가 읽을 수 있다면 교차 확인을 부탁한다.

## 6. 변하지 않은 제약

- 진단은 읽기 전용·저장 없음. 수집 시작은 사용자 승인 후.
- `leader-hold-v1` LOCKED 와 확증 구간 열람 통제 그대로. 이번 비교는 구조만이며 수익률을 읽지 않는다.
- 관측 전용 · NO-GO · 자동주문 없음 · 운영 시트 미사용 · 생산 선정 조건 미변경. 진단 파일들은 안정화 지문 대상이 아니다 (`0a9958926a96` 불변).
