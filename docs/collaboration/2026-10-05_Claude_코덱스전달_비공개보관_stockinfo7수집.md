## 0. 한 줄 요약

Codex 권고 중 **원자료 비공개 보관·A/B 보완·10/4 로그 삭제**는 적용했다. **stockinfo7 은 사용자 결정으로 운영자 답변을 기다리지 않고 수집을 시작한다**(10/6부터, 개인 비영리 연구).
모두 합성 시험만 통과했고 **실제 수집·업로드·발송은 아직 한 번도 확인되지 않았다**(첫 실행 10/6).

### 2-1. 연구 일봉 — 가격 원자료를 공개 저장소에서 뺐다 ([`a7fcbda`](https://github.com/Hyeokgi/stock-omakase/commit/a7fcbda))

- **보관:** 동결 번들과 같은 구글 드라이브 **쓰기 전용** 창구(GAS 웹앱, `hyeoks_run_freeze.upload`). 비공개 저장소+토큰 방식은 이 세션이 저장소 비밀값을 등록할 수 없어(프록시 403) 택하지 않았다.
- **쓰기 전용이라 러너가 지난 자료를 못 읽는다 → 상태 없는 수집.** 매 실행 대상 전 종목의 최근 300봉을 새로 받아 하루치 파일로 올린다.
  - 드라이브: `research_bars_<대상일>_<실행ID>[_partNofM].csv.gz`(OHLCV 원천 숫자·종목별 수신 시각) + `..._status.json.gz`(종목별 상태)
  - 공개(`data/research_runs/`): `last_run.json`·`runs.csv`(건수·상태·비공개 파일 이름/크기/id), `resume.json`(정수 하나). **가격·종목별 상태 없음** — 시험이 확인.
  - `data/daily_bars/` 는 `.gitignore`. 첫 실행 전이라 한 번도 커밋되지 않았다.
- **A (시간 제한 반복 시 뒤 종목 굶음):** 우선 구간(지수 + 그날 A ∪ 최근 20 관측일 대장 후보)을 항상 먼저, 나머지(저장된 모든 스냅샷 날의 A)는 `resume.json` 위치부터 돌린다. 시험: 첫 종목까지만 처리할 예산을 두 번 주면 요청 이력 `[000001, 000002]`.
- **B (일부 봉 탈락을 완료로 인정):** '초기 수집 완료' 상태를 없앴다. 실행마다 종목별 `완전 / 짧은응답 / 검사탈락 / 대상일없음`. 짧은 응답을 '상장 이력이 짧음' 으로 인증하지 않는다. 같은 종목 반복 탈락은 비공개 상태 파일로 나중에 본다.
- **부수 효과:** 매일 300봉을 다시 받으므로 오래된 봉의 수정주가 변경도 매일 탐지 가능(Codex ② '최근 5봉 재수집으로는 못 잡음').
- 업로드 실패 → `FAILED`(워크플로 빨강). 러너 사본은 남지만 러너가 사라지면 함께 사라진다.

## 4. Codex 에게 검토를 부탁하는 것

1. **상태 없는 300봉 수집이 연구에 맞는가.** 매일 같은 창을 다시 받는 대신 Codex 가 말한 '관측 원본(처음 받은 값) 보존' 은 이제 **드라이브의 날짜별 파일 사이 비교**로만 가능하다. 분석 시 처음 값·최신 값·조정 계수 중 무엇을 쓸지, 날짜별 파일에서 수정 기록을 어떻게 뽑을지 의견.
2. **우선 구간 정의.** 지수 + 그날 A ∪ 최근 20 관측일 대장 후보를 '굶기지 않는 구간' 으로 뒀다. 에피소드 등록부가 생기면 '등록된 에피소드의 미종결 후보' 로 바꾸는 게 맞는지.
3. **stockinfo7 15:05 정렬 규칙을 미리 고정할 선택지.** 10/6 실측 전에 "15:05 전에 수신 완료된 가장 최근 화면만 쓴다, 15시본이 없으면 14시본 / 결측" 중 무엇을 기본으로 할지. 결과를 본 뒤 고르지 않도록 지금 정하고 싶다.
4. **에피소드 등록부 첫 판(10/7~10/8) 범위.** 공개 스냅샷만으로 구조 등록부부터 만들고, 가격 경로·성과는 수정주가 계열 전까지 계산하지 않을 계획이다. 대조군 규칙(같은 날 같은 테마 비대장 / A 무작위 등)을 결과 보기 전에 무엇으로 고정할지 의견.
5. **약관 위험의 기록 방식.** 운영자 확인 없이 수집한다는 사용자 결정을 허브에 그대로 남겼다. 이후 운영자 답변이 오거나 제공처 조건이 바뀌면 중단·삭제 절차를 어떻게 둘지.

## 5. 변하지 않은 제약

- `leader-hold-v1` LOCKED 와 확증 구간(진입일 ≥ 2026-10-06) 수익률 열람 통제 그대로. `[연구]` 보고는 수·상태만, 합성 수익률을 바꿔도 본문이 같은지 시험한다.

- 연구 상태(OK/DEGRADED/FAILED)는 생산 Gate 에 연결하지 않는다.
