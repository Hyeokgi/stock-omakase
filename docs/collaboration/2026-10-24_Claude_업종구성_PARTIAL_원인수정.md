## 원인 — 조회 실패가 아니었다

- 10/21~10/23 1300 · 1505 스냅샷의 `upjongMembershipStatus=PARTIAL`. 업종 집계 파일(10/23 1505)을 보면 **79개 중 78개 OK, '기타' 1개만 PARTIAL** 이다.
  - '기타'는 구성 1,555종목을 끝까지 받았고(잘림 없음 · 오류 없음), 그중 스캔과 연결된 종목은 2개다.
  - 이 파일 머리 주석(2026-08-28)도 '기타'를 "분류라기보다 쓰레기통"이라고 적었다.
- `fetch_sector_data` 가 가격 연결 부족(`len(mine) < len(codes)`)도 `membershipStatus=PARTIAL` 로 쳤다.
  업종 하나라도 OK 가 아니면 `membership_status(out) != "OK"` → `belong = {}` 라 **모든 종목의 업종 연결(`upjongNos`)이 지워졌다.**
  10/21~10/23 종목행 약 2,870개의 업종 연결이 0건이다.
- `naver_membership.membership_status` 의 설명은 "구성 목록의 완전성만 집계한다. 가격 자료의 품질과는 별개다" 인데, 업종 행의 규칙이 이와 어긋났다.
- 10/15 이전에는 '기타'가 200종목에서 잘려 받혔고 상태 열이 없었다. 10/20 전량 조회로 바뀌면서 드러났다.
- 영향 없음: 대장 정의 v2(`themeMembershipStatus` 만 본다), 테마 · 그룹 연결, 선정 · 판정.
- 업종 요약표(`write_readme`)도 행 하나만 OK 가 아니어도 통째로 보류돼 10/21 부터 매일 비어 있었다.

## 수정

| 대상 | 전 | 후 |
|---|---|---|
| 업종 · 그룹 행 `membershipStatus` | 조회 실패 FAILED · 잘림 **또는 가격 연결 부족** PARTIAL | 조회 실패 FAILED · 잘림 PARTIAL · 그 외 OK |
| 그 업종의 집계(sum* · *Count · topBy*) | 상태가 OK 가 아니면 비움 | 상태가 OK 가 아니거나 **가격 연결 부족이면** 비움 — '기타' 합계는 지금처럼 빈칸 |
| 종목의 업종 연결 | 한 업종이라도 OK 아니면 전부 삭제 | 잘림 · 조회 실패가 있을 때만 전부 삭제(그대로) |
| 요약표 | 한 행이라도 OK 아니면 보류 | 구성 불완전이면 보류(그대로). 집계를 비운 업종만 빼고 "집계 보류 N개: 이름" 을 적는다 |
| 집계 파일 머리 주석 | "membershipStatus!=OK 는 구성/가격 연결 불완전" | "membershipStatus!=OK 는 구성 목록 불완전 · matchedCount<fetchedCount 는 가격 연결 부족 — 둘 다 집계 보류" |

**과거 파일은 고치지 않는다.** 10/21~10/23 의 빈 업종 연결은 되살리지 않는다(업종 구성은 거의 바뀌지 않아 필요하면 분석 때 현재 구성으로 채울 수 있다 — 그때 '사후 채움' 으로 표시).
