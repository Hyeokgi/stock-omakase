## 1. 정의 (v1 고정)

| 항목 | 정의 |
|---|---|
| 출처 | 네이버 15:05 스냅샷, 종목 테마 = `topThemeNo` (`SOURCE=naver-topThemeNo-1505`). stockinfo7 은 별도 출처로 두고 **합치지 않는다**(장중 시간본이 없어 15:05 등록에 쓸 수 없음 — 10/6 실측) |
| 에피소드 시작 | 현행 대장 정의(`build_B_current`)에 나온 종목 중 **그 종목에 열린 에피소드가 없을 때**. 테마는 t0 테마로 고정. 종목당 열린 에피소드 1개 — 다중 테마 중복을 독립 표본으로 세지 않음 |
| 주 대조군 | t0 같은 날 **같은 테마**의 A 적격 비대장(등락률 29.5% 이상 제외) 중 `|log 거래대금 차|` 가 작은 순 2종목, 동률은 코드순. 등락률은 맞추지 않는다(대장 정의 변수) |
| 보조 대조군 | 그날 A 의 적격 비대장 전체 → 코드 정렬 → `random.Random(20261007 + YYYYMMDD)` 로 3종목. 그날 열린 에피소드가 공유. 시드 기록 |
| 대조군 사건 | 대조군이 나중에 대장이 되면 교체·삭제하지 않고 `대조군→대장` 사건으로 처음 한 번 표시. 대조군 중 t0 에 이미 열린 에피소드가 있던 종목도 빼지 않고 표시 |
| 상태(관측일별) | 진행 중 · 관측 결측(그날 스냅샷에 없음) · 상한 도달(행정 상한 **60 관측일**, 우측 검열) · 종료(소멸 추정: **연속 10 관측일** 스냅샷에 없음). 배지 소실은 종료가 아니다 |
| 당시 상태표 | 관측일별 `in_snapshot · in_A · leader_today · same_theme_today` — 그날 스냅샷만 사용 |
| 이후 결과표 | **v1 에는 없다.** 수정주가 계열 확보 후 별도로 만든다. 탐색에서 결과 가격 날짜는 10/2 까지 |

행정 상한 60·소멸 10 은 수익 문턱이 아니라 추적 행정값이다. 결과를 보고 고른 값이 아니며, 바꾸려면 v2 로 등록한다.

## 2. 첫 실행 — 구조 수치만 (2026-08-28 ~ 10-06, 25 관측일)

| 항목 | 값 |
|---|---|

| 주 대조군 | 2개 315 · 1개 106 · 0개 0 (같은 테마 A 적격 비대장이 1개뿐인 테마) |

| `대조군→대장` 사건 | 504 |

| 등록 지문 | `d46326061392…` (t0 확정 필드 기준) |

### 구조에서 보이는 것 (해석은 탐색 — 결론 아님)

- **같은 테마 비대장의 절반 이상이 이미 대장이었던 종목이다.** 현행 대장 정의는 테마 안 상위 종목 사이에서 매일 바뀌기 때문이다
  (10/6 보고: 직전 관측일 대장 42 중 유지 6). '대장 vs 같은 테마 비대장' 비교는 사실상 **같은 대장 후보군 안의 교대** 비교가 된다.
- 그래서 주 대조군만으로 '대장 지위의 효과' 를 말하기 어렵다. 보조 대조군(그날 A 전체)·`primary_prior_episode` 표시로 나눠 볼 수 있게 남겼다. 정의는 바꾸지 않았다.
- 에피소드 정의가 '열린 에피소드가 없을 때만 시작' 이라, 60 관측일 안에 다시 대장이 되면 같은 에피소드다. `leader-firstday-v1` 의 '새 대장(직전 20 관측일 비대장)' 과 정의가 다르다 — 둘을 섞지 않는다.

## 3. 제안 — 연구 일봉 우선 구간 (사용자 확인 전에는 바꾸지 않음)

`hyeoks_research_daily.plan_order` 의 우선 구간을 지금의 '그날 유니버스(539)' 에서
**지수 + 미종결 에피소드 종목 + 그 주 대조군 + 오늘 보조 대조군**(10/6 기준 502종목, 그중 213 은 그날 A 밖)으로 바꾸는 안.

- 이점: 배지가 사라지거나 거래대금이 줄어 A 에서 빠진 대장·대조군도 우선 확보 — 분모가 사라지지 않는다.
- 현재 영향은 작다: 10/6 실행은 862 종목 전부를 12.5분(예산 20분)에 받았다. 우선 구간은 예산에 걸릴 때만 의미가 있다.
- 바꾸면 `hyeoks_research_daily.py`(지문 대상 아님)와 시험 수정. 등록부를 매일 그 실행 안에서 다시 계산한다(1~2초).
