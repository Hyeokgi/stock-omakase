## 3. 지킬 것

1. **연구 자료를 잃지 않는다** — 그날 Feature Store(약 750행)·순위 풀은 다시 만들 수 없다.
2. **15:05 규칙** — 그날 자료는 첫 적재 회차가 그 시각에 본 것이다. 뒤 회차의 관측으로 대신하지 않는다(운영대전제 §2·§4).
3. **판정 규칙을 완화하지 않는다** — 10/08 FAIL 분석에서 B안(판정 완화)을 버린 이유와 같다.
4. **아무것도 지어내지 않는다** — 되살리는 것은 원래 파일 그대로다.

## 5. 설계

### A. 증거 사본 — `main.yml` (지문 대상)

- ⑤ 바로 앞에 `if: always()` 단계를 둔다. ⑤ 가 커밋하려는 것과 **같은 파일**(`git status --porcelain --untracked-files=all` 로 본
  `data/receipts`·`data/feature_store`·`data/scanner_census` 의 변경분)만 모아 artifact `scanner-evidence-<run_id>` 로 올린다.
- 함께 넣는 것: 체크아웃 기준 SHA, 파일별 sha256 목록, 회차 시작 시각.
- 보존 14일. 변경분이 없으면(하루 대부분의 회차) 올리지 않는다.
- **경로를 위 세 폴더로만 한정한다.** 워크플로가 저장소 최상위에 `secret.json` 을 만들기 때문에, 폴더 지정 없이 올리면 안 된다.
- 공개 범위: 공개 저장소의 artifact 는 누구나 받을 수 있다. 올리는 파일은 같은 날 공개 저장소에 커밋되는 것과 똑같아서 노출이 늘지 않는다.

### B. 복구 도구 — 새 파일 `hyeoks_evidence_restore.py` + `evidence_restore.yml` (지문 대상 아님)

- 수동 실행(`workflow_dispatch`, 입력: 거래일·run_id). 사람이 FAIL 사유를 보고 실행한다.
- 확인(하나라도 어긋나면 **아무것도 쓰지 않고** 이유만 출력):
  영수증의 `cycle_date` = 입력 거래일 · `run_id` = artifact 의 회차 · `emitted_at` 이 그날 14:40~15:30 · sha256 일치 · 저장소에 같은 회차 영수증 없음.
- 되살리기:

| 파일 | 방법 |
|---|---|
| `data/feature_store/<날짜>.csv.gz` | 저장소에 없을 때만 원본 그대로 |
| `data/scanner_census/rank_pool.csv`·`envelope_census.csv` | artifact 의 기준 SHA 대비 **그 회차가 더한 줄만** 이어 붙인다. 이미 있는 줄은 건너뛴다 |
| 영수증 | 거래일 폴더가 아니라 `data/receipts/_restored/<날짜>/` 에 원본 그대로 → Evidence Builder 가 읽지 않는다(C) |
| 사건 기록 | `data/receipts/_incidents/<uuid>.json` — 스키마 `evidence-restored-v1`: 회차·artifact·sha256·복원 시각·사유·지시자 |

- 새로 계산하는 값은 없다. 종목명·종목코드를 로그에 찍지 않는다.

### C. 판정 처리 — 되살린 영수증은 판정에 쓰지 않는다 〔사용자 결정 사항〕

| 안 | 내용 | 평가 |
|---|---|---|
| **C-b (추천)** | 되살린 것은 연구 자료 보존용. 그날 판정은 그대로 FAIL | 판정 규칙 불변. 안정화 판정은 '보존까지 포함해 사람 손 없이 끝났는가' 를 본다 — 보존 실패도 불안정이다. 언제 되살려도 판정에 영향이 없다 |
| C-a | finalizer 가 판정 전에 자동으로 되살리고 판정에 쓴다 | 연속 기록을 지킬 수 있지만 판정 뜻이 '결국 자료가 남았는가' 로 바뀐다. `stability_finalizer.yml`·`stability_gate.py` 변경(지문 대상)이 필요하고, 다른 실패를 가릴 수 있다 |

## 6. 남는 위험

- **S1 은 되살릴 수 없다.** 증거가 파일로 쓰이기 전에 멈췄기 때문이다. 그날은 FAIL(`영수증없음`)이고 원장 행은 남는다. Feature Store·순위 풀은 그날 없다.
- artifact 업로드 자체가 실패하면 A 는 효과가 없다(⑤ 와 같이 실패할 확률은 낮다).

| C | — | A 와 함께 사용자 결정 |

## 8. 시험 계획

- B 단위 시험(가짜 artifact): 정상 복원 · run_id 불일치 거부 · 거래일 불일치 거부 · EOD 창 밖 거부 · sha256 불일치 거부 · 저장소에 이미 영수증이 있으면 거부 ·
  순위 풀 중복 줄 안 붙임 · 거래일 폴더에 쓰지 않음 · 사건 기록 생성 · 로그에 종목명 없음.
- A: 배포 뒤 첫 EOD 회차의 artifact 파일 sha256 = 같은 회차가 커밋한 파일 sha256 대조. 변경분 없는 회차는 artifact 가 없는지 확인. artifact 에 `secret.json` 이 없는지 확인.
