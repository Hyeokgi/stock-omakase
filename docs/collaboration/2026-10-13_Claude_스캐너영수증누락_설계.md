## 3. 지킬 것

1. **연구 자료를 잃지 않는다** — 그날 Feature Store(약 750행)·순위 풀은 다시 만들 수 없다.
2. **15:05 규칙** — 그날 자료는 첫 적재 회차가 그 시각에 본 것이다. 뒤 회차의 관측으로 대신하지 않는다(운영대전제 §2·§4).
3. **판정 규칙을 완화하지 않는다** — 10/08 FAIL 분석에서 B안(판정 완화)을 버린 이유와 같다.
4. **아무것도 지어내지 않는다** — 되살리는 것은 원래 파일 그대로다.

## 5. 설계

### A. 증거 사본 — `main.yml` + `.github/evidence_snapshot.py` (둘 다 지문 대상) · **브랜치 `fix/evidence-artifact` 에 구현**

- ⑤(커밋 단계) 바로 **앞에** 두 단계를 둔다. 커밋이 끝나면 변경분이 사라져 고를 수 없으므로 앞이어야 한다.

| 단계 | 내용 |
|---|---|
| 🧳 사본 준비 (`id: evidence`) | `python .github/evidence_snapshot.py --out "$RUNNER_TEMP/scanner-evidence"`. `if: always()` · **`continue-on-error: true`** · **`timeout-minutes: 1`** |
| 🧳 사본 올리기 | `actions/upload-artifact@v7`, 이름 `${{ steps.evidence.outputs.name }}`, 경로 `${{ runner.temp }}/scanner-evidence`, 보존 14일. 파일이 0개면 건너뛴다. `if: always()` · **`continue-on-error: true`** · **`timeout-minutes: 2`** |

- **비차단(Codex P2-5).** Evidence Builder 는 scanner 영수증의 run 결론으로 `no_unexplained_failure` 를 정한다(`evidence_builder.py:198~208`). 사본 단계가 실패해 run 이 실패하면 A 가 막으려던 FAIL 을 A 가 만든다. 그래서 두 단계 모두 `continue-on-error` 이고, 스크립트도 예외를 잡아 경고(`::warning::`)만 남기고 exit 0 이다. 상한 합계 3분 — 작업 상한 17분, 15:01 회차 실측 약 4분.
- **이름(Codex P2-6).** `scanner-evidence-<run_id>-<run_attempt>` — 재실행은 `run_id` 가 같아 `run_attempt` 를 붙인다.
- **고르는 파일(Codex P2-6, 재검토).** `git status --porcelain=v1 -z --untracked-files=all -- data/receipts data/feature_store data/scanner_census` 의 변경 항목 중 **일반 파일만** 복사한다. 경로를 고쳐 쓰지 않는다 — 역슬래시·빈·`.`·`..` 구성요소가 있으면 '비표준 경로' 로 거부하고, **검사한 경로 그대로** 복사한다. 숨김 이름은 경로의 **어느 구성요소**에 있어도 거부한다(upload-artifact 가 숨김 폴더 안 파일을 빼므로). 경로 중간의 링크도 거부한다. 임시(`.tmp` 등)·세 폴더 밖 경로도 복사하지 않고 manifest `rejected` 에 사유와 남긴다. 삭제 항목은 `deleted` 에 이름만. 폴더를 통째로 올리지 않는다 — 워크플로가 최상위에 만드는 `secret.json` 은 경로상 들어올 수 없다(시험이 확인).
- **사본 폴더**는 저장소 밖이어야 한다(안이거나 저장소를 품으면 거부). 앞 실행 사본은 소유 표식(`.scanner-evidence-owner`, 숨김이라 artifact 에 안 올라감)이 있을 때만 지운다.
- **manifest(`scanner-evidence-v1`) — B 가 읽을 형식(Codex: B 보다 먼저 확정).**

| 키 | 뜻 |
|---|---|
| `schema` · `name` | `scanner-evidence-v1` · artifact 이름 |
| `repository` · `workflow` · `run_id` · `run_attempt` · `sha` · `ref` · `event` | GitHub 실행 식별(환경 변수 그대로). `sha` 는 체크아웃 기준 커밋 |
| `head` | 사본을 만든 순간의 `HEAD` — B 가 '기존 줄이 바뀌지 않았다' 를 대조할 기준 |
| `created_at` | 사본 시각(KST). **15:05 관측의 인증이 아니다**(Codex P2-4) |
| `files[]` | `path` · `status`(git 두 글자 그대로 — `" M"`·`"??"`·`"R "` …) · `bytes` · `sha256` |
| `rejected[]` · `deleted[]` | 복사하지 않은 항목과 사유 · 삭제된 경로 |

- **부분 묶음(Codex P2-4).** census 기록은 진입 적재보다 앞이고 창이 14:40~15:10 이라, 14:41·14:51 회차는 **영수증 없이 census 만** 담은 사본을 정상적으로 만든다. Feature Store 저장 뒤 영수증 발행이 실패한 회차도 영수증 없는 묶음이 된다. A 는 이런 묶음도 그대로 올린다 — 복구 여부는 B 가 정한다.
- 공개 범위(Codex P3-7). 공개 저장소의 artifact 는 GitHub 문서상 받으려면 로그인과 저장소 읽기 권한이 필요하다(직접 확인 안 함). 그래도 **사실상 공개 자료로 취급한다** — 올리는 파일은 같은 날 공개 저장소에 커밋되는 것과 같다.
- 크기(Codex P3-7). 누적 CSV 는 변경되면 파일 **전체**가 올라간다. 지금은 `rank_pool.csv` 28KB·`envelope_census.csv` 2.5KB·Feature Store 하루 약 75KB 라 회차당 100KB 안팎이지만, 누적 CSV 가 커지는 만큼 커진다.

### P1-1. 정렬·건수 되읽기 예외 감싸기 — `omakase.py` (지문 대상) · **같은 브랜치에 구현**

- `sort_and_format_backtest_log(doc, bt_sheet)` 호출을 국소 `try` 로 감싼다. 실패하면 경고만 찍고 이어 간다. 정렬·서식은 보기용이고, 뒤의 Feature Store·순위 풀·영수증은 메모리의 적재 결과(`new_rows`·`results`·`_pool_plan`)를 쓰므로 정렬 실패와 무관하다.
- `rank_pool.recorded_count(...)` 호출도 국소 `try` 로 감싼다. 실패하면 `TELEMETRY.note('pool_row', …, OBSERVE)` 를 남겨(기존 '순위 풀 기록 실패' 와 같은 키·등급) 영수증의 `expected_state` 가 `degraded` 로 정직하게 표시되고, 영수증 발행은 계속한다.
- 함수 자체(`sort_and_format_backtest_log` 의 첫 조회)는 바꾸지 않는다 — 호출부에서 막는 것이 범위가 가장 작다.

### B. 복구 도구 — 새 파일 `hyeoks_evidence_restore.py` + `evidence_restore.yml` (지문 대상 아님) · 구현 전

- 수동 실행(`workflow_dispatch`, 입력: 거래일·artifact 이름). 사람이 FAIL 사유를 보고 실행한다.
- **원칙 — 전부 확인한 뒤 한 번에 쓴다.** 하나라도 어긋나면 **아무것도 쓰지 않고** 이유만 출력한다. 모두 맞으면 한 커밋으로 공개하고, push 가 원격 충돌로 거절되면 fetch 뒤 **처음부터 다시 검증**한다.

**① 출처 — 묶음 전체(Codex P1-2)**

| 확인 | 내용 |
|---|---|
| 실행 | GitHub API 로 run 을 조회해 `repository`·워크플로 파일(`main.yml`)·`run_id`·`run_attempt`·`head_sha`(= manifest `sha`)·`event` 가 manifest 와 같고, artifact 가 **그 run 의 것**이며 이름이 manifest `name` 과 같다 |
| 파일 | artifact 안 파일 = manifest `files[]` 정확히(빠짐·남는 파일 없음), 각 sha256 일치, 세 폴더 안 일반 파일 |
| 영수증 자체 | 묶음에 scanner 영수증이 있으면 그 `cycle_date` = 입력 거래일, `run_id` = manifest `run_id`, `kind` = `scanner`, `fingerprint` 를 기록한다(첫 설계의 조건 — 개정 때 빠진 것을 Codex 10/13 재검토 지적으로 되살림) |
| 행 | Feature Store 행의 날짜·run_id, 순위 풀 **추가 행**의 날짜·run_id, census **추가 행**의 날짜가 입력 거래일·이 run 과 같다. 헤더(스키마)가 저장소 현재 헤더와 같다 |
| 기준 불변 | 누적 CSV 사본 = (manifest `head` 시점 저장소 파일) + 뒤에 붙은 줄뿐이다 — 기존 줄의 수정·삭제가 없다 |

**③ 부분 묶음(Codex P2-4)** — 영수증이 없는 묶음(14:41·14:51 의 census 만, 또는 Feature Store 뒤 영수증 발행 실패)도 ①②를 같은 기준으로 통과하면 그 파일들만 되살린다. 영수증을 만들어 내지 않는다. 기본은 **보관만**이고, 되살리기는 실행자가 입력으로 명시할 때만 한다.

**④ 시각** — `created_at`·`emitted_at` 은 기록할 뿐 15:05 관측의 인증으로 쓰지 않는다(진입 창은 15:00~15:30, `omakase.py:3283`).
