# 봉인 사본 감시 — 만료 전 복원 알림 (2026-11-01, PC Claude)

## 왜
사용자 요청으로 Codex(GPT-6-Astra high)와 Gemini(Gemini 4 Argon High)가 전략 전체를 읽기 전용으로 평가했다(PC 허브 `work\전략평가_2026-10-31\`, 레포 밖). 우선순위 3 이 비공개 보관이고, 사용자가 진행하라고 했다("3번 진행해").

두 모델이 같은 지점을 짚었고 PC Claude 가 코드로 확인했다.
- `private_store.preserved()` 는 봉인 사본(`암호사본`)도 보존으로 친다(`private_store.py` 68~72행). 판정(`evidence_builder.private_preserved`)도 그 값을 쓴다.
- 봉인 사본은 artifact 라 14일 뒤 사라진다. PC 에서 `--restore` 를 하지 않으면 원본을 잃는데, 이를 알려 주는 장치가 없었다.
- artifact 올리기 단계는 `continue-on-error` 라 색인에는 `암호사본` 인데 원격에는 없을 수 있다(Codex).

2026-11-01 기준 색인 66행이 모두 `접수` 다. 봉인 사본이 생긴 날은 아직 없다.

## 무엇
| 곳 | 변경 |
|---|---|
| `private_sealed_watch.py` (새) | 공개 색인에서 `암호사본` 인데 같은 (종류 · 날짜 · 채널)의 `접수` 가 없는 행을 회차별로 모은다. 그 회차의 `private-fallback-<run_id>-*` artifact 가 실제로 있는지, 언제 만료되는지 GitHub API 로 본다. 남은 것이 있으면 작업 요약에 표와 PC 복원 명령(`gh run download … -n <artifact>` → `python private_store.py --restore …` → 색인 커밋)을 적고 종료 1로 끝난다. artifact 가 없거나 만료됐으면 '원본 잃음' 으로 적는다. 봉인 뒤 21일(14일 + 유예 7일)이 지나면 표에만 남기고 실패로 치지 않는다. 조회 실패도 실패로 띄운다 |
| `.github/workflows/private_sealed_watch.yml` (새) | 평일 19:00 KST(`0 10 * * 1-5`)와 수동 실행. 권한은 `contents: read` · `actions: read`, 비밀값은 쓰지 않는다 |
| `tests/test_private_sealed_watch_20261101.py` (새) | 미복원 판별 · artifact 있음/없음/만료/조회 실패 · 복원 명령 · 깨끗한 색인 통과 · 실제 색인 읽기 |

알림 위치는 **깃허브 실패 표시만** 쓴다(사용자 결정 2026-11-01). 지인과 같이 보는 텔레그램 채널에는 운영 메시지를 섞지 않는다.

## 하지 않은 것
- 지문 대상인 `private_store.py` · `evidence_builder.py` · `main.yml` 은 바꾸지 않았다(`FINGERPRINT_FILES` 직접 조회, 37개). 봉인 사본을 판정에서 보존으로 치는 규칙도 그대로다. 그 규칙을 바꾸려면 지문 변경과 사용자 승인이 필요하다.
- 복원은 자동으로 하지 않는다. 키(`PRIVATE_STORE_KEY`)가 있는 PC 에서 사람이 한다.
- 영구 보관(14일보다 긴 곳으로 옮기기)은 이번 범위 밖이다.

## 확인
- 새 시험 8건과 `test_private_sealed_20261025` · `test_ci_wiring` 을 합쳐 23건 통과(로컬).
- 전체 1,302건 중 실패 17건은 main 에서도 나는 윈도우 환경 실패와 같다. 새 실패는 없다.
- 실제 색인으로 실행하면 '복원할 봉인 사본 없음' 이 나오고 종료 0이다.
- artifact API 의 응답 모양(`name` · `expired` · `expires_at`)은 2026-11-01 실제 응답으로 확인했다.
- 실제 봉인 사본에 대한 실행과 깃허브 실패 메일 도착은 아직 보지 못했다(봉인 사본이 생긴 적 없음).
