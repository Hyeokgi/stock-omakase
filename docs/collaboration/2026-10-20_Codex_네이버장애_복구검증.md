## 실제 원인

원 경고 [run 39205180490](https://github.com/Hyeokgi/stock-omakase/actions/runs/39205180490)는 구성종목 조회 실패와 컨센서스 timeout을 함께 보고했다. 두 원인은 구분한다.

1. 구성 조회의 실제 HTTP 400 본문은 `marketType=ALL`이 허용되지 않는다는 `invalid_enum_value`였다. 오류 문장의 `/api/dom`은 잘린 URL이며 잘못된 기본 URL이라는 증거가 아니다.
2. 해당 인수를 빼는 것만으로는 부족했다. 응답이 배열에서 `items/hasNext/cursor`로, 종목키가 `itemCode`로, 시세가 `krx` 하위로 바뀌었다. 기존 `pageSize/startIdx` 대신 `size/cursor`로 끝까지 읽어야 했다.
3. 컨센서스 10/19 실행은 성공 108종목·실패 52종목이었다. 실패 중 timeout 47·SSL EOF 4·기준일 없음 1이었다. 추정치 없음 14건은 실패와 별도다. 저장 285행을 성공 종목 수로 해석하지 않는다. 원천 전체가 중단됐다는 결론은 아니다.

## 변경 범위

- `naver_membership.py`를 구성 조회 공통 경로로 만들었다. 테마·업종·그룹 전체 커서를 읽고 HTTP/스키마/중복코드/커서 중단은 실패로 반환한다. 부분 목록을 완성본처럼 반환하지 않는다.
- 스캐너는 KRX 시세와 원→백만원 변환을 사용한다. NXT나 미확인 값을 0으로 대신하지 않는다. 기존 선정 문턱·대장 규칙은 바꾸지 않았다.
- 구성 조회 실패·부분 성공과 정상 조회 뒤 후보 0건을 구분한다. `theme_source` 상태와 `theme_membership` CRITICAL 계측을 영수증에 남겨 기존 Gate 경로가 확인한다. Gate 기준 7개 자체는 바꾸지 않았다.
- 실패 시 기존 테마 시트 행을 지우거나 오늘 자료로 덮어쓰지 않는다. `수급_실시간!A1` 메모에 최신 확인 불가·이전 관측임을 기록하도록 했다. 메모 기록 실패는 경고로 남긴다. 이번 점검에서 실제 시트를 직접 쓰지는 않았다.
- 스냅샷은 가격을 계속 저장하되 구성 상태·실패 사유를 별도로 보존한다. 업종·그룹 불완전 집계는 0이 아니라 빈칸이다. 요약도 불완전 순위·0억 표시를 보류한다.
- 파일 존재 감시는 구성 연결 0과 명시적 실패도 탐지한다. 대장 유지·v2·첫날 연구 입력에서 미확인 구성을 정상 무테마/비대장으로 쓰지 않도록 했다.
- 첫날 연구는 구성 미확인일이 최근 20관측일 이력에 있으면 “처음 대장” 여부도 보류한다. **가격 관측일 자체를 삭제하지 않으며, 3관측일의 시간축을 압축하지 않는다.** 유효 표본이 늦게 쌓일 수 있다.
- 컨센서스는 timeout·SSL EOF·연결 리셋·일부 5xx만 1초 후 1회 재시도한다. 400/403/429·스키마·인증서 오류는 재시도하지 않는다. 55분 수집 예산과 실패 상태를 유지하고 대상/실제 시도/추정치 없음/실패/미처리 수를 구분한다. 각 요청 timeout은 전체 실행시간 상한을 보장하지 않는다.
