## 2. 반영 (연구 파일만, 생산 코드 무변경)

| Codex | 고친 방식 | 시험 |
|---|---|---|
| **R7** 우선 구간 반복 누락 | 지수는 맨 앞 고정, 우선 종목도 `resume.json.priorityOffset` 으로 회전. 우선 구간 안에서 멈추면 다음 실행이 그 자리부터. 종목 요청 시간 평균·p95·최대(ms)를 공개 요약에 남긴다 — 첫날 실측으로 예산(20분)을 판단 | 같은 예산 두 번 → `[000001, 000002]` |

| **R9** 원본 참조·영수증 부족 | 모든 유효 관측(동일 포함)이 **같은 내용 지문이 마지막으로 보관된 파일**을 가리킨다. 공개 `private_receipts.csv`(두 수집 공통): 시각·종류·실행·파일명·바이트·**sha256**·드라이브 id·상태(`접수`/`실패`)·`verified`(원격 재다운로드 대조 — 비워 두고 첫 생산 파일을 수동 대조) | 동일 3행 같은 원본 / sha256 = 업로드 바이트 |
| **R10** 백업 중복·대기 실행의 오래된 checkout | stockinfo7 실행 결과를 공개 `stockinfo7_runs.csv` 에 `완료 / 보류 / 부분 / 실패` 로 남기고, 다른 실행이 그날 `완료`·`보류` 면 백업은 생략, `부분`·`실패` 면 남은 시간을 관측. 두 워크플로 모두 실행 전 `git pull --ff-only origin main` 으로 **최신 상태**를 읽고 `RESEARCH_STATE_COMMIT`(읽은 상태 커밋)을 남긴다(코드 커밋은 `GITHUB_SHA`) | 부분 → 이어 관측, 완료 → 생략 |
| **R11** 보고만 실패하면 백업이 재시도 안 함 | 보고 결과를 공개 `report_log.csv` 에 `발송성공 / 발송실패 / 응답불명` 으로 남기고 별도 커밋 단계 추가. 백업은 수집을 반복하지 않고 **보고만** 다시 보낸다. `응답불명`(읽기 시간 초과 등 — 갔을 수도 있음)은 중복을 피하려고 자동 재발송하지 않는다. 연결 실패(`ConnectionError`·`ConnectTimeout`)·HTTP 오류·토큰 없음은 `발송실패` = 재시도 | 보고만 재발송 1회 / 응답불명 재발송 0 |
| ⑤ 중단 규칙 | HTTP 401·403·429 또는 로그인 요구 화면이면 **우회하지 않고 그날 수집을 멈춘다**(`보류`) | 403·429 → 1회 관측 후 정지 |

Codex `verify_review.py` 를 새 코드에 돌리면 R7·R8·R9 는 결함 단언이 실패한다(= 고쳐짐).
R10 은 그 스크립트가 `collect` 를 최소 dict 로 바꿔 끼워 원래 코드에서 KeyError 가 났다 → `run_status` 를 빠진 키에 견디게 고쳤다. 실제 경로는 실행 기록 파일로 판정한다(위 시험).
R11 은 그 스크립트의 발송 오류(`synthetic`)가 HTTP·연결 오류가 아니어서 `응답불명` 으로 분류되고, 설계대로 자동 재발송하지 않는다.

## 3. 사전 고정 — stockinfo7 의 15:05 정렬 규칙 (10/6 첫 실측 **전**에 정함)

Codex ③ 을 그대로 채택한다. 결과를 본 뒤 바꾸지 않는다.

- **주 분석 화면** = 그날 날짜의 **15시 기준 화면** 중 **15:05:00 까지 수신·파싱이 끝난 가장 최근 관측**. 없으면 **결측**.
- 14시본은 별도 '오래된 자료' 비교용으로만 남긴다. 15시본 빈칸에 대신 넣지 않는다.
- 15:05 뒤에 받은 15시본은 헤더가 15시라도 그날 판단에 소급 사용하지 않는다(보고에 '15시본 첫 확보 시각' 으로만 표시).
- 화면 날짜가 그날이 아니면 오늘 비교에서 뺀다.
- 운영 기준 15:05 는 유지. 10분 간격이라 갱신 시점은 '앞 관측 ~ 첫 갱신 관측' 구간으로만 안다. 관측 빈도는 실측을 보고 필요할 때만 바꾼다.

## 4. 다음 — 에피소드 등록부 (10/7~10/8, Codex ②·④ 채택)

- 핵심 추적 대상: 오늘 신규 후보 + 미종결 에피소드 종목 + 최초 고정 대조군 + 기준 지수. 생기면 R7 우선 구간을 이것으로 바꾼다.
- 주 대조군 = 같은 날 같은 테마의 적격 비대장 종목(사전에 제한된 유사성 규칙). 보조 대조군 = 그날 A 에서 같은 적격 조건, 고정 시드·코드 정렬 기록.
- 대조군이 나중에 대장이 돼도 교체·삭제하지 않고 사건으로 표시. 여러 테마 중복 종목은 독립 표본으로 반복 세지 않는다.
- 상태: 진행 중·관측 결측·종료·상한 도달. 배지 소실만으로 종료하지 않는다. 행정 상한은 시작 전에 정하고 10일·10% 를 수익 문턱으로 고정하지 않는다. 상한 미종결은 우측 검열.
- 당시 상태표와 이후 결과표 분리. **탐색은 결과에 쓰는 가격 날짜도 10/2 까지**. 경로 이름은 가격 계열 확인 후에만, 한 봉에서 상·하 기준을 모두 건드리면 미확정.
- 네이버와 stockinfo7 은 다른 출처로 병행 보존하고 하나로 합치지 않는다. stockinfo7 에 안 나온 종목을 테마 비구성원으로 단정하지 않는다.
