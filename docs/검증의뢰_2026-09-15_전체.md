## 2. A — 승인 게이트 선행 수정 (P0-1 · P0-3 · P1-2)

커밋 `98ceeb1` · `1fa817c`

### P0-1 재표본 길이 — 방향이 나쁜 결함이었다

```python
# 전
m = tot / (nb * block)          # nb = ceil(n/block) → 재표본이 원표본보다 길다
# 후
tail = n - (nb - 1) * block     # 마지막 블록만 자른다
m = tot / n
```

**왜 급한가** — 길게 평균내면 귀무분포가 **좁아지고** p가 **과소평가**된다.
즉 **승인이 쉬워지는 방향**이다. 크기는 현재 작지만(44→45, 1.02배)
작다는 것은 고치지 않을 이유가 아니라 **지금 고쳐도 기존 관측이 안 흔들린다**는 뜻이다.

**난수 소비를 바꾸지 않았다.** `rng.randrange` 호출은 그대로 `nb` 회라
`n % block == 0` 이면 **비트 단위로 같은 값**이 나온다. 테스트로 걸었다.

### P0-3 α 주입 — 호출부는 일부러 안 바꿨다

`holm(pairs, m=None, alpha=0.05)`. **기본값 0.05는 동작 보존용이지 트랙 C의 정답이 아니다.**
호출부(`hyeoks_verdict.py:1090`)에 0.0125를 지금 넣으면 **U 항목 하나를 코드로 선확정**하는
것이 되므로 하지 않고 경고 주석만 달았다. `passed = set()` 이라 운영 승인으로 새지 않는다.

### P1-2 과잉진단 — 그리고 보고서 자신의 오기

`scanner_census.py` 머리말이 *"엔벨로프(-20%) 통과 0"* 이라 적어 **이격률을 범인으로 단정**했다.

### F. 가동 감시 — 만들자마자 자기 결함을 잡았다

**목표:** 수집이 GitHub 밖이라 주말에 PC가 꺼지면 조용히 건너뛰고,
**"수집 실패"와 "이번 주 발간 없음"이 구분되지 않는다.**

**방법:** 파일명의 `source_id`(하나증권 `pid_bbsSeq_attachFileSeq`)로
**원천 목록 ∩ Drive ∩ 시트**를 대조. 원천 조회는 자격증명이 필요 없다.
수집은 토·일에만 도니 **직전 예정 수집 시각 이전 발간분만** '수집 대상'으로 센다(유예).

**첫 실행이 🔴 수집지연 1건을 냈다. 경보를 끄지 않고 manifest를 읽었다:**

```json
"source_id": "2220_1288680_1",
"sha256": "3e38e58bfea2…",        ← 2220_1288679_1 과 동일
"drive_id": "1kt6nmGpU5Bog…",      ← 1288679 와 같은 파일
"duplicate_of": "2220_1288679_1"
```

하나증권이 같은 리포트를 9/06 **20:28과 20:39에 두 번 게시**했고 SHA256이 같아
Drive엔 하나만 보관됐다. **수집은 정상이었고 내 감시가 오탐이었다.**
`duplicate_of` 를 읽도록 고쳤고, **그 오탐을 데이터로 재현하는 테스트**를 박았다.
재실행 → 미수집 0, 중복 제외 1, **미분석 4는 그대로**(진짜 신호는 안 지웠다).
