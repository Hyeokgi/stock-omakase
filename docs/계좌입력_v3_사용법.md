# 계좌 입력 v3 — 2026-09-09

v2의 가격/현금 계산은 유지하고 테마 제약과 입력 근거를 분리했다. 이 문서는 v2 사용법 중
테마 필수 조건과 신규 workflow 입력 규약을 대체한다. v2 직접 실행은 호환되지만 결과에
검증 근거 미확인 경고가 붙으며 진단용이다. 신규 수동 workflow는 v3 검증을 반드시 거친다.

## 테마 정책

| theme_policy | 용도 | 필수 정보 |
|---|---|---|
| none | 현금·종목 한도 기본 계좌, 테마 제약 미적용 | theme_map 생략 가능. 테마 최대 노출은 null(모름), 0이 아님 |
| representative | 당시 대표 테마에 한정한 제약 | 종목당 ID 1개와 theme_quality 상태 representative 또는 complete, 당시 출처 |
| complete | 전체 소속에 대한 제약 | 모든 당시 ID와 상태 complete, 출처. 부분/미확인은 거부 |

`theme_quality = {신호일: {종목코드: {status, source}}}`.
확인 결과 소속이 없는 경우만 status=`verified_none`, ID=`NO_THEME:종목코드`를 사용한다.
unknown/partial은 소속 없음과 다르다. representative 모드에서 모르는 행을 개별 테마로
위장하거나 미래 소속으로 채우지 않는다. 대표 테마를 모르면 기본 none 모드로 별도 계산한다.
테마 제한 모드에 따라 승인 주문이 달라지므로 수익률·MDD 차이를 상한·하한이라고 부르지 않는다.

## v3 추가 필드

- schema: `account-input-v3`
- theme_policy: 위 세 값 중 하나, 생략 불가
- calendar_verification: `{status: "verified", evidence: "검증 자료 참조/해시", sessions: [...]}`
- price_verification: `{status: "verified", evidence: "조정기준·기업행사 대조 자료 참조/해시"}`

calendar_verification.sessions는 분석 시작일부터 as_of까지 독립 기준 자료로 확인한 거래일이다.
주 sessions의 as_of까지 부분과 정확히 일치해야 한다. 요청한 시작일 이전/기준일 이후의
자료를 조용히 잘라 정합성을 꾸미지 않는다. API의 최근 20일만 받아 전체 기간이라고 하지 않는다.
코드가 evidence 문자열과 일치를 확인한다고 그 자료의 진위를 인증하는 것은 아니다.
검증 담당자는 실제 근거 자료를 함께 비공개 보존해야 한다. 원래 목록을 복사해 검증했다고 하지 않는다.

price_basis는 여전히 consistent_adjusted_ohlc만 지원한다. 조정 기준을 모르면 unverified로
표시하고 실행을 중단한다. 당시 원시 가격＋실제 분할/배당 현금흐름은 미구현이다.
수정주가 정수 수량은 실제 매수 가능 수량과 달라질 수 있으며 실계좌 체결 모형이 아니다.
tradable은 거래 가능 상태 자료로 확인해야 한다. 가격이 양수이거나 거래량이 0이라는 사실만으로
정상 거래/거래정지를 임의 판정하지 않는다. 상장폐지·거래정지 종목을 사후 삭제하지 않는다.

## 입력 빌더 실행

`python account_input_builder.py --source PRIVATE_SOURCE.json --output-dir data/account_private`

원장 rows와 달력·OHLC·상태·출처를 합친 **준비된 JSON**을 입력받는 오프라인 빌더다.
현재 빌더는 시트/네이버에서 자동 수집하지 않는다. 기존 수집기의 짧은 기간 캐시,
인증서 검증 해제, 오류 행 생략을 그대로 재사용하지 않기 위해 자동 수집은 연결하지 않았다.
실제 공급자별 수집 어댑터와 조정 기준 검증은 별도 남은 작업이다.

실행마다 새 input-* 폴더에 quality.json을 남긴다. 원장 물리 행 수는 승인/거절 주문,
명시 제외·지수 행·진입 대기 및 빈 행으로 대사한다. 실패하면 입력 파일을 내보내지 않고
종료 코드 2를 반환한다. 원본 오류 상세는 비공개 quality.json에만 기록하며 표준 출력에는 숨긴다.
성공하면 input.json을 별도 쓰고 전체 SHA256을 읽어 확인한다. 이를 계좌 계산에 전달한다.

`python hyeoks_account.py --input data/account_private/input-RUN/input.json`

quality와 원본은 로컬에서 비공개 보존한다. 성공한 workflow의 계좌 증거 ZIP에는 검증된 입력과
계산 결과가 보존되지만 입력 준비의 quality.json은 별도 원격 업로드되지 않는다. 실패한 Actions의
임시 파일은 지속 보존되지 않으므로 첫 입력 검증은 로컬에서 진행한다. 업로드/공유권한 자동 변경은 없다.

## 연구 관리

Q5는 기존 연구의 주 검정으로 유지한다. 테마 대장 연구는 별도 탐색 연구이며 새 가설 묶음,
비용·체결 기준·검증 구간·재현·오류율 관리가 확정되기 전 채택하지 않는다. 동일 미래 날짜의
공동 검증이 원천 금지는 아니지만 같은 날짜의 두 분석을 독립 재현이라고 부를 수 없다.
10/5 종베 자료 점검 방침과 기존 수급 채널 강제조항은 변경하지 않았다.
