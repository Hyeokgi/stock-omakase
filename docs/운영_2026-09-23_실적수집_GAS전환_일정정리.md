# 실적 수집을 GAS 발사로 옮긴다 · 주요일정 중복 정리 (2026-09-23)

## 1. 실적 수집 — GitHub cron 은 한 번도 제시간에 돌지 않았다

`earnings_collector.yml` 의 `cron: '0 11 * * *'`(20:00 KST) 최근 8회:

| 회차 | 실제 기동(KST) | 지연 | 결과 |
|---|---|---|---|
| #71 | 9/16 00:25 | 4h25m | 실패 |
| #72 | 9/17 00:18 | 4h18m | 실패 |
| #73 | 9/18 00:25 | 4h25m | 실패 |
| #74 | 9/18 23:45 | 3h45m | 성공 |
| #75 | 9/19 23:08 | 3h08m | 성공 |
| #76 | 9/20 23:27 | 3h27m | 성공 |
| #77 | 9/22 01:46 | 5h46m | 거부(`_incidents` 도입 전) |
| #78 | 9/23 00:24 | 4h24m | 거부 → `_incidents` 기록 |

8번 중 5번이 자정을 넘겼다. 자정을 넘기면 거래일이 모호해 수집기가 거부하고(설계대로),
그날은 `earnings_schema_ok`·`dart_complete` 가 비어 Gate 에서 탈락한다.
**이 상태로는 3거래일 연속 통과가 사실상 불가능하다.** 코드가 아니라 발사 시각의 문제다.

### 결정 (사용자, 2026-09-23): GAS 가 쏜다

이 저장소는 이미 그렇게 하고 있다. `main.yml`·`ai_report.yml`·`market_snapshot.yml` 은
GAS(`매크로.gs`)가 `workflow_dispatch` 로 쏜다. 스크레이퍼 발사 시각은 10분마다
`xx:x1:28` 로 **±2초** 다. 같은 방식으로 실적·컨센서스를 쏘면 된다.

### 저장소는 지금 바꾸지 않는다

`earnings_collector.yml` 은 지문 대상이다. 지금 cron 을 지우면 지문이 바뀌고,
오늘 14:40 이후에 바꾸면 9/23 영수증이 전부 무효가 된다.
**GAS 트리거만 추가하면 저장소 변경 없이 된다** — 워크플로에 `workflow_dispatch` 가 이미 있다.

기존 cron 은 3거래일 판정까지 그대로 둔다. 그 동안의 동작:

- GAS 가 20:40 에 쏜다 → 제시간 수집 → 그날 영수증 발행
- cron 이 자정 **이후**에 도착 → 거부, 빨간 실행 + `_incidents` 한 건. **영수증이 없으므로
  Gate 는 그 실행을 보지 않는다**(`workflow_states` 는 영수증의 `run_id` 만 조회한다)
- cron 이 자정 **이전**에 도착 → 두 번째 수집. 시트는 읽고-병합-쓰기라 중복 행은 안 생긴다.
  다만 그 영수증이 그날의 "마지막 것" 이 된다. 그 실행이 망가지면 GAS 실행의 좋은 결과를
  덮는다. 지금까지 자정 전 도착분은 모두 성공했다(#74~#76)

판정 뒤 할 일(백로그): cron 을 지워 매일 밤 빨간 실행과 이중 수집을 없앤다.

### `cycle_date` 는 넘기지 않는다

GAS 가 20시에 쏘면 수집기가 스스로 오늘을 거래일로 정한다. 명시 날짜를 넘기면
GitHub 쪽에서 몇 시간 밀려도 그날로 붙는데, 그건 "새 자료를 과거 거래일 자료로 소급
취급하지 않는다" 는 원칙과 부딪힌다. 늦으면 자정 가드가 거부하도록 그대로 둔다.

### GAS 코드 (사용자가 준 `매크로.gs` v6.2 에 맞춤 — 2026-09-23 갱신)

처음 이 문서에 적은 코드는 토큰 속성을 `GITHUB_TOKEN` 으로 가정했다. 실제는
`GITHUB_MASTER_TOKEN` 이고 파일 상단에서 전역으로 읽는다. 아래가 실제 파일에 맞춘 판이다.
**파일 맨 끝에 붙이는 추가 블록**이고 기존 함수는 바꾸지 않는다.

```javascript
// -------------------------------------------------------------
// 📊 [2026-09-23 신규] 실적 PRIMARY · 컨센서스 AUX 수집 발사
//    깃허브 cron(20:00)은 최근 8회 전부 3~6시간 늦었고, 그중 5회는 자정을 넘겨 거부됐다.
//    (자정을 넘기면 거래일이 모호해서 수집기가 스스로 거부한다 — 설계된 동작)
//    스캐너·스냅샷처럼 GAS 가 쏜다. 기존 cron 은 3거래일 판정까지 늦은 백업으로 남는다.
//
//    ⚠️ cycle_date 는 넘기지 않는다. 제시간에 돌면 수집기가 오늘을 거래일로 정하고,
//       어쩌다 늦으면 자정 가드가 거부한다. 날짜를 넘기면 늦은 수집이 과거 거래일에 붙는다.
//    ⚠️ 20:05 AI 리포트(시간외 브리핑, 최대 6분)와 겹치지 않게 20:40 / 21:20 에 쏜다.
// -------------------------------------------------------------
function triggerEarningsCollector(e) { dispatchCollector_(e, "earnings_collector.yml"); }
function triggerConsensusAux(e)      { dispatchCollector_(e, "consensus_aux.yml"); }

function dispatchCollector_(e, file) {
  // 🛡️ 주말 방어막 (다른 트리거들과 같은 규칙 — 수동 실행은 통과)
  if (e && (new Date().getDay() === 0 || new Date().getDay() === 6)) return;
  if (!GITHUB_MASTER_TOKEN) throw new Error("GITHUB_MASTER_TOKEN 스크립트 속성이 비어 있다");

  var url = "https://api.github.com/repos/" + GITHUB_OWNER + "/" + GITHUB_REPO
          + "/actions/workflows/" + file + "/dispatches";
  var res = UrlFetchApp.fetch(url, {
    "method": "post",
    "contentType": "application/json",
    "headers": {
      "Authorization": "Bearer " + GITHUB_MASTER_TOKEN,
      "Accept": "application/vnd.github.v3+json"
    },
    "payload": JSON.stringify({ "ref": "main" }),
    "muteHttpExceptions": true
  });
  var code = res.getResponseCode();
  // ⚠️ 실패를 삼키지 않는다 — 예외를 던져야 GAS 가 트리거 실패 메일을 보낸다.
  //    (스냅샷 함수처럼 로그만 남기면 발사 실패가 조용히 묻힌다)
  if (code !== 204) {
    throw new Error("📊 " + file + " 발사 실패 HTTP " + code + ": " + res.getContentText().slice(0, 200));
  }
  Logger.log("📊 " + file + " dispatch 완료");
}

// 🧪 연결 시험용 — 시트를 건드리지 않는 FRED 점검 워크플로를 쏜다(텔레그램 발송도 없음).
//    실적 함수로 시험하지 말 것: 그건 DB_실적 에 실제로 쓰는 생산 실행이다.
function testDispatchSafe() { dispatchCollector_(null, "fred_check.yml"); }

// ⏰ 실적·컨센서스 트리거만 설치한다. 이 두 함수의 기존 트리거만 지우고 다시 만든다.
//    다른 트리거는 건드리지 않는다 — 여러 번 눌러도 중복되지 않는다.
function setupCollectorAlarms() {
  var handlers = ["triggerEarningsCollector", "triggerConsensusAux"];
  ScriptApp.getProjectTriggers().forEach(function (t) {
    if (handlers.indexOf(t.getHandlerFunction()) !== -1) ScriptApp.deleteTrigger(t);
  });
  ScriptApp.newTrigger("triggerEarningsCollector").timeBased().everyDays(1).atHour(20).nearMinute(40).create();
  ScriptApp.newTrigger("triggerConsensusAux").timeBased().everyDays(1).atHour(21).nearMinute(20).create();
  SpreadsheetApp.getActiveSpreadsheet().toast("✅ 실적 20:40 · 컨센서스 21:20 트리거 설치", "HYEOKS 시스템");
}
```

GAS 모의 실행으로 확인한 것: 세 워크플로 경로와 `{"ref":"main"}` 본문, 설치 함수가
자기 두 트리거만 지우고 다른 트리거는 남기는 것, HTTP 204 가 아니면 예외를 던지는 것.

### 발사 시각

| 트리거 | 시각(±15분) | 이유 |
|---|---|---|
| `triggerAiReport` (기존) | 20:05 | 시간외 브리핑. 최근 5회 소요 0~6분, 20:14 이전 종료 |
| `triggerEarningsCollector` | **20:40** | AI 리포트와 겹치지 않게. 자정까지 3시간 이상 |
| `triggerConsensusAux` | **21:20** | 실적과 40분 간격(기존 cron 간격과 같다). 락은 서로 다르다 |

주말은 다른 GAS 트리거와 같은 규칙으로 건너뛴다. 주말 수집은 판정 전까지 남아 있는 cron 이 한다.

### 설정 순서

1. `매크로.gs` 맨 끝에 추가 블록을 붙이고 저장한다.
2. 함수 선택 → **`testDispatchSafe`** → 실행. 처음이면 권한 승인. Actions 탭에
   `🔎 HYEOKS FRED 점검` 이 방금 시각으로 뜨면 토큰·경로가 맞다.
3. 함수 선택 → **`setupCollectorAlarms`** → 실행. 토스트 "실적 20:40 · 컨센서스 21:20 트리거 설치".
4. 왼쪽 시계 아이콘(트리거)에서 두 줄이 생겼는지, 실패 알림이 "즉시" 인지 확인한다.

### ⚠️ `setupAllMasterAlarms()` 는 누르지 않는다

이 함수는 **프로젝트의 트리거를 전부 지우고** 목록에 적힌 것만 다시 만든다.
목록에 없는 트리거 — 예컨대 `onCheckboxEdit`(모바일 체크박스, UrlFetchApp 을 부르므로
설치형 트리거여야 한다)나 `refreshCalendarOnly` 가 설치돼 있다면 — 함께 사라지고
돌아오지 않는다. 실적 트리거는 `setupCollectorAlarms()` 로만 설치한다.
`setupAllMasterAlarms()` 에 두 줄을 더하는 것은 이 문제를 먼저 정리한 뒤로 미룬다.

## 2. 주요일정 중복 — 캘린더에 보이는 것은 2쌍

`주식정리` 시트를 Drive 로 읽어(2026-09-23 07:25 KST 수정본) **`주요일정` 탭만** 분석했다.
시트 전체(66만 자)를 다 검토한 것은 아니다. 헤더가 비슷한 `이슈브리핑` 탭(AI분석 열)과
구분했다 — `이슈브리핑` 은 `주요일정` 에서 주 1회 파생된다.

- 전체 693행 · 2026-07-24 ~ 12-31 · 그중 545행이 `자동수집(당일)` 뉴스 제목
- 공백 무시 **완전 중복은 0건** — 두 작성기(`omakase.manage_schedule_sheet`,
  `hyeoks_calendar_ingest`)의 중복 제거가 완전 일치만 막기 때문이다
- 캘린더에 보이는 오늘 이후 42행 중 **같은 날 같은 일정의 표현만 다른 쌍 2개**:

| 날짜 | 지울 행 | 남길 행 | 이유 |
|---|---|---|---|
| 09/23 | `메타 커넥트 2026 (시작)` | `메타 커넥트 2026(~24일)` | 기간 정보가 있는 쪽을 남긴다 |
| 10/23 | `유럽종양학회(ESMO 2026)` | `유럽종양학회(ESMO) (~27일)` | 같은 이유 |

행 번호(r653, r673)는 읽은 시점 기준이다. 스캐너가 탭을 통째로 다시 쓰므로 번호가 아니라
**내용으로 찾아** 지운다. 두 작성기 모두 "읽고 → 합치고 → 다시 쓰기" 라 지운 행은 되살아나지 않는다.
장중(09:00~20:00)엔 스캐너가 탭을 다시 쓰는 순간과 겹칠 수 있으니 그 밖에 지우는 게 안전하다.

과거 651행(숨김 처리됨)은 캘린더에 보이지 않고 보관 정책(60·90일)으로 자동 삭제되므로 손대지 않았다.

**시트는 쓰지 않았다.** 이 세션엔 시트 쓰기 수단이 없고, 분석 도구로 원장 시트에 쓰지 않는다는
원칙도 있다. 2행 삭제는 사용자가 한다.

재발 방지(판정 뒤 백로그): 중복 키에서 괄호 꼬리표(`(시작)`, `(~24일)`, `(ESMO 2026)`)를 떼고
비교하도록 두 작성기를 고친다. 지문 대상 코드라 지금은 하지 않는다.
