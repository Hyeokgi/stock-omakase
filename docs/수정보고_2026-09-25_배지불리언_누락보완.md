# 수정보고 2026-09-25 — 배지 조건의 NumPy 참·거짓이 결측으로 사라지던 결함

근거: 코덱스 감사 결과(배지 불리언 누락)와 수정 방향. 사용자 지시로 적용.
코덱스 패치 파일(`0001-fix-preserve-numpy-boolean-badge-evidence-and-expose.patch`)은 대화에
첨부되지 않아 **받지 못했다.** 이 수정은 코덱스가 설명한 네 가지 변경을 같은 범위로 **따로 구현**한 것이다.
그래서 지문이 코덱스 예상값 `1af4a5c8d3a5` 와 다르다(아래). 두 구현의 차이는 코덱스 패치와 대조해 확인할 일이다.

## 결함

`badge_observations.capture()` 는 조건값을 `isinstance(v, bool)` 일 때만 참·거짓으로 받고 나머지는 `None` 으로 바꿨다.
스캐너(`omakase.py`)의 배지 다수는 pandas 값과의 비교다 — 예: `is_jongbe_cand` 의 `current_price >= ma20`,
`is_platform_breakout` 의 `current_price > ma20`. 이 결과는 `numpy.bool_` 이고 파이썬 `bool` 이 **아니다.**

```
>>> isinstance(np.float64(10500) >= np.float64(10000), bool)
False
```

그래서 **계산된 참·거짓이 "계산 안 됨" 과 구분 없이 결측(None)** 으로 기록됐다. 같은 경로의 `clean()` 은
`numpy.int64` 지표를 문자열(`"12000000000"`)로, 미너비니 진단의 `numpy.bool_` 을 `"True"` 문자열로 남겼다.

영향 범위: `data/research_private/badge_observations` 의 선정 전 증거(연구용)만이다. 선정 조건·점수·표시 배지·
15:05 기준·시트·원장은 이 값을 읽지 않는다. 과거 기록(v1)은 **수정하지 않는다.** v1 의 None 은
"계산 안 됨" 과 "NumPy 참·거짓" 이 섞여 있으므로 결측률로 해석하지 않는다.

## 수정

| 변경 | 내용 |
|---|---|
| `condition()` | `bool`·`numpy.bool_` → 참·거짓 그대로. `None` → 결측(`missing`). 0·1·문자열·NumPy 정수 등 → **거짓으로 바꾸지 않고** 결측 + `bad_type:<타입명>` |
| `clean()` | NumPy 스칼라를 파이썬 값으로(`bool_`→bool, `int64`→int, `float64`→float, NaN→None). numpy 는 import 하지 않는다 |
| `capture()` | 행별 `condition_issues`(사유) 와 `conditions_version: badge-conditions-v2` 기록. 미너비니 데이터 없음은 `no_data` |
| `condition_counts()` | 배지별 `true/false/missing/bad_type` 건수. 계산된 행만 센다(수집 실패 행은 기존 `missing_or_failed`) |
| 파일·로그 | `observations.json.gz`·`completed.json.gz` 에 `conditions_version`·`condition_counts`. 로그에 배지별 한 줄 |
| CI | `review_regressions.yml` 에 `numpy` 설치 — 실제 NumPy 값 시험이 CI 에서 돌도록(건너뛰지 않음) |

번들 스키마 `VERSION = badge-observations-v1` 은 그대로 둔다(`select_predecision` 이 이 값으로 번들을 고른다).
조건 해석 규칙은 별도 `CONDITIONS_VERSION` 으로 구분한다.

바꾸지 않은 것: 선정 조건·점수·밴드(ENVELOPE_BAND·SUPPLY_V2_BAND off 유지)·15:05 기준·과거 데이터·Track C/E/L.
